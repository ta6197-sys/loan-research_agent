# 기업 대출 검토 사전조사 에이전트 — 상세 설계

작성일: 2026-10-20 · 설계 기준 확정본 1.0 · 구현·실행 검증 전

> 이 문서의 ‘설계까지만’과 ‘구현 전’은 작성 당시의 범위다. 이후 구현·시험은 [진행 기록](../IMPLEMENTATION_LOG.md), 현재 보안 통제·하루 작업 우선순위·미구현 한계는 [프로젝트 README](../../../README.md)의 금융 안내를 따른다. 기존 결정은 유지하며, 설계에 적힌 기능을 구현 완료로 간주하지 않는다.

현재 작업 범위는 **설계와 구현 인계 문서까지**다. 금융 기능의 소스 코드 작성·수정, 서버 실행, 라이브러리 설치는 이 설계 작업에 포함하지 않는다. 이후 구현에서는 기존 코드를 최대한 활용한다.

> 흩어진 공시와 IR 자료를 조사 목적에 맞게 연결하고, 확인된 사실·해석·미확인 사항·추가 질문을 구분해 담당자의 기업 대출 사전조사를 돕는 에이전트

기획·화면·시연·평가의 중심은 **조사 시간 단축·자료 누락 감소·근거 추적성·추가 질문의 구체화**다. 효과는 비교 평가로 확인할 목표다. 일곱 항목에 맞춘 자료 연결, 변화에 따른 추가 확인, 이유가 있는 내부 자료 질문, 수치·원문 위치를 추적할 수 있는 초안을 설계한다.

## 합의한 큰 방향

- IBK 기업금융 담당자의 운전자금 신규 대출 사전조사를 돕는다.
- 첫 구현은 개인 PC의 사용자 1명, 공시를 확보할 수 있는 상장 제조기업을 대상으로 한다.
- 일곱 기본 항목을 확인하고 근거에 따라 추가 조사한다. 사람이 다음 조회를 계속 지시하는 방식으로 만들지 않는다.
- 핵심 요약·질문을 앞에 두고, 확인한 범위로 바로 초안을 제공한다. 최소 확인표·본문 13개 계정·기본 두 차트 주제를 적용한다.
- 화면 보고서와 PDF, Markdown·차트·근거 목록 ZIP 다운로드를 제공한다.
- 화면 연결이 끊겨도 서버가 살아 있으면 조사를 계속하고 재접속 시 복원한다. 서버 시작 시 비정상 중단 조사는 남은 한도로 자동 재개한다.
- 사용자가 삭제할 때까지 조사·원문·첨부·보고서 이력을 로컬 보관한다.
- 기존 FastAPI·Vue·LangGraph·MCP 연결을 유지하고 금융 도구를 별도 구성한다.
- 첨부는 텍스트 PDF·XLSX·CSV·TXT부터 지원한다. XLSX는 저장된 계산 결과를 사용하고 숨김도 구분해 포함한다.
- 충돌·기본 누락 보완 후 목적 관련 쟁점을 심화한다. 첫 평가는 상신브레이크와 직접 만든 오류 상황부터 검증한 뒤 확대한다.
- 모델명은 구현 시 실제 PC 검증 후 선택한다. 일시 조회 오류 최초 포함3회·초안 수정 최대2회·자동 복구 연속 실패2회 상한을 적용한다.
- 고정 절차와 에이전트를 각각3회 평가하며, 검사 범위의 공개 확인 누락·게시 수치/근거 오류를 우선 확인한다.
- 첨부한 메시지를 전송하면 자동 조사/대기하며 별도 제출·조사 시작 단계는 없다.
- 중단은 같은 조사의 대기 후속 작업도 멈춘다. 계획 변경은 현재 조사 완료 후 수정 계획으로 추가 조사한다.
- 실행 최대30분·마지막5분 작성/검증, 새 후속 조사에 새 한도·전체 누적량을 표시한다.
- 미완성 결과도 확인한 범위까지 제공하며 공시 원문 대조는 에이전트의 수행 책임이다.
- 기본 모델 처리는 로컬이며 외부 모델·추적 전송은 사용자가 설정할 때만 허용한다. NCS 교재의 기존 이용 제한은 별도 준수한다.

## 문서 상태와 설계 완료 조건

문서의 `확정`은 사용자 선택 또는 이전 합의다. `설계 제안`은 구체적인 검토안이며 자동으로 승인된 기본값이 아니다. 미응답 항목을 구현 담당자가 임의로 확정하지 않는다.

지원 범위·비교 정책·최소 확인표·수치표, 입력/화면/출력, 근거/버전 구조, 중단/재개/계획 변경, 운영·모델/첨부 정책, 평가 대상·반복 수·수용 기준의 서비스 동작을 확정했다. 가장 최근 사용자 답변을 반영한 기준은 [결정 기록](DECISIONS.md)과 [최종 결정](FINAL_REVIEW.md)이다.

이 확정은 **설계 기준의 확정**이다. 금융 기능 코딩·실제 모델 선정·서버/도구·PDF/차트 출력·자동 원문 검증·복구 시험은 수행하지 않았다. 모델명·라이브러리 버전·그래프 저장 연결·DDL·폰트·성능·화면 세부 등 실제 환경에서 검증할 기술 선택은 구현 인계서에 남겼다. 이후 새로운 선택이 생기면 사용자 지침에 따라 질문한다.

상위 기획은 [PROJECT_PLAN.md](../../../PROJECT_PLAN.md), 실제 자료·초안은 [상신브레이크 사례](../cases/sangsin_brake/CASE_REPORT.md), 항목·양식의 출발점은 [기존 검토안](../REPORT_DESIGN_REVIEW.md)이다. 충돌 시 가장 최근 사용자 답변과 [결정 기록](DECISIONS.md)을 먼저 대조한다.

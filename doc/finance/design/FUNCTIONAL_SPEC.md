# 기능 명세

버전 1.0 · 설계 기준 확정본. 기능 코드는 작성하지 않았다. 세부 제안과 미결정 사항은 [결정 기록](DECISIONS.md)을 따른다.

## 1. 사용자와 지원 범위

개인 PC에서 한 명이 실행하는 한국어 서비스다. 첫 목적은 IBK 담당자의 신규 운전자금 대출 사전조사이며, 첫 지원 기업군은 필요한 DART 공시와 공식 자료를 확보할 수 있는 국내 상장 제조기업이다.

기업 식별 시 법인명·고유번호·종목코드·공시 존재·사업 내용을 대조한다. 업종코드 하나만으로 제조·비제조를 확정하지 않는다. 후보가 여러 개이거나 사업 범위가 애매하면 차이를 제시해 선택을 요청한다. 범위 밖 기업을 몰래 다른 기업으로 대체하거나 지원 완료로 표시하지 않는다.

장기 방향인 국내 기업 일반 지원, 은행 운영계 접속·내부 신용정보 연계, 대출 승인·한도 산정, 뉴스·산업 전체 탐색, 스캔 OCR은 이번 첫 구현의 합의 범위에 포함하지 않는다.

## 2. 입력 계약

| 구분 | 입력 | 동작 |
| --- | --- | --- |
| 필수 | 회사, 조사 목적 | 회사는 법인 식별까지 확인. 목적은 기존 운전자금 사전조사에서 시작 |
| 조사 기준 | 공개 자료 기준일, 비교 기간·재무 범위 | 기본 비교 정책을 표시하고 변경 가능. 과거 기준일이면 이후 공개 자료 제외 |
| 선택 | 신청 용도·금액·기간·집행 시점·상환 계획 | 미제공이어도 조사 진행. 필요해진 질문에 연결 |
| 선택 | 사용자 설명·파일 | 별도 출처로 수신. 공식 수치나 조사 지시를 자동 덮어쓰지 않음 |
| 운영 설정 | 조회·모델·시간·첨부 한도, 외부 전송 설정 | 실행 시작 시 설정 스냅샷으로 고정·이력 보존 |

법인 식별이 안 되면 특정 법인의 재무 수치를 작성하지 않는다. 식별 후보·확인 질문과 진행 가능한 준비 결과를 제공한다. 사용자 임의 설명이 공식 법인 확인을 대신한 것처럼 표시하지 않는다.

## 4. 자료 수집·선택 규칙

1. 회사 고유번호로 접수 목록을 얻고 보고기간·접수일·정정·첨부 관계를 기록한다.
2. 공개 기준일 당시 허용되는 자료를 선택한다. 최신 재무 API 응답의 접수번호가 기준일 이후이면 과거 분석에 쓰지 않는다.
3. API 본표 수치와 공시 원문의 해당 표·열을 연결한다. 사업·원인 설명·조건은 주석·본문에서 별도로 확보한다.
4. 중간보고서의 설명이 생략되거나 이전 연간 자료를 참조하면 관련 연간 자료까지 확인한다.
5. 최신 정기보고서 이후 기준일 사이의 관련 공시를 확인한다. 모든 공시 제목이 아니라 해당 쟁점과 관계를 기준으로 본문을 선택한다.
6. 공식 IR은 원문에 이르는 경로와 수치 범위를 기록해 보조 대조한다. ‘공식’이라는 이유만으로 다른 기간·범위의 차이를 없애지 않는다.

검색·수집 범위는 DART와 기업 공식 IR이다. KIND는 이미 수행한 수작업 사례의 열람 경로이며 자동 수집 지원을 추가한 결정은 아니다. 필요 시 사용자와 범위 확대를 논의한다.

## 5. 수치·설명·차트 계약

- 금액은 원문 문자열과 정밀 수치를 함께 보관한다. 계산과 검증 전에는 반올림하지 않는다.
- 통화·단위·연결/별도·기간·누적/시점을 필수 메타데이터로 취급한다. 빈 값·미공시·추출 실패·실제 0은 구분한다.
- 계정 이름만 닮았다고 같은 항목으로 연결하지 않는다. 계정 ID·본표 위치·구성·주석과 대조한다.
- 별도 수치를 연결로 대체하지 않는다. 차입 합계에는 구성과 리스 포함 여부를 명시하고 보증과 중복 합산하지 않는다.
- 비교 가능한 입력에서만 증감·차트를 만든다. 기간 길이·사업 범위·회계정책 변경을 발견하면 비교의 제한을 표시한다.
- 원인 해석에는 근거와 설명의 한계를 붙인다. 채권 증가를 연체, 현금 감소를 손실, 보증 연장을 신규 부담으로 자동 확정하지 않는다.
- 표·차트·본문 숫자는 같은 검증 데이터와 계산 결과를 참조한다. 모델이 본문에서 별도로 재계산해 숫자를 만들어내지 않는다.

본문에는 합의한 13개 계정을 표시한다. 정확한 구성과 최소 확인표는 [기본 항목·양식](../REPORT_DESIGN_REVIEW.md)을 따른다. 기본 차트는 영업이익·영업현금흐름, 현금·차입금의 두 주제이며 비교 가능한 기간만 작성하고 쟁점별 차트를 추가한다. 네 차트를 모든 기업에 강제하지 않는다.

## 6. 첨부 처리 계약

지원: 검색 가능한 PDF, XLSX, CSV, TXT. 파일 수신과 조사 근거로 채택하는 단계는 다르다. 수신 후 형식·처리량·텍스트 추출 가능 여부를 검사하고, 성공한 범위와 읽지 못한 부분을 사용자에게 보여준다.

| 형식 | 근거 위치 | 읽기·검증 규칙 제안 |
| --- | --- | --- |
| PDF | 물리 페이지, 표·영역·텍스트 위치 | 문자가 없는 페이지를 확인 완료로 처리하지 않음. PDF 표 추출값은 원문과 대조 |
| XLSX | 시트·셀·범위 | 저장된 계산 결과 사용. 숨김 시트·행·열도 구분해 포함하고 단위·머리글·필터 상태 보존. 수식·매크로·외부 링크 실행 금지 |
| CSV | 인코딩·행·열 | 인코딩·구분자·머리글 확인, 코드/앞자리 0 임의 손실 방지 |
| TXT | 줄·문단 | 인코딩·제목·날짜·발행주체가 없으면 누락 표시 |

암호화·손상·잘못된 확장자·스캔·수식값 부재는 서로 다른 상태로 안내한다. 사용자에게 암호를 채팅에 적도록 요구하지 않는다. XLSX는 수식과 파일에 저장된 계산 결과를 구분해 기록하고 재계산하지 않는다. 저장된 결과가 없으면 미확인으로 남기며, 결과가 있어도 최신성을 검증한 값처럼 표현하지 않는다. 숨김 시트·행·열은 조사에 포함하되 숨김 상태와 위치를 표시한다. 숨김 여부를 신뢰도 판단 근거로 쓰지 않고 다른 자료와 동일하게 대조한다.

확정한 초기 한도: 조사당 10개, 파일당 20MB, 합계 100MB, PDF 파일당 200쪽, 표 파일당 50,000셀. 설정에서 조정 가능하다. 초과 자료를 일부만 읽고 전체를 읽었다고 표시하지 않는다. 누적 첨부도 같은 조사 한도에 포함하며, 삭제·교체 시 계산 기준을 일관되게 적용한다.

## 7. 오류와 사용자 메시지

| 상황 | 메시지가 포함할 내용 | 계속할 수 있는 작업 |
| --- | --- | --- |
| API 키 없음·인증 실패 | 설정 항목과 확인 필요 사실. 키·인증 주소 출력 금지 | 저장된 근거 열람·기존 초안·허용된 다른 자료 |
| 일시 네트워크·제공처 오류 | 어느 자료·언제 실패했는지와 재시도 상태 | 독립 자료 조회·분석 |
| 이용 한도·제공처 제한 | 한도 때문에 멈춘 범위·다음 가능 행동 | 확인된 근거로 제한 초안 |
| 본문·첨부 파싱 실패 | 원문 존재/읽기 실패를 구분, 실패 위치 | 다른 원문 형식·관련 공시 확인 |
| 자료 충돌 | 서로 다른 값과 범위·시점, 이미 수행한 대조 | 충돌 영향 밖의 조사·초안 |
| 로컬 모델 실행 실패 | 모델 상태와 작성되지 않은 범위 | 수집 근거·검증 표는 보존. 외부 모델로 몰래 전환 금지 |
| 출력 생성 실패 | 게시 보고서 버전과 실패한 형식 | 화면 결과 유지, 동일 버전 재출력 |

일시 조회 오류는 최초 포함 최대3회, 초안은 최초 이후 최대2회 수정, 자동 복구는 연속2회 실패하면 중지하도록 확정했다. 전체 예산을 우선 적용하고 설정에서 조정한다. 재시도 대기는 2초·5초, 외부 요청 최대60초·모델 최대180초로 확정했고 전체 남은 시간이 우선이다. 총20회 중 마지막4회와 마지막5분은 작성·검토·수정에 남긴다. [운영·모델 정책](RUNTIME_AND_MODEL_POLICY.md)을 따른다. 잘못된 인증이나 자료 없음은 같은 요청을 반복한다고 해결되는 일시 오류로 취급하지 않는다.

## 최신 사용자 동작 결정

- 조사 중단은 현재 실행과 같은 조사의 대기 후속 작업까지 적용한다. 재개 전 자동 실행하지 않는다.
- 계획 수정은 현재 조사를 마친 뒤 수정 계획으로 추가 조사한다. 현재 실행의 계획·근거는 고정하고 새 계획 대기 상태를 표시한다. 즉시 멈추려면 중단을 사용한다.
- 초안 본문을 완성하지 못해도 검증된 표·계산·근거·남은 부분을 제공하고 미검증 범위를 명시한다.
- 원문 대조의 최종 수행 주체는 에이전트다. 원문 위치·대조값·계산·검사 결과를 남기며 사용자 최종 대조를 의무화하지 않는다.
- 첨부 포함 메시지 전송으로 자동 조사하며 별도 제출/시작 버튼을 두지 않는다. 같은 메시지 파일은 한 입력으로 접수하고, 실행 중이면 다음 실행으로 대기한다.
- 전체 실행 최대30분·마지막5분 작성/검증을 적용한다. 새 후속 실행에는 새 한도·누적 사용량, 동일 실행의 장애 복구는 잔여 한도를 적용한다.

## 8. 목적별 자료 연결과 추가 질문의 출력 계약

서비스의 중심 산출물은 조사 목적과 일곱 항목에 맞춰 근거를 연결한 검토 초안이다. 영업현금흐름·재고·채권·차입금의 변화는 본표·관련 주석·후속 자료를 확인할 출발점이며 변화 자체를 위험·연체·상환 불능으로 확정하지 않는다.

| 추가 질문의 구성 | 남길 내용 |
| --- | --- |
| 연결 대상 | 기본 항목·쟁점·영향받는 주장/계산 |
| 발견한 근거 | 법인·기간·범위가 확인된 사실과 원문 위치 |
| 먼저 확인한 공개 자료 | 본표·주석·공식 IR의 실제 조회 내용과 남은 한계 |
| 부족한 정보 | 확보한 자료로 알 수 없는 구체 내용 |
| 요청 자료/답변 | 부족한 정보를 확인할 자료의 대상·기간·구성. 불필요한 전체 내부 자료 요구 금지 |
| 요청 이유 | 답변으로 어떤 설명·계산·확인 범위를 보완하거나 수정하는지 |
| 상태 | 질문됨·부분 답변·대조 중·해결·미해결 등, 답변 출처와 처리 결과 |

질문 개수를 늘리는 것 자체를 성과로 보지 않는다. 공개 자료에서 확인 가능한 내용을 다시 요구하거나 동일 정보에 대한 중복 질문을 만들지 않도록 기존 근거·질문과 대조한다. 응답이 없으면 답을 만들어 채우지 않고 영향과 한계를 표시한 초안을 제공한다. 추가 조사는 충돌·기본 누락을 먼저 보완한 뒤 대출 목적 관련 설명 공백을 심화한다. 질문 품질의 세부 수용 기준은 평가 설계와 남은 선택을 따른다.

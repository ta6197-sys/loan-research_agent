# 검증·완료 조건·비교 평가 설계

버전 1.0. 아래는 구현 시 확인할 규칙·시험 계획이다. 이번 설계 작업에서 제품 테스트를 실행했다는 뜻이 아니다.

## 1. 검증 책임

| 대상 | 우선 검사 | 모델의 역할·한계 |
| --- | --- | --- |
| 법인·기간·범위·단위 | 식별·메타데이터·표/열 확인 | 후보 설명 가능, 불명확한 법인/기간을 임의 확정 불가 |
| 숫자·계산 | 원문 해당 행/열과 정확값·산식 대조 | 숫자를 추정·산술 보완하는 판정자로 쓰지 않음 |
| 원인 설명 | 연결 근거·반대 근거·표현 범위 | 해석 후보·반론·수정 제안. 자체 평가 점수만으로 참이라고 판정 불가 |
| 최소 항목 충족 | 합의 체크리스트와 실제 근거·조사 시도 | 긴 문장을 썼다는 것으로 충족 처리 불가 |
| 보고서·차트 | 같은 데이터 참조·근거·누락·표시 | 잘못된 수치를 유창한 문장으로 가리는 동작 금지 |

원문에 숫자가 존재하는지만 찾으면 다른 계정·연도·범위의 수치를 잘못 연결할 수 있다. 해당 표의 머리글·계층·행·열과 대조해야 한다.

반올림 일치는 정확한 일치와 별도로 기록한다. 보고서가 제시하지 않은 조정 항목을 합계 맞추기 위해 만들어내지 않는다. 적용 불가·미실행은 pass가 아니다.

## 3. 검증 실패와 초안 제공

실패한 주장만 관련 근거·계산과 함께 수정하고 영향 없는 부분을 보존한다. 재작성 중 새 사실을 추가하면 그 사실도 다시 검증한다. 횟수만 채워서 기존 형식 검증을 통과시키는 실습 로직은 교체한다.

검증 실패가 남으면 지원되는 문장을 남기고 해결되지 않은 주장·숫자는 보류해 표시한다. 필요한 항목이 빠지면 빠진 이유와 다음 행동을 쓴다. 이를 모든 주장이 확인됐다는 보고서로 표시하지 않는다. 작성 전 승인이나 모든 내부 답변 수신을 필수로 두지 않는다.

## 5. 비교 평가

비교 대상은 같은 기본 항목을 정해진 순서로 확인하는 고정 절차다. 회사·공개 기준·자료 접근 범위·모델·예산·캐시 조건을 맞춘다. 에이전트에만 더 많은 자료나 다른 기간을 허용한 뒤 효과라고 보고하지 않는다.

| 지표 | 측정 정의 |
| --- | --- |
| 수치 오류 | 잘못된 값·단위·기간·범위·산식 수, 표본/전체 범위를 명시 |
| 근거 오류 | 근거 없음·관련 없는 근거·지원 범위를 넘은 주장 |
| 공개 자료 충족 | 수작업에서 확인 가능한 항목 중 실제 채운 항목 비율 |
| 주요 누락 | 기준 사례의 필요한 질문·근거·쟁점이 빠진 내용 |
| 추가 조사 효과 | 추가 조회로 해결·수정한 내용과 중복/불필요 조회 |
| 사용자 개입 | 수동 조회 지시·필요 정보 제공·충돌 해결을 나눠 집계 |
| 시간·자원 | 실행·대기·모델·수집 시간과 실제 호출, 실패·캐시 구분 |
| 후속 갱신 | 새 입력의 영향 범위가 결과에 반영되고 이전 결과 추적 가능 여부 |

상신브레이크는 첫 수작업 기준 사례이며 모든 원문·주장을 검증한 은행 전문가 정답은 아니다. 이미 대조한 13개 계정과 명확한 계산·범위 오류를 기준으로 먼저 확인한다. 첫 평가 범위는 **상신브레이크와 직접 만든 오류 상황**으로 확정했다. 여기서 근거·누락·질문과 같은 조건의 고정 절차 비교를 먼저 검증한 뒤 다른 기업으로 확대한다. 고정 절차와 에이전트 각각 3회로 확정했다. 정해진 검사 범위에서 게시 수치·근거 오류와 수작업 기준표의 공개 확인 가능 항목 누락이 없는지 우선 검사한다. 추가 기업은 이후 사용자와 선정한다. 더 많은 미확인 표시나 질문 감소만으로 성공을 판단하지 않는다.

## 6. 중심 가치에 맞춘 평가 기록안

사용자가 확정한 목표 가치는 조사 시간 단축·자료 누락 감소·근거 추적성·추가 질문의 구체화다. 아래는 이를 실제 결과로 확인할 기록 방법이다. 목표·측정 정의와 합격선을 구분하며, 초기 대상은 D38, 반복 수·정확성/누락 우선 수용 기준은 D42로 확정했다. 시간 단축·질문 유용성의 임의 성과 수치는 설정하지 않는다. 금융 수치·근거 오류를 먼저 확인하고 속도만 개선한 결과를 성공으로 표시하지 않는다.

| 목표 가치 | 측정할 내용 | 해석할 때의 한계 |
| --- | --- | --- |
| 조사 시간 단축 | 수집·대조·작성 시간과 사람이 근거를 다시 찾고 확인하는 시간. 답변 대기는 별도 | 자동 실행 시간 감소만으로 담당자 업무 시간 단축을 입증할 수 없음. 실제 담당자 검증이 없으면 자체 모의 검토로 표시 |
| 자료 누락 감소 | 사전에 만든 수작업 기준표에서 공개 확인 가능한 항목·관련 주석·핵심 질문 중 실제 채운 수와 누락 | 분모·확인 범위를 공개. 모든 칸을 미확인으로 채우는 방식이나 단순 글자 수로 충족 처리 금지 |
| 근거 추적성 | 사실·해석·수치·계산에서 정확한 원문 위치로 돌아갈 수 있는지, 연결 근거가 그 내용을 실제 지원하는지 | 링크 존재와 의미상 뒷받침 여부를 따로 검사. 같은 숫자가 나오는 다른 기간의 표 연결은 오류 |
| 추가 질문의 구체화 | 질문별 발견 근거·공개 조사 시도·부족한 정보/필요 자료·이유·영향받는 쟁점의 연결 여부 | 필드 개수만으로 질문의 유용성을 확정하지 않음. 중복·이미 공개된 정보 요구·답으로 무엇이 달라지는지 설명하지 못한 질문을 별도 기록 |

질문 검토의 예시는 ‘현금이 부족하니 자료를 달라’ 대신, 관찰한 채권 변동과 관련 주석을 제시하고 공개 자료로 알 수 없는 회수 일정·실제 회수 내역을 어느 기간·대상 범위로 요청해야 하는지 밝히는 것이다. 필요한 범위는 확보한 근거에 맞춰 정하며 변화만으로 연체나 손실을 단정하지 않는다.

포트폴리오에는 조사 기준·대상 수·사용 모델·예산·비교 절차·수작업 검토 범위와 함께 측정 결과를 제시한다. 아직 측정하지 않은 시간 절감률·누락 감소율·질문 유용성 수치를 작성하지 않는다. 승인·거절 정확도는 이 서비스의 목표 지표로 추가하지 않는다.

## 7. 반복 수·수용 조건 — 사용자 선택으로 확정

사용자는 고정 절차와 에이전트를 각각 3회 비교하고 정확성·누락을 우선 확인하도록 선택했다. 아래는 그 조건을 평가 기록으로 구체화한 것이다.

- 고정 절차와 에이전트를 각각 3회 실행하고 회차별 결과를 보존한다. 같은 원문 버전·기준일·모델·예산·캐시 조건을 사용하고 환경과 실패 이력도 기록한다.
- 실행 전 수작업 공개 확인표의 정답·근거 위치·내부 정보가 필요한 항목·자료 한계를 정리한다. 기존 첫 초안을 전체 검증을 마친 정답으로 간주하지 않는다.
- 게시된 수치·법인·기간·단위·계산·지원 근거 오류와 수작업 기준표의 공개 확인 가능 항목 누락이 없는지 우선 검사한다. 한 번의 성공만 골라 보고하지 않고 모든 회차를 기록한다.
- 자료 부재·접근 실패·외부 제한 때문에 확인 못 한 경우는 숨기지 않고 별도 분류한다. 미확인이라고 쓴 것만으로 공개 확인 항목의 누락을 통과시키지 않는다.
- 시간·원문 위치 추적·질문 구체화는 정확성·누락 결과와 함께 공개한다. 표본 하나의 성공을 전체 상장 제조기업 성능으로 일반화하지 않는다.

이 수용 기준의 ‘오류 없음’은 정해진 검사 범위에서 관찰한 결과를 뜻한다. 검사하지 않은 주장까지 무오류를 보장한다는 의미가 아니다. 오류 발견 시 수정 후 다시 검증하고, 사후 변경 전 결과·설정과 재검증 결과를 함께 보존한다.

## 8. 원문 대조의 수행 책임 — 사용자 최신 결정

정해진 검증 항목의 최종 원문 대조는 에이전트가 수행한다. 사용자가 직접 최종 확인해야만 초안 제공·검증을 마칠 수 있다는 필수 단계를 두지 않는다. 수작업 기준표 준비·공시 원문 해당 행/열 대조·계산 검산·주장 지원 여부를 에이전트의 실제 작업으로 기록한다.

| 검증 대상 | 에이전트가 남길 증거 |
| --- | --- |
| 수치·계산 | 원시 응답/보고서 위치·법인·계정·기간·단위·정정, 정확한 값·계산 입력과 결과 |
| 사실 주장 | 주장을 지원하는 실제 원문 구간, 적용 범위와 기준시점 |
| 해석·추가 질문 | 지지/반대 근거·공개 조사 시도·부족한 정보·확정할 수 없는 부분 |
| 검증 결과 | 규칙·도구/모델/검사 버전·수행 시점·검사 범위·통과/실패/미실행·오차/보류 이유 |

모델이 작성한 문장을 다시 읽고 자체 점수를 주는 행위를 원문 검증으로 대체하지 않는다. 원문 대조와 산술 검사 결과를 보존하며 의미 검증이 불명확하면 보류한다. 수작업 사례와 자동 실행의 검사를 모두 에이전트가 수행한 경우 그 사실을 표시한다. 이를 독립 평가자·은행 현직자의 검증 결과로 표현하지 않는다. 아직 실행하지 않은 검증은 수행 완료로 표시하지 않는다.

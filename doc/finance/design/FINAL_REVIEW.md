# 최종 설계 결정과 검토 이력

작성일: 2026-10-20 · 설계 확정본 1.0. 사용자의 최종 명시적 답변을 반영했다.

## 1. 여섯 질문의 최종 처리

| 질문 | 확정한 동작 | 설명·변경 이력 |
| --- | --- | --- |
| 1. 여러 후속 자료 묶기 | 파일을 첨부한 메시지 전송으로 자동 조사. 별도 자료 제출/조사 시작 버튼 없음 | 파일 선택·전송의 기술 처리와 사용자의 조사 시작 행동을 분리하지 않음. 같은 메시지의 파일은 함께 접수 |
| 2. 추가 조사 시간 | 실행 최대30분·마지막5분 작성/검증. 새 추가 조사에는 새 작업 한도, 전체 누적 사용량 표시 | 30분은 단순 알림이 아닌 종료 상한. 실제 자료를 모두 확인할 수 있다는 성능 보장은 아님. 장애 복구는 같은 실행의 남은 한도 |
| 3. 중단 범위 | 현재 실행과 같은 조사의 대기 후속 작업 모두 중지, 재개 전 자동 실행 금지 | 서버 재시작·답변/파일 수신이 사용자 중단을 취소하지 않음 |
| 4. 계획 변경 | 현재 조사를 마친 뒤 수정 계획으로 추가 조사 | 사용자가 처음 제시한 즉시 변경 의견을 설명 후 위 방식으로 변경. 즉시 멈추고 싶으면 중단 사용 |
| 5. 미완성 결과 | 검증한 표·계산·근거·남은 부분 제공, 미작성·미검증 상태 표시 | 실패 안내만 반환하거나 미완성 결과를 완성 보고서로 표시하지 않음 |
| 6. 최종 원문 대조 | 에이전트가 정해진 항목을 공시 원문·주석·계산과 대조 | 사용자에게 필수 최종 대조를 요구하는 제안은 채택하지 않음. 원문 위치·결과·검사 범위를 기록 |

### 파일과 대기열을 구분하는 예

- 같은 메시지에 파일7개를 첨부해 전송하면 그7개를 하나의 후속 입력으로 접수한다. 파일을 내부적으로 나누어 전송하더라도 파일마다 전체 조사 실행을 생성하지 않는다.
- 이미 조사 중에 새 메시지로 파일을 보내면 전송은 완료되고 후속 조사로 대기한다. 현재 실행의 입력·작성 근거를 중간에 바꾸지 않는다.
- 같은 기업·기준에 아직 시작하지 않은 후속 입력이 여럿이면 함께 처리하되 메시지/파일별 이력·적용 순서·출처를 보존한다. 처리 시작 후 새로 온 자료는 다시 다음 실행으로 대기한다.
- 사용자가 중단한 조사에는 새 입력이 들어와도 자동 실행하지 않는다. 재개 선택을 기다린다.
- 첨부 한도는 앞서 선택한 조사당10개·파일20MB·총100MB·PDF200쪽·표5만 셀의 조정 가능한 초기값을 유지한다. 여러 번 전송한다고 조사 전체 상한이 풀리지 않으며 초과 자료를 몰래 누락하지 않는다.

### 여러 기업과 계획 변경의 구분

기존 범위는 기업마다 독립된 조사·보고서를 만들고 한 번에1개 실행, 나머지 대기다. 여러 기업을 하나의 보고서로 섞거나 한 번에 여러 기업을 분석하는 신규 기능을 확정한 것이 아니다. 사용자는 이 범위 설명을 들은 뒤 현재 조사 완료 후 계획 변경 반영을 명시적으로 선택했다.

## 검증 주체의 구분

시스템이 원문 대조·수치 검산·근거 확인을 수행하는 책임과, 그 결과가 은행 현직자나 외부 독립 검토자의 검증을 거쳤는지는 구분한다. 에이전트의 작업을 수행했다는 이유만으로 실무 정확성이나 무오류를 보장했다고 표현하지 않는다. AI 문장 생성의 자체 점수만으로 검증을 통과시키지 않는다. 실제 원문 위치·입력값·계산·적용 규칙을 남긴다.

## 3. 구현 단계에서 검증·선택할 기술 세부

모델 후보·장비/라이선스 확인, 패키지 버전·호환성, 영속 그래프 체크포인터의 실제 연결 방식, 테이블 DDL/마이그레이션, 추출/차트/PDF 라이브러리·한글 폰트, 실제 오류 코드와 상태 매핑, 인덱스·렌더링 성능·픽셀 단위 배치는 실행·출력 검증이 필요한 구현 세부다. 구현 완료 뒤에는 LangSmith를 공개·가상 자료에 한정해 쓸 필요, 전송 차단, 기록 범위, 보존·삭제·공유·비용과 평가 이점을 검토한다. 설계에서 기능 완성이나 성능 보장으로 소개하지 않는다.

코딩 담당자는 이 기술 세부를 구현할 때 사용자의 AGENTS 지침에 따라 선택·논의할 내용을 질문한다. 이번 묶음 응답은 미래의 모든 기술 선택·새 기능·외부 전송을 미리 승인하는 것이 아니다.

## 4. 문서 점검 범위와 한계

확정/미정 구분, 기획과 상세 명세의 정책 일치, 문서 링크·기존 사례 연결을 점검한다. 서버·모델·DART 재실행, 금융 기능·출력·복구 시험을 수행하는 단계는 아니다. 첫 수작업 사례에 남은 공개 자료 대조와 전체 주장 검증은 이후 구현 평가 기준표 준비 과정에서 명시적으로 보완한다.

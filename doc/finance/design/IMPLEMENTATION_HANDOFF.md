## 2. 재사용의 원칙

FastAPI·Vue·LangGraph·MCP 연결·모델 호출·SQLite 기반을 유지한다. 금융 도구는 별도 구성한다. 프레임워크 전면 교체·새 서비스/저장소·벡터 DB 도입을 당연한 전제로 삼지 않는다.

장애 도메인 판단·가짜 오류·형식 검증·최대 횟수 강제 통과는 그대로 재사용하지 않는다. 기존 시작 스크립트가 DB를 삭제하거나 프로세스를 강제 종료하므로 조사 이력에 사용하기 전에 바꾼다. `.env`나 키를 덮어쓰거나 출력하지 않는다.

## 3. 구현 단계와 단계별 완료 조건

| 순서 | 작업 | 완료 조건 |
| --- | --- | --- |
| 0 | 기존 환경·파일·DB·합의 확인 | 필요한 부분만 변경할 계획, 기존 자료 보존, 미정 사항 질문 |
| 1 | 조사/기준/실행/버전·근거 저장 | 대화와 조사 분리, 원문/값/출처 연결, 재시작 후 상태 읽기 |
| 2 | 별도 금융 MCP 도구 연결 | 키 비노출, 법인·접수·본표·원문 조회 및 오류 구분 |
| 3 | 원문 위치·표·단위·기간 정규화 | 선택 계정과 주석이 정확한 위치로 돌아감, 실패·복구 경고 보존 |
| 4 | 숫자 대조·계산·비교 정책 | 13개 계정·산술·정정·중간기간·범위 검증, 잘못된 값 보류 |
| 5 | 일곱 항목 기본 조사·초안 | 회사 입력부터 근거·질문·표·차트·게시본까지 한 사례 실행 |
| 6 | 추가 조사·질문·후속 입력 | 발견 쟁점에 따라 경로 변화, 답변 없이도 초안, 관련 결과 갱신 |
| 7 | 중단·단절·자동 복구·대기열 | 명시 중단과 비정상 종료 구분, 예산·이력·게시의 중복 방지 |
| 8 | 보고서·근거 중심 화면·출력 | 원문 연결·정정 요청·버전·PDF/Markdown 동기화, 비기술적 UI |

단계별로 실제로 필요한 테스트를 수행한다. 가짜 모델의 형식 성공을 실제 금융 조사 정확성으로 보고하지 않는다. 환경 버전과 도구의 최신 계약은 구현 시작 때 공식 문서로 재확인하되, 전체 패키지 재설치를 기본 행동으로 하지 않는다.

## 4. 계약상 바뀌면 안 되는 동작

- 공개 자료를 먼저 조사하고 충돌·기본 누락 보완 후 목적 관련 설명 공백을 심화한다. 매번 사용자가 다음 도구를 골라주는 흐름으로 바꾸지 않는다.
- 계획은 표시 후 자동 시작한다. 초안 게시 전에 승인 단계를 추가하지 않는다.
- 일곱 항목의 확인 범위·미확인 이유를 남긴다. 한도 도달을 검증 통과로 바꾸지 않는다.
- 확인된 사실·해석·미확인·질문과 공식/사용자 출처를 구분한다.
- 연결 현금·일부 만기표·기존 보증 연장을 차주의 현재 자금/전체 상환/신규 부담으로 임의 변환하지 않는다.
- 계획 수정은 현재 조사 완료 후 수정 계획으로 추가 조사한다. 현재 입력·계획은 유지하고 새 계획의 대기 상태를 표시한다. 즉시 멈추려면 중단을 사용한다.
- 조사 중단은 같은 조사의 대기 후속 작업까지 멈추고 사용자의 재개 전 자동 실행하지 않는다.
- 에이전트가 정해진 항목을 공시 원문·주석·정확한 계산과 대조하고 검사 범위·결과를 남긴다. 사용자 최종 대조를 필수 단계로 강제하지 않는다.
- 모델 장애 등으로 미완성이어도 확인된 표·계산·근거·미해결/미검증 부분을 제공한다.
- 화면 단절은 조사 중단이 아니다. 서버 재시작은 예기치 않게 끊긴 실행을 복구하되 명시 중단·삭제를 취소하지 않는다.
- 외부 전송·추적은 기본 꺼짐이며 사용자의 설정과 자료 이용 제한을 검사한다.
- 생성 본문은 읽기 전용이며 정정 요청·답변으로 새 버전을 만든다. 일반 메모는 저장만, ‘조사에 반영’ 선택 시 재조사한다.
- 회사 변경은 새 조사, 목적·기준일 변경은 새 기준 버전이다. 이전 결과를 보존한다.
- 화면·PDF·Markdown은 같은 게시 버전·검증 데이터에서 생성한다. Markdown·차트·근거 목록은 ZIP으로 동봉한다.
- 시연은 목적별 자료 연결→변화 발견→관련 근거 추가 확인→이유가 있는 질문→검증 가능한 초안의 흐름을 보여준다. 시간·누락·추적성·질문 구체화는 측정한 범위 안에서 설명한다.
- XLSX는 저장된 계산 결과를 읽고 숨김 데이터도 표시해 포함한다. 결과 부재/최신성 한계를 남기며 수식·매크로·외부 연결을 실행하지 않는다.
- 평가는 상신브레이크와 직접 만든 오류 상황부터 고정 절차와 비교한 뒤 다른 기업으로 확대한다.
- NCS 권리 제한은 키가 있거나 로컬 모델을 쓴다는 이유로 해제되지 않는다.

## 5. 설계 확정 후 구현에서 검증·선택할 것

서비스 동작에 대해 질문한 항목은 최신 답변으로 확정했다. 별도 제출/시작 단계를 두지 않는 메시지 전송, 새 후속 작업 한도·누적량, 최대30분 종료, 현재 조사 후 계획 변경 반영을 적용한다. 이전의 즉시 취소/재시작·사용자 필수 원문 대조·시간 경고만 적용하는 안을 구현하지 않는다.

모델명은 실제 PC 검증 후 선택한다. 모델 후보·장비/라이선스·패키지 버전/호환성, 영속 그래프 저장의 실제 연결, DDL/마이그레이션, 추출/차트/PDF 라이브러리·폰트, 실제 오류 코드·로컬 요청 보호·성능/화면 세부는 구현 시 확인하고 선택한다. 기술 선택이 생기면 사용자 AGENTS 지침에 따라 질문한다.

초기 운영값은 성능 보장이 아니다. 실제 모델·자료의 결과가 설계 한도에서 충분하지 않으면 검증 누락을 숨기거나 한도를 자동으로 늘리지 않고 측정 결과와 수정안을 제시한다. 기존 사례에 남은 원문 대조와 수작업 기준표 준비도 실제 수행 결과로 보완한다.

## 6. 인계 산출물의 구분

이 폴더는 요구·흐름·데이터·API·검증 계약이다. 상신브레이크 폴더는 원문·일부 수치 검증·첫 초안이다. 도메인 공부 노트는 학습 자료다. 어느 문서도 IBK 직원용 전체 심사 매뉴얼·현직자 검증·운영 금융 기능이 이미 완성됐다는 증거로 쓰지 않는다.

## 7. 구현 시작 시 첫 작업

이 문서와 결정 기록을 읽고 기존 코드·실습 자료·키·DB·사례 원문을 보존한다. 필요한 기술 선택과 현재 환경을 확인한 뒤 단계0~1부터 구현한다. 첫 실행 목표는 상신브레이크 한 기업에서 회사 식별→자료/근거 저장→13개 계정 대조→일곱 항목/질문/차트 초안까지 연결하는 것이다. 후속 조사·복구·출력·비교 평가는 각각의 단계별 실제 시험으로 확인한다.

설계 문서를 읽었다는 사실이나 가짜 모델의 흐름 성공을 실자료 정확성·시간 절감·현직자 검증 완료로 소개하지 않는다. 사용자 요청 없이 지금 코딩을 시작하거나 별도 작업/외부 전송을 생성하는 문서가 아니다.

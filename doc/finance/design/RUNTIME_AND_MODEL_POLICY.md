# 운영 한도·오류 반복·모델 선택 정책

작성일: 2026-10-20 · 설계 기준1.0. 제품 코드·성능 시험을 작성하거나 실행한 결과가 아니다.

## 1. 확정한 초기 운영값

**전체 실행은 최대30분에 종료**한다. 마지막5분은 작성/검증에 남긴다. 새 자료에 대한 추가 조사에는 새 작업 한도를 주고 조사 전체 누적 사용량도 표시한다. 장애 복구는 새 작업이 아니므로 기존 잔여 한도로 이어간다.

모든 수치는 조정 가능한 실험값이다. 은행 기준이나 검증된 처리 성능으로 소개하지 않는다. 실행 시작 시 정책 스냅샷으로 고정한다.

| 항목 | 초기값 | 집계·제한 |
| --- | ---: | --- |
| 실제 외부 요청 | 60회/실행 | 페이지 추가·실패·재시도 포함. 캐시 읽기 별도 |
| 심화 행동 | 10회/실행 | 기본 조사 이후 쟁점별 추가 행동. 요청 개수와 구분 |
| 모델 호출 | 20회/실행 | 계획·분석·작성·검토·출력 구조 수정·실패한 호출 포함 |
| 실제 작업 시간 | 30분/실행 | 네트워크·모델 대기·재시도 대기 포함. 대기열·서버 정지 시간 별도 |
| 작성·검증 여유 | 마지막5분 | 새 수집 종료 후 확보 근거로 작성. 검증 통과 보장 아님 |
| 작성·검토·수정용 모델 호출 | 마지막 4회 확보 | 20회에 포함. 앞 단계에서 모두 소진하지 않음 |
| 외부 요청당 제한시간 | 최대 60초 | 남은 단계·실행시간이 더 짧으면 그 범위 안에서 종료 |
| 모델 호출당 제한시간 | 최대 180초 | 남은 작성·검증시간도 함께 검사 |
| 일시 조회 오류 시도 | 최초 포함 최대 3회 | 첫 실패 후 2초, 둘째 실패 후 5초 대기. 외부 요청·시간 한도에 포함 |
| 초안 수정 | 최초 작성 후 최대 2회 | 상한이지 의무 횟수가 아님. 정확성이 충족되지 않으면 해당 주장 보류 |
| 자동 복구 연속 실패 | 2회 실패 시 중지 | 서버 재시작으로 실패 수를 지우지 않음 |
| 동시 실행 | 1개 | 다른 조사는 대기. 화면 이벤트 구독은 실행을 소유하지 않음 |

외부 요청과 모델 호출은 실행 전에 잔여량을 확인하고 시작 사실·예약을 저장한다. 장애로 전송 여부가 불명확하면 소비량을 임의로 되돌리지 않고 불확실성을 기록한다. 복구는 같은 실행의 남은 한도로 이어가며 재시작이 새 예산을 만드는 경로가 되지 않게 한다.

## 2. 시간과 호출 여유의 우선순위

기본 모델 호출 예산 중 앞 단계가 사용할 수 있는 상한은 16회다. 모델 호출 여유가 4회에 도달하거나 수집/분석 작업시간이 25분에 도달하면 새 모델 기반 탐색을 시작하지 않고 작성·검증 단계로 전환한다. 단계 전환 시 어느 기준으로 전환했는지 기록한다. 외부 요청이나 심화 한도가 먼저 소진돼도 가능한 검증·작성은 잔여 예산 안에서 진행한다.

실제 호출의 제한시간은 60초/180초를 항상 끝까지 허용하는 값이 아니다. 전체 마감, 현재 단계의 남은 시간, 중단 여부를 먼저 확인한다. 마지막 5분에 180초 호출을 네 번 실행할 수 있다고 보장하지 않는다. 생성·수정·검증을 마감 안에 할 수 없다면 추가 호출을 시작하지 않고 지원되는 결과·미확인·수행하지 못한 검사를 표시한다.

초안 작성은 1회와 수정 최대 2회로 구분한다. 검토·수정도 총 20회와 작성용 잔여량을 사용한다. 구조화 데이터·수치·근거 검사는 실행 코드의 책임이며 모델의 자기평가 점수로 통과시키지 않는다. 이미 검증한 표·계산을 글을 다시 쓸 때 임의로 재계산하지 않는다.

## 3. 오류 분류와 반복

| 오류·상황 | 처리 | 초안에 남길 것 |
| --- | --- | --- |
| 일시 통신·제공처 오류 | 재시도 가능한 실패로 분류한 경우에만 최초 포함3회 범위에서 재요청 | 실패한 자료·시각·횟수·남은 한계 |
| 제공처가 대기시간 안내 | 그 조건을 우선 확인. 제시된 시간과 전체 마감을 지킬 수 없으면 해당 요청 보류 | 제공처 제한으로 못 한 범위 |
| 인증·잘못된 설정 | 같은 요청을 반복하지 않고 설정 필요 안내 | 수집 실패와 자료 부재 구분 |
| 정상 응답의 자료 없음 | 조회 조건·접수 이력 확인, 같은 실패를 맹목 반복하지 않음 | 실제 조회 범위와 자료 부재 |
| 표·기간·법인·단위 충돌 | 원문·정정·주석을 대조하는 조사 행동으로 처리 | 충돌 값·근거·사용 보류 범위 |
| 모델 형식·해석 오류 | 오류 항목을 기록하고 허용된 남은 호출·수정 범위에서 보완 | 검증하지 못한 설명을 사실로 게시하지 않음 |
| 모델 실행 불가 | 확보 근거 보존, 외부 모델로 자동 대체 금지 | 작성되지 않은 부분과 모델 상태 |
| 명시 중단·삭제 | 새 호출·자동 복구 발행 금지 | 저장 범위·명령 적용 상태 |

DART 오류 코드와 HTTP 상태의 실제 매핑은 구현 시 공식 계약·실응답으로 확인한다. 코드 번호를 추정해 처리표를 완성하지 않는다. 반복 상한은 작업 수준의 정책이고 전체 예산이 항상 우선한다.

자동 복구의 실패는 저장 지점부터 다시 실행하려 했으나 다음 정상 저장 지점에 이르지 못한 경우로 구분해 기록한다. 완료 작업·원문·게시본은 재사용하고 동일 산출물을 중복 게시하지 않는다. 복구 진행 여부와 연속 실패 수를 영속 저장한다. 인증 실패처럼 회복 불가한 원인은 2회가 될 때까지 반복하지 않는다.

## 4. 모델명 확정 시점과 평가 순서

사용자는 **선택 기준까지 설계하고 모델명은 구현 시 실제 PC에서 검증 후 확정**하도록 선택했다. 기존 실습 코드의 모델명은 검증을 마친 프로젝트 기본값으로 취급하지 않는다. 설계 완료를 특정 모델 다운로드나 성능 시험 완료와 혼동하지 않는다.

| 확인 항목 | 비교 과제 | 기록 |
| --- | --- | --- |
| 한국어 이해·작성 | 같은 근거에서 사실·해석·미확인·질문을 분리한 설명 | 근거 범위를 넘은 문장·해석 단정·누락 |
| 수치·표 구조 이해 | 같은 본표에서 법인·계정·기간·범위·단위를 올바르게 연결 | 값뿐 아니라 표 행/열·메타데이터 오류 |
| 근거 연결 | 제공한 원문 구간과 주장·질문을 연결 | 없는 근거 생성·다른 기간 인용·반대 근거 누락 |
| 구조 출력 | 같은 입력에서 도구 행동 후보·주장·질문 구조 생성 | 형식 성공과 의미 검증 결과를 분리 |
| 로컬 성능 | 실제 장비에서 같은 입력·설정으로 실행 | 메모리·응답/전체 시간·실패·콜드/웜 상태 |
| 한도 준수 | 계획·심화·작성에 필요한 호출과 문맥 처리 | 입력량·호출/토큰·수정 횟수·중단 가능성 |

모델 후보·라이선스·장비 사양·추론 설정은 구현 시작 시 확인하고 사용자와 선택한다. 정확성·근거 충족을 우선하며 더 작은 모델이나 빠른 응답 자체를 채택 이유로 삼지 않는다. 한 모델로 충분한지 또는 역할별 구성이 필요한지도 실제 비교 결과를 보고 결정한다. 현재 설계가 여러 모델의 동시 사용을 확정한 것은 아니다.

## 5. 교체 가능한 모델 호출 계약

기존 Ollama 연결과 선택적 OpenAI 연결을 유지한다. 호출부에는 역할·조사/기준/실행 ID·공개 가능한 근거 구간·허용된 도구/필드·출력 구조·남은 예산·전송 정책을 전달하는 계약을 둔다. 키·임의 실행 권한·NCS 원문을 전달하지 않는다.

| 역할 | 모델이 제안할 것 | 실행 코드가 결정·검사할 것 |
| --- | --- | --- |
| 계획 | 기본 항목과 자료 필요·추가 질문 후보 | 지원 범위·기준일·일곱 항목·예산 |
| 추가 조사 | 해결 질문·참조 근거·허용 도구와 입력·기대 정보 | 충돌/누락 우선·중복·범위·전송·호출 허용 |
| 설명 | 사실/해석/미확인 문장·지지/반대 근거 | 원문 위치·메타데이터·정확한 계산·출처 존재 |
| 질문 | 부족 정보·요청 이유·대상 기간·영향받는 쟁점 | 공개 조사 시도·중복·이미 답변된 질문 |
| 초안 | 근거 참조를 포함한 구조화된 보고서 | 주장·표·차트·버전·출력의 일치 |

모델 출력의 필수 필드·형식을 확인한 뒤 의미 검증을 별도로 한다. 형식이 맞는 답변도 잘못된 근거·기간·계정일 수 있다. 모델이 제안한 숫자나 도구 인자를 검증 없이 사실·행동으로 승격하지 않는다. 원문의 실행 지시·링크·스크립트는 조사 자료이며 시스템 지시가 아니다.

문맥 한도를 넘는 자료는 문서 구조·표·키워드 검색으로 필요한 구간을 고른다. 법인·기간·단위·머리글·주석 위치가 떨어지지 않게 전달하고, 제외·추출 실패 구간은 기록한다. 자료 일부만 읽은 상태를 전체 검토로 표시하지 않는다. 미검증 토큰 스트림과 게시 보고서를 구분한다.

## 6. 후속 입력의 실행 경계

사용자가 선택한 방식은 **현재 실행의 입력을 고정하고, 새 답변·정정 요청·파일은 다음 실행으로 자동 대기**시키는 것이다. 현재 작성·검증 중인 근거 집합에 새 입력을 끼워 넣지 않는다. 수신 사실·대기 상태·적용될 기준/입력을 표시하고, 기존 게시본은 새 버전 검증·게시 전까지 보존한다.

일반 메모는 ‘조사에 반영’을 선택한 경우에만 이 경로에 들어간다. 회사 변경은 새 조사, 목적·공개 기준일 변경은 새 기준 버전이다. 같은 메시지의 첨부는 한 입력으로 접수하며, 아직 시작하지 않은 같은 기준의 후속 입력은 이력을 보존해 함께 처리한다. 새 후속 실행에 초기 한도 스냅샷을 적용하고 누적 사용량을 표시한다. 조사 중단은 같은 조사의 대기 후속 실행까지 멈추고 사용자 재개 전 자동 실행하지 않는다. 계획 수정은 현재 조사 완료 후 다음 실행에 적용하며, 즉시 멈추려면 중단을 사용한다.

## 7. 종료 시각과 새 후속 작업

30분은 수집만의 시간이 아니라 실행의 조사·분석·작성·검증을 포함한 상한이다. 종료 시각에 남은 작업·호출의 취소를 요청하고 저장된 검증 결과로 제한 결과를 확정한다. 늦게 도착한 응답이나 검증 전 생성 문장은 자동 게시하지 않는다. 실행 상태와 종료 이유를 저장해 재시작이 시간·호출 한도를 초기화하지 않게 한다.

업로드 전송·대기열 시간은 실행30분과 구분한다. 사용자가 새 자료를 보내 생성한 다음 실행에는 새 한도를 적용하되, 입력 재전송·명시 중단 후 동일 실행 재개·서버 장애는 한도 초기화 이유가 아니다. 실제 새 자료/정정/수정 계획·입력 ID와 이전 실행의 관계를 기록한다. 한도 도달만으로 입력 없는 후속 실행을 자동 생성하지 않는다.

## 8. LangSmith 사용 보류와 구현 완료 후 검토

현재 금융 조사 실행은 LangSmith 외부 추적을 사용하지 않는다. 조사 상태·근거·수치 검증·보고서 버전은 로컬 저장소에 보관한다. 외부 추적을 사용하지 않아도 조사 실행·근거 연결·비교 평가는 완결되어야 한다.

구현 완료 뒤, 포트폴리오 시연과 에이전트 평가에 도움이 필요한지 별도 결정한다. 검토용 실행은 공개 DART·IR 자료와 직접 만든 가상 시험 자료만 사용하며, 실제 사용자 설명·첨부·내부 회수·차입·신청 자료와 NCS 제한 자료는 LangSmith에 전송하지 않는다.

| 비용·보존·삭제 | 무료/유료 한도, 보존 기간, 프로젝트·실행 삭제, 공유 링크와 접근권한을 확인 |

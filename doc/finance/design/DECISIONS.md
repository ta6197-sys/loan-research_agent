## 2. 설계 확정 상태와 구현 시 검증 항목

서비스 동작에 대해 이번 설계에서 질문한 사항은 모두 정리했다. 계획 변경은 사용자의 마지막 명시적 답변인 **현재 조사 완료 후 수정 계획으로 추가 조사**를 적용한다. 첨부는 별도 제출/시작 흐름을 두지 않고 기존 메시지 전송에 통합한다. 기존 첨부 한도 D26은 변경 요청이 없으므로 조정 가능한 초기 설정으로 유지한다.

현재 범위는 기업별 조사·보고서와 한 번에1개 실행/나머지 대기다. 화면 제품 형태나 한 보고서에 여러 기업을 혼합하는 기능을 새로 선택한 것이 아니다. 이전 Q23~Q30의 논의와 실제 결정은 [최종 검토](FINAL_REVIEW.md)에 보존했다.

**구현 시 검증 후 선택하기로 한 내용:** 실제 PC의 모델명·모델 설정, 패키지 버전/호환성, 영속 그래프 저장의 구체 연결, 테이블 DDL·마이그레이션, 추출/차트/PDF 라이브러리·한글 폰트, 실제 오류 코드·성능·화면 세부. 미검증 기술 선택을 이미 실행 확인된 구현으로 소개하지 않는다. 이후 코딩에서 새로운 동작이나 기술 선택이 생기면 사용자 지침에 따라 질문한다.

## 3. 질문의 경계

개발·설계 과정에서는 사용자가 선택할 동작·범위·우선순위를 반드시 질문한다. 합의한 규칙을 일관되게 표현하는 식별자·문서 편집과, 새 동작을 결정하는 일은 구분한다.

서비스 실행 중에는 합의한 범위 안에서 조회·대조를 스스로 진행한다. 내부 정보 필요, 추가 조회로 해결되지 않는 충돌, 기업·주제 범위 확대를 구체적으로 묻는다. 중요한 이유 없이 모든 조회를 승인 요청으로 바꾸지 않는다.

## 4. 설계 변경 기록

- 사용자 요구로 현재 작업을 ‘설계까지만’으로 명확히 제한했다.
- 비교 정책 질문에 대해 사용자가 근거 조사를 요청했다. 기존 제안을 확정하지 않고 [조사 결과](COMPARISON_POLICY_RESEARCH.md)에 기관 요건·회계 기준·서비스 판단을 구분했다.
- 상세 설계의 상태·테이블·API 이름은 구현 인계를 위한 제안 명칭이다. 사용자의 미응답 동작을 이름만 붙여 확정한 것으로 취급하지 않는다.

- 최신 답변: 세부 최소 확인표와 본문 13개 계정, 서버 재시작 자동 재개, 일반 기업의 기본 두 차트 주제를 확정했다.
- 수정한 기본 비교 정책·운영 한도·첨부 한도·검색·동시 실행·화면·읽기 전용 정책도 결정 기록에 동기화했다.

- 사용자는 자료 연결·검증 가능한 초안·변화의 추가 확인·이유가 있는 질문·수치/원문 추적에 집중하도록 지시했다. Q12·Q15·Q16은 D34~D36으로 확정했다.

- 최신 답변으로 Q17·Q19를 D37·D39로 확정했고, Q13의 평가 범위는 D38로 확정했다. 평가 반복 수·수용 기준은 이후 D42로 확정했다.

- 최신 답변으로 Q07·Q13·Q18의 모델 선정 시점·반복 상한·평가 조건을 D40~D42에 반영했다. 호출별 시간·호출 배분·실행 중 후속 입력의 적용 시점은 Q20~Q22로 구분해 질문했다.

- 사용자가 이후 질문은 한 번에 모아 달라고 요청했다. 세부 질문을 순차로 새로 발행하지 않고 최종 점검에서 남은 동작을 묶어 확인한다.

- 사용자 설명 요청에 따라 파일 전송/조사 묶음·시간 한도·복수 기업 범위를 재검토했다. 이후 D50~D53과 기존 기업별 조사 범위로 정리했다. 중단·제한 결과·에이전트 원문 대조는 유지했다.

- 최종 명시적 답변: 현재 조사 완료 후 수정 계획으로 추가 조사(D53). 메시지 전송 통합(D50), 새 후속 한도/누적 사용량(D51), 최대30분 종료(D52), 중단·제한 결과·에이전트 검증 유지. 서비스 동작의 설계 선택을 마무리했다.

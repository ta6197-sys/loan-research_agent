# 화면·보고서·내보내기 설계

버전 1.0. 제품 화면 코드는 작성하지 않았다. 아래 배치는 기존 Vue 화면을 확장할 작업 명세다.

## 1. 합의한 화면 방향

보고서와 원문 근거를 함께 검토하는 화면을 중심으로 두고 대화는 보조로 둔다. 생성 본문은 읽기 전용이며 정정 요청·답변·메모를 제공한다. 원시 프롬프트·모델 내부 추론·API 키·실습용 장애 지표를 사용자 업무 화면에 노출하지 않는다.

화면 배치안:

```text
[조사 목록]  [회사·목적·공개 기준일·별도/연결·보고서 버전]
             [진행 요약·중단·설정/범위 확인]
             [보고서 본문]               [선택한 근거 원문]
             [핵심 요약]                 [보고서·절/표·기간·단위]
             [우선 질문]                 [선택 수치·원문 위치]
             [표·차트·쟁점]              [관련 반대 근거·대조 상태]
             [질문/대화·진행 이력·버전 변경 구역]
```

좁은 화면에서는 원문 구역을 별도 패널로 열되 보고서의 선택 위치를 보존하는 안을 제안한다. 픽셀 단위 크기·색상·탭 개수는 이후 시안 검토 대상이다.

## 2. 화면별 표시와 행동

| 화면/구역 | 표시 | 가능한 행동 | 중요한 예외 |
| --- | --- | --- | --- |
| 조사 목록 | 회사·목적·기준일·진행·최신 초안·미해결 질문 | 새 조사·이전 조사 열기·삭제 | 삭제 전 대상·포함 자료를 구체적으로 안내 |
| 시작 | 회사·목적·기본 비교 범위·선택 파일 | 회사 식별·설명/조건 추가·시작 | 후보가 여러 법인이면 선택 요청 |
| 계획·진행 | 일곱 항목, 현재 확인 중인 자료·목적·이미 확인한 범위 | 계획 수정·중단·질문 답변 | 계획 표시는 승인 대기 화면이 아님 |
| 보고서 | 요약·질문·기준·사업·13개 수치·차트·쟁점·부록 | 근거 선택·다운로드·정정 요청 | 새 실행 중에도 이전 게시본 열람 가능 |
| 근거 | 원문·절/표·범위·기간·단위·정정·조회 정보 | 관련 근거 간 이동 | 실패한 원문은 이유·공식 링크·복구 경로 표시 |
| 질문·답변 | 질문·이유·관련 쟁점·공개 조사 시도·해결 상태 | 답변·파일·추가 설명 | 답변 수신을 확인 사실로 자동 표시하지 않음 |
| 이력 | 조회 목적·발견·설명 변경·중단/재개·게시 버전 | 이전 버전·차이 확인 | 단절·재시작으로 이전 기록이 없어지지 않음 |
| 설정 | 로컬 모델 상태·키 설정 여부·예산·첨부 한도·외부 전송 | 허용 범위와 새 실행 기본값 조정 | 실제 키를 화면·로그에 다시 출력하지 않음 |

등록 버튼 중복 클릭·재전송은 같은 요청으로 인식한다. 새 버전이 게시되면 보고 있던 과거 버전을 강제로 덮지 않고 새 결과와 변경 사실을 알린다. 근거 원문 링크를 열어도 조사 화면으로 돌아올 위치가 남아 있어야 한다.

## 3. 보고서 순서와 내용

머리말에는 법인·목적·공개 기준·재무 범위·보고서 버전을 표시한다. 본문 순서는 핵심 요약→우선 질문→조사 기준·사업→재무 표·차트→쟁점→근거·계산·확인 범위 부록이다. [기본 양식](../REPORT_TEMPLATE.md)을 구체화한다.

핵심 요약은 사실·해석·한계를 함께 연결한다. 위험 등급·승인 의견을 자동 추가하지 않는다. 질문에는 필요한 정보와 이유, 어떤 설명을 바꾸는지, 공개 자료에서 먼저 확인한 범위를 남긴다.

각 기본 항목에는 ‘어디까지 확인했고 무엇이 남았는가’를 표시한다. 일곱 항목 모두에 ‘완료’라는 단어만 붙여 세부 미확인을 숨기지 않는다. 주석·공시 사건은 자료의 기준일/발행일과 현재 확인 수준을 구분한다.

## 4. 수치 표·비교 열

본문에는 합의한 13개 계정을 표시한다: 매출·영업이익·순이익, 영업현금흐름, 현금·재고·매출채권 및 기타유동채권, 단기·유동성장기·비유동 차입금, 자산·부채·자본. 차입 합계는 구성과 리스 포함 여부를 명시한 계산값으로 추가할 수 있다.

표를 나누는 기준:

| 표 | 열의 기준 | 주의 |
| --- | --- | --- |
| 연간 손익·현금흐름 | 최근 3개 회계연도 각각의 누적 | 결산기 변경·재작성 비교 여부 표시 |
| 연말 재무상태 | 같은 세 연도 말 | 기간 누적과 잔액을 제목에서 구분 |
| 최신 중간 손익·현금흐름 | 이번 누적/중간기간과 전년 동기간 | 3개월과 누적을 같은 열에 섞지 않음 |
| 최신 중간 재무상태 | 이번 기간 말과 직전 연말 | 전년 동기 말은 목적이 있을 때 보조 열/표 |

열에 단위·기간·별도/연결을 명확히 쓴다. 각 수치에는 원문·검산으로 이동할 참조를 붙인다. 지표에 필요한 값이 없으면 ‘미확인(이유)’로 표시하고 차트는 해당 값을 0으로 그리지 않는다.

## 5. 차트

기본 두 주제는 영업이익·영업현금흐름과 현금·차입금이다. 비교 가능한 자료에서만 만들며 쟁점에 따라 추가한다. 모든 기업에 개수 네 개를 강제하지 않는다.

흐름 지표는 동기간, 잔액 지표는 명확한 기준일끼리 비교한다. 전년 동기 말 잔액 차트는 보조 분석임을 표시한다. 주석의 만기표를 차트로 만들려면 범위·원금/이자·전체/일부 차입의 의미를 먼저 확인한다.

차트 구성은 같은 검증 데이터 ID와 계산 ID에서 생성한다. 연결/별도 비교가 필요한 경우 계열명에 범위를 쓰고 서로 다른 범위의 현금과 차입을 한 비율로 만들지 않는다. 색상만으로 시리즈를 구별하지 않고 범례·값·음수·단위·원문을 표시한다. 축 생략·이중축으로 변화가 과장되지 않도록 검토한다.

## 6. 수정·메모·후속 자료

생성 본문은 읽기 전용이다. 정정 요청이나 질문 답변이 들어오면 연결 쟁점을 재검토하고 새 보고서 버전을 제공한다. 사용자 문장을 그대로 ‘검증된 사실’로 교체하지 않는다. 일반 메모는 저장만 한다. 사용자가 ‘조사에 반영’을 선택하면 해당 메모를 출처가 표시된 후속 입력으로 접수해 재조사한다. 단순 메모 저장만으로 실행을 시작하거나 보고서 버전을 올리지 않는다.

현재 작업 중 사용자가 계획을 바꾸면 새 계획을 저장하고 ‘현재 조사 종료 후 반영’으로 표시한다. 현재 실행은 고정한 계획으로 마친 뒤 수정 계획을 후속 실행에 적용한다. 즉시 멈추고 싶으면 중단을 사용하며, 중단은 대기 중인 후속 실행도 멈춘다. 회사 변경은 새 조사로 분리한다. 목적·공개 기준일 변경은 같은 조사의 새 기준 버전으로 남긴다. 이전 보고서·근거·실행 이력을 보존하고, 새 기준으로 재사용할 자료의 적합성을 검사한다.

## 7. PDF·Markdown 출력

화면·PDF·Markdown은 동일한 게시 보고서 버전과 참조 manifest에서 만든다. 출력 요청 후 더 최신 보고서가 생겨도 요청한 버전을 내려준다. 미확인·자료 충돌·범위 제한을 내보내기 과정에서 생략하지 않는다.

PDF 요구: 한글 폰트, 표의 페이지 나눔·반복 머리글, 차트 잘림 방지, 읽을 수 있는 단위·음수·출처, 페이지 번호·버전, 클릭 가능한 공식 원문 링크와 사람이 읽을 수 있는 위치 설명. 파일 생성 성공만으로 출력 검증 완료로 간주하지 않는다.

Markdown 요구: 제목·표·근거 링크·차트 참조가 다른 뷰어에서도 읽혀야 한다. 로컬 절대경로·앱 내부 전용 주소·비밀값을 내보내지 않는다. 사용자가 선택한 구성은 Markdown·차트·근거 목록 ZIP이다. ZIP 안에서 이미지는 상대경로로 참조하며, 근거 목록에는 공식 링크·원문 위치·기간·범위·보고서 버전을 남긴다. 파일을 다른 PC로 옮겨도 차트를 볼 수 있어야 한다. 원문·사용자 첨부 전체를 보고서 다운로드에 자동 포함하지 않는다.

보고서에서 사용자 제공 자료를 인용하면 파일명·기준·위치를 표시하되 공개 공시와 구분한다. NCS 원문·도표·서식은 결과물에 넣지 않는다. PDF/문서 생성 라이브러리 선택은 출력 요구 충족 여부를 확인할 구현 세부다.

## 8. 완료·중단·한도 표시

‘초안 제공’과 ‘미해결 없음’을 구분한다. 표시할 내용은 게시 버전, 확인한 항목·근거, 미해결 질문, 한도/장애로 수행하지 못한 작업, 후속 조사 가능 행동이다. 실제 작업 시간과 사용자의 답변 대기를 구분한다.

화면 재접속 시 현재 실행을 자동 재시작하지 않는다. 서버 재시작 시 예기치 않게 끊긴 실행은 자동 복구 정책을 따르고, 명시적 중단·삭제·한도 종료는 다시 실행하지 않는다.

## 9. 최근 사용자 답변 반영

- 조사 중단은 현재 실행과 같은 조사의 대기 후속 작업까지 적용한다. 사용자의 재개 전 자동 실행하지 않는다.
- 모델 오류나 제한으로 본문을 완성하지 못해도 검증된 수치표·계산·근거와 미완성/미검증 부분을 제공한다. ‘보고서 완성’으로 표시하지 않는다.
- 원문 대조는 에이전트가 수행하고 검사 항목·근거 위치·결과·수행하지 못한 범위를 보여준다. 사용자에게 필수 최종 대조를 요구하지 않는다.
- 첨부한 메시지를 전송하면 자동으로 조사한다. 별도 파일 제출/조사 시작 버튼은 없으며, 같은 메시지의 파일은 한 입력으로 접수한다.
- 최대30분 안에 실행을 종료하고, 새 추가 조사에는 새 작업 한도와 누적 사용량을 표시한다.
- 기업별 독립 조사, 한 번에1개 실행·나머지 대기를 유지한다.

## 10. 첨부 포함 메시지 전송

사용자 행동은 파일 첨부·메시지 전송이다. 별도 자료 제출이나 조사 시작 단계를 추가하지 않는다. 파일 선택을 여러 번 하거나 전송을 내부적으로 나누더라도 같은 메시지에 포함된 파일 목록을 먼저 확정해 하나의 입력으로 접수한다. 메시지 전송을 접수한 뒤 조사 계획을 표시하고 자동 실행하거나 현재 실행 뒤 대기시킨다.

첨부 전송 완료·실패·처리 가능 여부는 파일별로 표시한다. 실패한 파일을 조용히 제외하고 전체 입력을 조사했다고 안내하지 않는다. 새 파일을 나중에 별도 메시지로 보내면 그 메시지의 수신/대기 상태를 표시하고, 실행 중인 입력에 끼워 넣지 않는다. 전송 중복은 메시지/파일 식별자로 제거한다. 첨부 한도는 설정값과 누적량을 함께 안내한다.

# 7단계 — 중단·재개·서버 종료 후 복구

2026-10-21 사용자는 화면보다 **7단계 중단·재개·복구**를 우선하고, **현재 FastAPI 안의 실행 관리자 + SQLite 저장**을 선택했다. 별도 Redis·작업 서버·새 외부 서비스를 추가하지 않았다. 현재 구현/시험 범위는 보관한 상신브레이크 조사·텍스트 후속 입력이다. 일반 신규 기업 자동 수집·첨부·화면·실무 검토의 완성이 아니다.

## 동작

| 상황 | 처리 |
| --- | --- |
| 브라우저 연결 종료 | 서버 내부 관리자가 계속 실행. HTTP 응답은 접수이며 모델 실행의 소유자가 아님 |
| 사용자 중단 | 같은 조사의 실행/대기를 중단하고 현재 작업을 취소. 새 답변·서버 재시작으로 자동 해제하지 않음 |
| 명시 재개 | 같은 실행 ID·고정 입력·예산·사용량·모델 시도 횟수로 이어감. 새 한도를 만들지 않음 |
| 서버 비정상 종료 | 저장된 단계에서 같은 실행으로 복구. 원문/검증을 다시 확인하고 저장된 초안은 재사용 |
| 전송 후 모델 결과 불명 | 요청 전에 예약한 모델 횟수를 보존. 이전 결과를 받았다고 추정하지 않으며 남은 최대3회 시도 안에서 처리 |
| 복구 연속2회 실패 | 영속 실패 수와 이유를 남기고 자동 실행 중지. 재시작으로 실패 수를 초기화하지 않음 |
| 마감 | 기본30분의 남은 시간에 작업 취소를 요청. 최종 검증이 미완료면 새 판을 게시하지 않고 이전 판·근거와 제한 결과를 유지 |
| 여러 서버/CLI | DB별 OS 파일 잠금의 소유자만 실행/복구. 다른 서버는 읽기/접수 가능. 직접 실행 CLI도 같은 잠금 적용 |

## 저장과 게시

v5 마이그레이션은 `research_executions`만 추가한다. 실행/요청 키별 단계·고정 상태·모델 시도·미완료 호출·복구 실패·소유자를 저장하며 원래 보고서·원문·대화 행을 수정하지 않는다. 실행 상태·사용량·단계 체크포인트는 짧은 트랜잭션으로 저장한다. 실제 기존 수집 DB를 열어 변환하지 않았으며 분석 복사본과 임시 DB에서 검증했다. 이후 사용자가 서버를 열면 저장소 마이그레이션이 적용된다.

`execution_journal.py`는 계획·조사 문맥·검증된 모델 결과를 저장한다. `research_stage05.py`의 LangGraph는 재개 시 완료한 계획/초안을 재사용하고 수치 배치·원문 위치·해시·현재 문맥·모델 계약을 다시 확인한다. 모델 시도는 최초+최대2회 수정으로 실행 요청 전체에서3회이며 재시작으로 늘어나지 않는다. 전체 모델20회 한도도 별도로 유지한다.

게시본·게시 이력·워크플로 완료 상태는 같은 트랜잭션으로 저장한다. 보고서를 게시한 뒤 서버가 꺼져도 같은 요청 키를 다시 게시하지 않는다. 실행마다 소유자 ID를 검사하고, 다른 서버에서 명시 재개하면 이전 소유자를 무효화한다. 늦은 응답이 새 실행 상태/보고서를 덮어쓰지 못한다.

`research_runtime.py`는 승인된 작업과 후속 입력을 한 번에 하나씩 실행한다. 시작할 때 끊긴 실행을 복구 대기로 바꾸되 명시 중단과 종료된 실행은 제외한다. 접수 이벤트만 있고 원문 저장 전에 끊긴 입력도 같은 입력 ID로 완성한다. 정상 저장 지점에 도달하면 연속 복구 실패는0으로 돌아가며 누적 `Usage.recovery_failures`는 줄이지 않는다. 복구 중 다시 종료된 경우와 분류한 일시 파일 I/O 실패는 횟수를 보존해 제한하고, 근거 훼손 등 검증 오류는 맹목적으로 반복하지 않는다.

실행 시간은 단조 시계로 계산하고 약1초 간격으로 다음 구간을 미리 사용량에 기록한다. 강제 종료해도 최근 구간을 무료로 되돌리지 않도록 초 단위 올림으로 최대 약2초를 보수적으로 계상할 수 있다. 서버 정지·대기열·사용자 답변 대기 시간은 새로 합산하지 않는다. 정지 전 예약 사용량은 환불하지 않는다.

전체 남은 시간의 비동기 마감 감시와 단계/게시 직전 검사를 함께 적용한다. 취소할 수 없는 로컬 추출 스레드는 반환까지 끝날 수 있지만, 마감/중단 뒤 새 모델 요청·게시를 허용하지 않는다. 마감 시 최종 검증을 끝내지 못한 결과는 `limited_result.publication_status=not_published`로 표시하며 저장된 이전 검증 문맥의 범위를 알려준다. 마감만으로 금융 확인을 통과시키거나 새 후속 실행을 만들지 않는다.

## API와 시작

- `POST /runs/{id}/drafts`는 이제 202 접수 응답 후 관리자가 실행한다. `request_key`를 저장하고 연결 종료와 독립적으로 진행한다. 일반 신규 기업 전체 조사 시작 API는 아니다.
- `POST /researches/{id}/inputs`는 기존처럼202 접수/후속 대기다.
- `POST /researches/{id}/stop`은 실행 중·대기 작업까지 중단한다.
- `POST /researches/{id}/resume`는 `{"request_key":"재개 명령 고유 키"}`를 받아 남은 한도로 같은 실행을 재개한다. 같은 재개 키의 재전송은 새 재개/한도를 만들지 않는다.
- `GET /runs/{id}/execution`은 단계·모델 시도·복구 상태·저장 문맥·제한 결과를 반환하고 내부 소유자 ID는 제외한다.
- `/events`, `/runs/{id}`, `/reports/{id}`와 보고서 목록의 기존 조회를 유지한다.

서버 시작 시 저장된 승인 대기/복구 작업이 있으면 처리한다. 새 조사를 자동 생성하지 않으며 명시 중단은 유지한다. 작업이 없는 저장소의 시작은 DART·모델 호출을 하지 않는다. 예전 코드에서 재개 지점을 저장하지 않은 실행은 `interrupted/checkpoint_missing`으로 남기고 모델 결과/시도 이력을 추정해 자동 재실행하지 않는다. 이미 게시한 판은 계속 볼 수 있다.

## 검증

합성 단위 수용 시험12개가 단일 소유자/CLI 우회 거부, 중단·명시 재개, 서버 종료 후 같은 예산 복구, 명시 중단 유지, 연속 복구 실패 보존, 저장 초안 재사용/중복 게시 방지, 중단 반복에도 모델 최대3회,2초 축소 마감과 미게시 제한 결과, 재개 지점 없는 과거 실행 거부, 일시 실패 자동 복구2회 중지, 접수 후 원문 미등록 복구, 다른 서버 재개의 이전 소유자 차단을 확인했다.

실제 HTTP 서버 강제 종료/재시작 시험:
`data/research/validation_stage07/20261021T090706Z-676b4752/result.json`.

- 서로 다른 로컬 서버8개(PID87919,87934,87944,87946,87949,87953,87955,87957)를 기동하고 시험 서버만 종료했다. 실제 기존 공시·수치 검증은 재사용/재검사했고 **모델은 시험 전용 합성 응답**이다. 실모델의 생성 품질/복구 시간 평가로 소개하지 않는다.
- 초안 저장 뒤 강제 종료해도 모델 요청1회를 그대로 유지하고7판을 게시했다.
- 모델 요청 뒤 중단·재시작 시 자동 실행하지 않았으며, 명시 재개 뒤 같은 실행으로 이어가2회 사용량을 유지하고8판을 게시했다.
- 복구가 정상 저장 지점에 도달하기 전에 두 번 다시 종료되자 연속 실패2회/누적 실패2회로 중지했다. 해당 실행의 모델 사용량은1회이며 추가 게시하지 않았다.
- 기존1~6판 보존·새7~8판과 모든 이전 판의 HTTP 내용 일치. 원본 분석167파일 변경/삭제0. 시험용 합성 모델 호출은 총4회이며 실제 모델·외부 자료·외부 추적 호출은0이다.

7·8판의 입력도 합성 생명주기 시험이며 실제 회사 답변/내부자료가 아니다. 6단계의 실제 로컬 모델5·6판과 시험 성격을 구분한다. 4단계 구현 완료·기존 금융 미확인은 그대로 유지한다. 최신 전체 회귀/소스 지문 결과는 [진행 기록](IMPLEMENTATION_LOG.md)의 마지막 항목을 따른다.

```bash
.venv/bin/python -m unittest tests.test_research_runtime -q
.venv/bin/python sh/verify_stage07_runtime.py \
  data/research/validation_stage06/20261021T084149Z-6f04ab4a
```

두 번째 명령은 새 분석 복사본과 합성 모델 시험 서버를 만든다. 기존 결과 재조회에 실모델을 추가 호출할 필요는 없다. 실행 잠금 파일은 Git/배포 ZIP에서 제외한다.

## 남은 범위

보관 사례 외의 일반 기업 수집·첨부/OCR·계획 수정의 제품 입력·금융 화면/출력·실무 평가가 남아 있다. 다중 PC 분산 실행·독립 워커·다중 사용자 인증/인가를 구현하지 않았다. 현재 상태/잠금은 같은 PC의 로컬 PoC 범위다. DB 수정 권한자에 대한 감사 무결성·암호화·DLP 등의 보안 한계는 [README](../../README.md)를 따른다. 원본 수집 예산12/20·추가15/20과 금융 미확인16묶음을 유지한다.

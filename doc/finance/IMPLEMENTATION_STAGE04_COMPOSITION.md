### 새로 질문한 내용 — 답변 대기

한 문서에 명시적0원 대출 행이 있고 다른 문서에는 그 행이 없는 경우, 계약 항목 전체 일치와 **양수 잔액 구성 일치**를 구분할지 질문했다. 추천안은 원래0원 행을 보존하고 양수 잔액 항목 전체의 명칭·각 금액·합계까지 일치한 경우만 잔액 구성 기준으로 계정 합계 연결을 허용하는 것이다. 계약 목록 전체나 은행별 일정이 같다고 표시하지 않으며 빈칸/대시/불명확한 항목은 제거하지 않는다. 다른 선택은 명시적0원 행까지 모든 항목이 같아야 연결하는 것이다.

이 선택은 아직 적용하지 않았다. 은행/대출 명칭 변형의 자동 연결도 승인하거나 구현하지 않았다. 현재 엄격 대조와18개 구성 보류를 유지한다. 후속 변경은 사용자 답변 후 해당 범위만 구현·검증한다. NCS 본문을 복사·모델 적재·외부 전송하지 않았으며 기존 키·DB·원문·사례는 보존한다.


## 2026-10-21 — 명시적 0원 행 후속 선택 확정

사용자는 ‘전체 항목·잔액 구성 구분 후 제한적으로 사용’을 선택했다. 원문에 명시된0원 항목과 계약 항목 전체를 보존하면서, 양수 잔액 구성의 명칭·각 금액·빠짐없는 합계가 같은 경우에 한해 계정 합계 연결에 사용할 수 있도록 다음 보완에서 구분한다. 빈칸·대시·불명확한 항목을 제외하거나0원으로 바꾸지 않는다. 계약 전체·은행별 상환 일정의 동일성 확인으로 확대하지 않는다.

이 답변을 받은 시점에는 아직 코드 반영·후속 재검증을 수행하지 않았다. 최신 검증 결과는 계속 numeric-validation-1.22의 구성 보류18개/금융 필수·추가·4단계 미완료다. 사용자의 현재 요청인 진행 현황 설명은 이 상태를 기준으로 한다. 앞의 ‘답변 대기’ 기록은 이 선택으로 해소됐다.


## 명시적0원 보존·양수 잔액 구성 검증 결과

사용자가 승인한 ‘전체 항목·잔액 구성 구분 후 제한적으로 사용’을 구현했다. 기존 다섯 독립 검증 축은 유지하고 `composition_identity` 안에서 `all_disclosed_items`(공시상 전체 항목)와 `positive_balance_items`(양수 잔액 항목)의 판정·근거·차이 목록을 별도로 저장한다.

공시상 명시적0원 항목은 원문 명칭·금액·위치·소스·상세검증 ID와 함께 `zero_items_preserved`에 보존한다. 원본 항목을 삭제하거나 다른 문서의 누락된 행을0원으로 채우지 않는다. 빈칸/대시/불명확한 상세가 있으면 완전한 양수 잔액 구성 확인에 사용할 수 없다. 양수 항목의 명칭·각 금액·합계·공식 계정 코드·회사·실행·별도/연결·기준일·통화가 모두 맞는 경우만 잔액 기준으로 사용한다. 유동/비유동 차입은 기존 재분류 산술 요건도 유지한다.

사용 범위에 `account_total_identity_basis`와 `all_disclosed_items_match`를 추가했다. 전체 항목이 달라도 잔액만 일치하면 `account_balance_totals_only`다. 이 상태를 전체 계약/공시 항목 일치, 은행별 상환 배분 확인으로 확대하지 않는다. 해당 계정 합계·증감 계산에도 `composition_usage`로 검토 ID·사용 범위·제한을 연결하고 수용 판정에서 재계산한다. 계산의 제한을 제거하거나 은행별 분석 확인으로 바꾸면 실패한다.

최종 정책 `numeric-validation-1.24`, 검증 축 `borrowing-verification-levels-1.2`, 구성 검토 `composition-review-1.2`, 수용 판정 `stage04-acceptance-1.13`이다. 과거1.1 구성 검토는 기존 엄격한 전체 항목 기준으로 재평가하며 새 잔액 허용을 소급하지 않는다. 이전1.22 분석 자료는 그대로 보존하고 현행 수용 판정에서도 종전 미완료 상태가 유지됨을 확인했다.

### 남은 은행명 표기 검토

사용자는 **공식 근거가 확인된 은행 표기쌍만 지원**하는 원칙을 승인했다. 보관한 공식 DART 기업 목록의 ZIP 해시를 검증한 뒤 `농협은행` 고유번호 `00908757`을 확인했다. 기존 공시의 `농협은행(주) 시설자금대출`과 `(주)농협은행 시설자금대출` 원문 위치·영문 설명을 함께 기록했다.

다만 공식 목록 자체가 이 두 변형 표기를 함께 직접 열거하는 것은 아니다. ‘(주)’ 위치만 다른 두 정확한 표기를 공식 목록의 같은 이름으로 연결하는 **해석을 명시해 이 한 쌍만 지원할지**, 두 표기의 관계를 명시한 추가 자료까지 기다릴지 질문했다. 이 선택은 아직 은행 연결 규칙에 적용하지 않았다. 영문 설명 일치를 고유 계약 식별자로 쓰거나 운영자금/운영자금대출까지 묶지 않는다. 새 외부 조회도 하지 않았다.

`bank_identity_candidate.json`에 공식 목록 출처·해시·갱신 시각·법인 식별과 두 공시의 원문 근거, 부족한 점을 저장했다. 답변 전에는 은행 별칭을 적용하지 않으며 현재16개 구성 보류를 유지한다.

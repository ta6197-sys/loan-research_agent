# SK㈜ 정기공시 기반 분석 현황 (2026-10-26)

현재 운영 `session.db`를 읽기 전용으로 확인했다. SK㈜ 법인코드 `00181712`의 조사에는 원문 레코드 96건, 검증 배치 3건, 보고서 작업본 3건이 있다. 기존 원문·배치·작업본을 수정하지 않았다.

최신 보고서 작업본(`c709b997eef74fea8ced2f8c878c9dff`)의 `context.financial_rows`는 130행이다. 이 중 `verified` 8행, `withheld` 122행이다. 확인 8행은 연결 범위의 총자산·부채총계·자본총계(2025-12-31, 2026-06-30)와 연결 영업현금흐름(2025년·2026년 각 상반기)이다. 보류 행에는 `input_missing` 사유가 있다. 현재 자료만으로 매출액, 이익, 운전자금, 차입금에 관한 범용 비율·변화 분석을 임의 완성할 수 없다.

이전 일반기업 수집 실행의 비교기간 계획에서는 2023·2024·2025년 사업보고서와 2025년 반기보고서 접수번호가 `null`이었고, 2026년 반기보고서만 `20260814002185`로 연결됐다. 당시 API 요청·원문 저장은 별도 수행됐지만, 이 계획의 접수번호 공백은 정정 접두어를 인식하지 못한 문제와 함께 최신본 대응을 다시 살펴야 하는 이유다. 새 코드로 재수집하기 전에는 실제 결손 원인을 확정하지 않는다.

보고서 3건은 모두 `building`이며 게시된 결과가 아니다. 재무 분석 API와 UI가 요구하는 게시본으로 취급하지 않는다. 기존 수치 검증 배치의 정책 버전은 `numeric-validation-1.27`이고, 중간 XBRL 매핑 배치는 `xbrl-mapping-1.6`이다. 이후 검증 코드는 더 발전했으므로 현재 운영 작업본을 새 규칙의 통과 결과로 소급하지 않는다.

이번 범용 수집 수정은 공시명 앞의 `[기재정정]` 등 표식을 제거하고 정기보고서 종류를 판정해, 최신 정정본이 수집 계획과 결산월 확인에서 빠지는 오류를 막는다. 실제 SK㈜ 재수집이나 검증 배치 재실행은 아직 수행하지 않았다. 다음 실제 실행은 새 불변 실행을 만들고 공개 기준일·요청 예산을 고정한 뒤 원문/API/XBRL 네 가지 게이트를 적용해야 한다.

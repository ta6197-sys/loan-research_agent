## 미게시 검증 데이터 분석 화면

새 읽기 전용 `GET /api/runs/{run_id}/verified-analysis`는 완료된 범용 수집 실행에서 같은 실행의 수치 검증 배치와 XBRL 배치를 각각 하나씩 요구한다. 결산월·실제 대상 기간을 재구성하고 원문 파일 해시·위치를 다시 확인한 뒤, 독립 XBRL 계정·기간·금액 게이트를 통과한 행만 결정론적 재무지표에 전달한다. 응답은 `report_id: null`, `publication_status: not_published`로 게시본과 구분하며 검증·보류 행, 계산 가능 지표, 계산 보류 이유, 후속 자료 요청 후보, 원문·검증 ID를 제공한다. 비교집단 통계와 ML은 이 실행에 연결된 적격 스냅샷이 없어 제공하지 않는다. 검증 배치·원문·기존 보고서는 변경하지 않는다.

SK㈜ 재실행 `a2121e8cb8cd41eab7af9a9111b5b4a3`의 실제 API 조회는 HTTP 200, 검증 8행·보류 122행, XBRL 게이트 `pass`, 계산 가능 지표 4개, 후속 자료 요청 8개였다. 분석 조회는 약 3초에 끝났으며 모델·외부 API를 호출하지 않았다. Vue 화면은 이 미게시 실행의 수치·지표·보류 사유를 게시 보고서와 구분해 표시한다. 이 조회로 보고서나 PDF·ZIP이 생성되는 것은 아니다. `node sh/test_finance_analytics_ui.cjs`와 전체 Python 회귀 435개가 통과했다. 전체 회귀 중 실제 HTTP 재시작 시험은 로컬 루프백 소켓 권한이 필요해 허용된 환경에서 재실행했다.

원문 근거 탐색은 검증된 행의 `fact_id`에서 원문 조각·공시 접수번호·표와 행 위치·원문 해시를 읽기 전용으로 연결한다. 화면의 수치 또는 지표에서 해당 근거를 선택할 수 있고, DART 공시 링크와 검증 위치의 원본 바이트 다운로드를 제공한다. 보류 행의 미검증 원문은 이 근거 목록에 넣지 않는다.

## 저장 원문 검색 성능

`prepare_context`의 일반 기업 문맥 생성은 같은 원문 조각을 검색어마다 반복 조회했다. `ExtractionService.search_many`는 원문 해시 검사를 유지하면서 원문별로 필요한 검색어의 결과를 한 번의 조각 순회에서 계산한다. 보고 문맥의 확인 신호 조사와 일곱 항목 검색은 이 일괄 결과를 공유한다. 검색 결과의 일치 건수, 최대 반환 2건, 순서, 원문 위치와 보류 계약은 유지한다.

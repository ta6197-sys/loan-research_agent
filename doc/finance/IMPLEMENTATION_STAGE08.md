# 8단계 — 로컬 금융 화면과 게시본 출력

2026-10-21. 사용자10번에서 로컬 Vue + 한글 PDF + Markdown ZIP과 공개 배포처의 의존성 다운로드를 승인했다. 기존 설계의 조사 목록·보고서·근거 패널, 질문/정정/메모, 이전 판 보존과 자동 게시 방식을 따른다. 새 금융 사실을 확인한 단계가 아니다.

## 구현

- `finance.html`, `static/finance*`: 로컬 Vue 화면. 조사 입력·저장된 조사·진행/사용량·중단/재개·표/차트·수치별 근거·후속 입력·버전 비교를 연결했다. 새 판이 생겨도 사용자가 보고 있는 이전 판을 자동 교체하지 않는다. 생성 본문 직접 편집이나 별도 승인 버튼은 없다.
- `report_view.py`: 게시된 보고서만 투영한다. 게시 해시와 확인 수치의 검증 이력·근거·원문 바이트를 다시 확인한다. 내부 파일 경로/소유자/저장 키는 노출하지 않는다. 미확인·별도/연결·기간·단위·근거 위치/권리 정보를 유지한다.
- `report_exports.py`: 동일 투영의 보고서 ID·판·게시 해시·표시 해시를 PDF/ZIP에 기록한다. PDF는 한글 폰트·반복 표 머리글·쪽 번호·차트·질문·미확인·원문 위치 부록을 포함한다. ZIP은 `report.md`, `evidence.json`, `manifest.json`, 허용 차트 SVG만 포함한다. 원문 전체/사용자 첨부를 묶지 않는다.
- 금액은 Decimal 문자열을 유지하며 브라우저에서도 Number로 변환하지 않는다. 보류 수치는 숫자·0으로 출력하지 않는다. 반기 손익/현금흐름은 동기간 누적, 반기 잔액은 직전 연말과 비교하고 전년 반기 말 잔액은 보조 표로 구분한다.
- 내보내기는 원자적 파일 교체와 파일 잠금을 사용하고 같은 게시본/표시/형식은 같은 ID로 재사용한다. 다운로드 때 내용 해시를 검사한다. 보고서·이전 판·실행 예산을 변경하거나 모델을 호출하지 않는다.

## API와 실행

`GET /reports/{id}/view`, `GET /reports/{id}/compare/{previous_id}`, `GET /reports/{id}/charts/{chart_id}.svg`, `POST /reports/{id}/exports` (`format=pdf|markdown_zip`), `GET /exports/{id}`, `GET /researches/{id}/summary`를 추가했다. `web_demo_server.py`는 `/api/`의 고정 경로만 로컬8100으로 중계한다. 임의 URL 프록시·리다이렉트·환경 프록시는 허용하지 않는다.

먼저 `bash sh/run_research.sh`, 다른 터미널에서 `bash sh/run_frontend.sh`, 브라우저에서 `http://localhost:8600`. 템플릿 수정 후 `node sh/build_finance_ui.cjs`. 검증용 분석 복사본 미리보기는 `.venv/bin/python sh/preview_stage08.py <stage08 분석 폴더>`이며 기존8100/8600 사용 시 실패하고 기존 프로세스를 종료하지 않는다.

## 공급 파일과 보안

Vue3.5.44 npm 공식 패키지의 SHA512를 검사한 후 배포 JS/라이선스만 보관했다. Nanum Gothic Regular/Bold와 OFL은 Google Fonts 고정 커밋에서 받았다. 경로·출처·SHA256은 `static/DEPENDENCIES.json`에 있다. ReportLab5.0.1과 pypdf6.21.1을 의존성/잠금 목록에 추가했다. 공식 공개 배포 파일 다운로드는6 HTTP요청이며 패키지 설치 요청은 별도다. DART 수집 한도를 사용하지 않았고 금융 자료·키를 전송하지 않았다.

실행 화면은 CDN/eval/v-html 없이 동일 출처 CSP를 적용한다. 인증 URL/로컬 경로를 제거하고 근거 발췌를 텍스트로 표시한다. 일반 첨부·원문 HTML을 앱 출처에서 실행하지 않는다. 내보낸 문서에 DRM이나 저장 암호화는 없다. 배포 패키지와 Git에서 실자료·출력 PDF·임시 렌더 파일을 제외한다. 일반 실습용 `/legacy`는 기존 범위로 보존한다.

## 검증과 한계

실자료 분석 결과: `data/research/validation_stage08/20261021T095811Z-b7087ea8/result.json`. 6단계 원본의 별도 분석 복사본을 만들었다. 6판 `994ea6c2dc504d579fb8f13aed36da15` 기준 화면/PDF/ZIP의 판·해시 일치, PDF14쪽·확인 수치114개 보존·보류16개 유지·미확인/한글/미검증 사용자 입력 표시, ZIP 차트2개·원문/첨부 제외를 검사했다. 서로 다른 실제 HTTP 프로세스90077/90089에서 동일 조회/다운로드를 확인했다. 원본167파일 변경/삭제0, 모델/외부 금융 요청0이다.

첫 분석은 과거 메타데이터의 선택 필드 `usage_restrictions` 누락으로 출력 전에 실패했다. 과거 자료를 수정하지 않고 선택 필드 기본값 처리를 보완하고 회귀 시험을 추가했다. 실패 분석을 성공으로 덮어쓰지 않았다.

14쪽 전체를 렌더한 접촉 시트와 수치표·차트·부록·마지막 쪽의 확대 이미지에서 한글/표/쪽 번호 잘림을 확인했다. Chrome에서 수치→근거, 별도/연결, 4판→6판 변경 비교, 새로고침 후 이전 판 유지와 조사 미반영 합성 메모를 확인했다. 실제 회사 답변은 아니다. 최종 브라우저/전체 회귀 결과는 진행 기록을 따른다.

현재는 상신브레이크 보관 사례의 화면/출력 수용 범위다. 일반 신규 기업 수집·공식 IR·일반 첨부/OCR·목적별 심화·실제 금융 전체 확인·9단계 비교 평가는 남았다. 예전 판의 당시 한계 문구는 역사 기록으로 그대로 출력하며 현재 구현 상태로 자동 수정하지 않는다. 공식 버전 대응/연결 범위·차입 구성 미확인은 계속 보류한다. 9단계의 대상·비교 방법·모델 호출 범위는 새 번호로 질문한 뒤 확정한다.

# 범용 정기공시 기업 분석 후속 작업

2026-10-26 기준. 30392 감사보고서 9곳은 공식 재무 API·XBRL의 정기보고서 코드로 동일 접수번호를 대조할 수 없어 기존 검증 게이트에 머문다. 범용 분석은 정기 사업·반기보고서가 있는 기업의 기존 수집·검증 흐름에서 계속 진행한다.

## 이번 수정

`general_collection.report_code`가 `[기재정정]사업보고서`처럼 앞에 정정 표식이 붙은 실제 공시명을 정기보고서로 인식하지 못했다. 이는 정정본을 수집 대상에서 제외하고 결산월 대조에서도 빠뜨릴 수 있었다. 앞쪽 대괄호 표식만 제거한 뒤 원래의 사업·반기·분기보고서 판별을 적용한다. 정정본 접수번호를 최신본으로 선택하며 기존 보관 원문·검증 배치·보고서·코호트는 수정하지 않는다.

`tests/test_general_company.py`에 복수 정정 표식이 붙은 사업·반기보고서 선택과 결산월 대조 회귀를 추가했다. 실제 외부 API 호출 없이 합성 공시목록으로 확인했다.

## 남은 게이트

일반기업 `GeneralCollectionService`는 법인개황·공시목록·재무 API·원문·XBRL을 수집하지만 결과를 `financial_verification=not_performed`로 유지한다. 검증된 재무 분석은 원문/API 수치 일치, 실제 기간과 결산월, 계정·기간의 독립 XBRL 대조를 통과한 행에서만 가능하다. 다음 실기업 확대에서는 정기공시 보유 기업의 신규 실행 계획과 요청 예산을 먼저 고정하고, 보관 원문을 재사용할 수 있는 기업부터 숫자 검증·분석 연결을 시험해야 한다. 감사보고서 전용 후보를 이 경로에 넣지 않는다.

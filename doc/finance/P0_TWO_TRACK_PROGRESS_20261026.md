# 범용 금융분석·30392 코호트 병행 P0 기록

기준일: 2026-10-26. 기존 원문, 검증 배치, 게시 보고서, 코호트 스냅샷은 수정하지 않았다.

## 공시 수집 가능성 게이트

기존 13개 DART 후보의 보관된 `list.json` 응답 9개와 2026-10-26 공시 감사 JSON을 해시로 대조해 [분류 결과](KSIC30392_DISCLOSURE_AVAILABILITY_20261026.json)를 새로 만들었다. 외부 요청은 0회다.

| 분류 | 법인 수 | 다음 작업 |
|---|---:|---|
| 사업·반기·분기보고서 확인 | 0 | 신규 정기공시가 생기면 원문·API·XBRL 검증 계획 수립 |
| 감사보고서 문서 확인 후보 | 9 | 감사보고서 원문에 재무표가 있는지 확인. 기존 정기공시 전용 수집·검증 규칙을 통과한 것으로 취급하지 않음 |
| 조회 기간의 공시 `no_data` | 4 | 새 기준일에 증분 재조회. 음성 응답 원문이 별도 보관되지 않아 과거 감사 기록에 의존 |

감사보고서 접수건은 총 21건이다. 9곳에 공시 문서가 있다는 뜻이며, 검증된 재무제표 또는 21개 기업-기간 관측치를 뜻하지 않는다. 모든 후보의 `financial_statement_status`는 `unverified`, `cohort_eligible`은 `false`다. 13곳의 사업·반기·분기 정기공시가 없는 현재 결과는 기존 감사의 “사업·반기 0곳”보다 분류 범위가 넓다.

사용자가 승인한 추가 원문 확인은 [고정 요청 계획](KSIC30392_AUDIT_REPORT_PLAN_20261026.json)에 최신 감사보고서 1건씩 9개 법인·9개 접수번호·최대 9회로 봉인한 뒤 실행했다. OpenDART `document.xml`을 **9회 요청**했고 안전 검사한 원문 ZIP 9개를 `data/research/cohort_official_30392_20261026/audit_reports_latest/`에 보관했다. [원문 확인 결과](KSIC30392_AUDIT_REPORT_INSPECTION_20261026.json)에서는 9개 모두 재무제표 관련 문자열 표식을 찾았다. 이는 원문 내부에 재무표 검토 후보가 있음을 뜻할 뿐 표의 구조, 해당 기업·기간, 계정·금액, 독립 XBRL 존재를 확인한 것은 아니다. ZIP의 일부 XML은 엄격한 XML 파서에서 태그 불일치가 관찰돼 기존 추출·검증 규칙의 적용 가능성을 별도로 시험해야 한다. 두 번째 실행은 보관 원문·불변 결과를 재대조했고 **신규 요청 0회**였다.

## 공식 식별자 출처

- [한국산업단지공단 공장등록생산정보조회서비스](https://www.data.go.kr/data/15087611/openapi.do)는 회사명·주소·대표자·생산품으로 공장정보를 조회하는 공식 API다. 공공데이터포털의 공개 소개에는 무료, 개발단계 자동승인, 개발계정 1,000건 한도가 표시된다. 현재 공개 소개만으로는 `공장관리번호` 또는 사업자등록번호가 실제 응답에 포함되는지 검증하지 못했다. 키와 실제 응답 또는 공식 응답 명세가 확보될 때만 필드 연결을 구현한다.
- [OpenDART 기업개황](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019002)의 공식 명세에는 `jurir_no`, `bizr_no`, 주소, 결산월이 있다. 기존에 보관한 13개 기업개황 원문에서는 네 항목이 모두 13곳에 존재한다. 식별 번호값은 이 문서에 복사하지 않았다.
- [강화군 제조업체 현황](https://www.data.go.kr/data/15130409/fileData.do)은 업체명·사업자등록번호·공장주소·업종명을 제공하며 사업자등록번호는 공란일 수 있다. 강화군 자료라는 지역 범위를 벗어난 30392 후보에 자동 적용하지 않는다.

공장관리번호는 공장 자체의 식별자이며, 그 값만으로 DART 법인 `corp_code`를 확정할 수 없다. 사업자등록번호 또는 법인등록번호의 직접 일치, 공식 등록 근거, 주소·공장 소재지, KSIC 개정 차수와 법인 주력 업종을 확인해야 `확인` 상태로 넘긴다. 회사명·지역 일치는 계속 `미확인`이다.

사용자가 공공데이터포털 서비스키를 아직 보유하지 않아 공장등록생산정보 API의 실제 응답과 공장관리번호 필드는 조회하지 않았다. 현재 단계에서 신규 법인-공장 `확인` 판정은 0건이다.

## 두 분석 트랙의 현재 상태

- **단일기업:** 게시 보고서의 검증 행만 쓰는 `financial_analytics.py`, 확인 신호, 보고서별 `/financial-analysis` 읽기 API를 재사용했다. 새 `analysis_plan.py`가 확인 신호와 보류·미측정 항목을 회사명과 산업코드에 무관하게 조사 질문·필요 자료로 묶는다. API의 `analysis_plan`과 Vue의 “다음 조사 계획”에서 원문·검증 ID를 따라갈 수 있다. 계획은 기존 보고서·PDF·수치 검증 상태를 변경하지 않는다.
- **산업 비교:** 30392는 상신브레이크 1곳·5기간 그대로다. 별도 303 비교집단은 현재 만들지 않았고 두 집단의 통계를 섞지 않는다. 기존 통계·ML 게이트도 변경하지 않았다.

## 후속 실행 게이트

1. 감사보고서 9곳의 원문 조회 계획은 위와 같이 완료했다. 다음에는 원문 XML의 재무표 구조와 실제 보고기간을 소수 사례에서 먼저 대조한다.
2. 감사보고서 재무표는 기존 정기공시 숫자 검증을 통과한 것으로 승격하지 않는다. 원문/API·기간·결산월·독립 XBRL 대조 가능 여부를 별도로 판정한다.
3. 공장 API는 공식 응답 명세 또는 실제 응답으로 식별 필드를 확인한 뒤 최소 요청으로 시험한다. 키가 없으면 연결 구현은 보류한다.
4. 이후 세부 30392와 광역 303 코호트를 각각 불변 스냅샷으로 구성하고, 표본 적격성을 독립 평가한다.

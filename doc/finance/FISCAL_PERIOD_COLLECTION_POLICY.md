# 일반 기업 결산월 수집 계획·검증 게이트

적용일: 2026-10-25. 기존 `cached_case`와 게시 보고서·검증 배치는 변경하지 않는다.

## 입력과 계획

- 새 일반 기업 조사 접수 시 비교 창은 잠정 상태 `pending_company_identity`로 저장한다. 공시 조회 시작일은 기준일 연도에서 3년 전의 1월 1일로 계산한다. 예: 2026-10-25 → 2023-01-01, 2028-10-23 → 2025-01-01.
- 수집 시 공식 OpenDART [기업개황](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019002)의 `acc_mt`(결산월)를 원문과 함께 저장한다. 같은 회사의 최신 조회 창 안에 있는 사업보고서 제목의 월과 대조한다. 일치하면 `supported`, 비교할 사업보고서가 없으면 계획 입력에 한정된 `identity_only`다. `acc_mt`가 없거나 유효한 `01`~`12`가 아니면 `unverified`, 제목과 불일치하면 `conflict`다. 뒤의 두 경우에는 재무 API 요청을 시작하지 않는다.
- 결산월이 확인되면 기준일 이전에 끝난 최근 연간 3개와 반기 2개를 계산한다. `12`월 결산은 기존 12월·6월 계획과 같다. `03`월 결산은 3월·9월, `06`월 결산은 6월·12월을 사용한다. 보고서 제목의 월이 계획과 다르면 그 접수번호는 사용하지 않는다. 목록에서 누락된 보고기간의 재무 API 조회 계획은 유지하되, 응답 원문과 접수일이 기준일을 넘으면 사용하지 않는다.
- `POST /runs/{run_id}/collect` 결과에 `fiscal_period`와 `target_reports`가 포함된다. 결산월 충돌·누락 시 `next_phase=fiscal_month_review_required`, 비12월 결산 수집 후에는 `next_phase=non_calendar_numeric_mapping_pending`이다. `POST /researches/{research_id}/refresh`도 기업개황과 공시목록을 다시 호출하며, 결산월이 바뀌었으면 검토 상태를 반환한다. 변경 없음 실행이 반복돼도 마지막 전체 수집 실행을 기준으로 새 접수번호를 비교한다.

## 검증 경계

2026-10-25부터 숫자 검증 정책 `numeric-validation-1.30`은 확인된 결산월과 보고서 코드로 연간·반기 당기 기간을 계산한다. 기업코드가 맞는 공식 기업개황, 원문 표지의 시작·종료일, API 조회·응답 연도와 보고서 코드, 표별 당기·전기 금액 열, 실제 금액 및 원문 위치가 모두 일치한 사실만 V04를 통과시킨다. 월이 누락·충돌하거나 표지·열 대응이 맞지 않으면 보류한다. 기존 12월 결산 정책과 원문·검증 배치는 불변이며, 새 정책은 새 배치로 저장한다.

일반 기업 수집 응답의 `non_calendar_numeric_mapping_pending`은 기존 실행 흐름의 다음 단계 이름으로 남아 있다. 수집 자체는 숫자 검증을 자동 실행하지 않는다. 별도 검증 배치에서 숫자가 통과하더라도, 보고서 컨텍스트 생성은 아직 `non_calendar_numeric_mapping_pending`으로 차단된다. 따라서 비12월 결산 숫자를 게시 보고서·재무 분석·코호트 관측치로 승격하지 않는다. 분기 자료와 결산월 변경 이력은 계속 보류한다.

남은 확장은 XBRL 컨텍스트의 독립 기간 대조, 보고서·차트·품질 수용 규칙 및 통계·ML 데이터셋을 같은 기간 정의로 연결하는 작업이다. 결산월 변경 이력이 있는 회사는 과거 기간을 현재 결산월에 강제로 맞추지 않고 별도 검토한다. 연간·반기 외 분기 자료도 이번 계획에 포함하지 않는다.

## 확인

- 합성 3월·6월 결산 계획과 결산월 충돌 차단, V04 수치 보류, 보고서 컨텍스트 게이트를 단위·통합 테스트로 확인했다.
- 실제 OpenDART 읽기 조회에서 세원정공 `acc_mt=06`/사업보고서 월 `06`, 동원모빌리티 `acc_mt=03`/사업보고서 월 `03`을 확인했고, 각각 다른 연간·반기 조회 연도를 계산했다. 이는 계획 계산의 실제 입력 확인이며 두 회사의 금융 수치 검증을 의미하지 않는다.
- 격리된 임시 저장소에서 세원정공의 실제 공개 자료 수집을 실행했다. 연간 2024~2026과 반기 2024~2025를 계획했고, 재무 API 10회 요청을 포함한 외부 요청 22회로 원문 묶음 5개를 확보했다. 공시목록에 2024 연간 접수번호가 없어도 재무 API에서 해당 원문을 찾아 수집했다. 결과의 다음 단계는 `non_calendar_numeric_mapping_pending`이며 수치는 검증 완료 처리하지 않았다.
- 전체 회귀 명령 `.venv/bin/python -m unittest discover -s tests -q`는 로컬 소켓 접근이 가능한 환경에서 399개 통과했다.
- 2026-10-25 후속: 실제 세원정공 6월 결산 원문 5개 묶음과 재무 API 10회(전체 외부 요청 22회)를 격리 저장소에 보존했다. 새 검증 배치 `869f774c6f57433ba5a8b11a0549eea8`에서 숫자 후보 447건 중 382건이 필수 검사에 통과했고 65건은 API 계정 대응 부재·모호성으로 보류됐다. 이는 원문·API 대조 결과이며 공시 자체의 진실성 인증 또는 게시 가능 판정이 아니다. 상세 결과는 [후속 검증 기록](FISCAL_VALIDATION_AND_COHORT_FOLLOWUP_20261025.md)에 있다.

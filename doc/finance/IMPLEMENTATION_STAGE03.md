# 3단계 — DART 원문 위치·표·단위·기간 추출


후속 구현은 [4단계 수치 대조·계산 기록](IMPLEMENTATION_STAGE04.md)을 참조한다. 아래 내용은 3단계 당시 결과다.
설계 기준1.0 · 2026-10-20 (한국시간) · 추출 후보/위치 확인 완료, 금융 검증 전

## 사용자 선택과 구현 범위

1. `lxml`을 프로젝트 `.venv`에 추가한다.
2. 먼저 엄격하게 검사하고 실패하면 오류 위치·복구 경고와 함께 미검증 후보만 남긴다.
3. 저장된 DART XML·HTML/API 응답부터 구현한다. 사용자 첨부 파서의 확정 지원 범위는 변경하지 않고 후속 작업으로 남긴다.

추가한 패키지는 lxml6.1.3이며 실제 libxml2는2.14.6이다. `requirements.txt`와 `requirements.lock.txt`에 기록했다. 원문을 파서의 직렬화 결과로 덮어쓰거나 모델로 보정하지 않는다. 외부 엔티티·DTD/네트워크 참조를 차단하고 기본 파서 안전 제한을 유지한다. 현재 문서 입력은 UTF-8이며 다른 인코딩은 임의로 대체 문자로 바꾸지 않는다.

## 연결 구조

| 구현 | 역할 |
| --- | --- |
| `agent/finance/source_locations.py` | 원본 바이트 시작/끝·행·바이트 열·부분 해시. 반복 숫자도 위치로 구분 |
| `agent/finance/document_extractor.py` | 엄격 검사/복구, DART TE/TU/TD/TH, 절·표·병합 셀·머리글·단위·기간 |
| `agent/finance/extraction_service.py` | API 레코드·표/문단 인덱스·13개 계정 후보의 원자적 저장/재사용·키워드 검색 |
| `mcp_server_finance.py` | 기존 금융 MCP에 로컬 추출·검색·구간 도구 추가 |
| `agent/research_api.py` | 저장 구간과 확인된 원문 바이트 열람 |
| `sh/validate_extraction.py` | 저장된 실자료만 사용한 별도 DB 추출 검증 |

기존 `research_fragments`·`research_facts`·`research_events`를 사용하며 새 테이블/외부 저장소를 도입하지 않았다. 원문 해시·파서 정책/버전·lxml/libxml 버전 지문이 같으면 저장 인덱스를 재사용한다. 바뀐 파서의 인덱스를 새로 만들어도 이전 인덱스와 후보를 지우지 않는다. 현재 검색은 현재 지문의 인덱스 하나만 사용한다.

`Fact`는 계속 `candidate`이며 확정 수치/확인된 사실로 게시하지 않는다. 계정 이름 규칙은 후보 검색에만 쓰고 계정 ID·계층·구성·주석 대조는4단계에서 수행한다.

## 위치와 문맥 계약

구간에 원문 버전/해시·접수번호·절 경로·표 번호·행/열·병합 범위·원시 텍스트·단위/머리글/기간 위치·추출 경고를 연결한다. XML/HTML에서는 바이트 범위와 부분 SHA-256이 원문 복원 기준이다. XPath는 `xpath_basis=parsed_tree`로 표시하며, 손상된 원문의 원래 유효 XPath를 보장한다고 설명하지 않는다.

바이트 범위는0부터 시작하고 끝 위치는 포함하지 않는다. 표/행/열 번호와 원문 행·바이트 열은1부터 시작한다. UTF-8 바이트 열과 화면의 문자 열은 다를 수 있다.

`raw_span_verified`는 원본 바이트 경계/텍스트 연결의 확인 상태다. 금융 수치의 의미가 옳다는 판정이 아니다. 위치·원문 텍스트·범위 표시·단위·기간 머리말이 불명확하면 해당 숫자를 계정 후보로 채택하지 않는다.

표의 ROWSPAN/COLSPAN은 좌표로 확장하되 병합된 값을 여러 원시 셀처럼 복제하지 않는다. 겹치거나 잘못된 병합·5만 셀 초과는 실패로 표시하고 부분만 읽어 전체 처리로 보이지 않게 한다.

기간은 원문 머리말과 열 머리글을 함께 연결한다. 반기 손익의 `3개월`과 `누적`은 다른 열/기간으로 보존한다. 명시한 기간 종료일과 3개월 머리글로 달력 시작일을 계산한 경우 그 도출 이유도 기록한다. 월말이 아니거나 시작일을 정할 수 없으면 추정하지 않는다. 현금흐름은 원문이 밝힌 기간으로 읽으며 손익의 API 필드 규칙을 일괄 적용하지 않는다.

금액은 원문 문자열을 보존하고 쉼표·괄호 음수만 정밀 십진 문자열로 정리한다. 실제0·빈 값·대시를 구분한다. 천원/백만원 단위 환산·반올림·계산은 아직 하지 않는다. 불명확한 단위나 혼합 단위는 기본값을 넣지 않는다.

API는 `/list/0` 같은 JSON Pointer, 원본 해시·접수번호·조회 조건·레코드를 보존한다. 이 단계에서는 API 수치 필드만으로 기간/범위를 추정해 사실을 만들지 않는다.

## 사용

서버 실행은 기존과 같다.

```bash
bash sh/run_research.sh
```

`/health`는3단계와 금융 MCP 연결 상태를 표시한다. 모델과 전체 자동 조사 그래프는 아직 연결 전이다. 새 사용자 제출/조사 시작 UI를 추가하지 않았다.

| 내부 MCP 도구 | 입력 | 반환 |
| --- | --- | --- |
| `extract_source` | 저장된 원문ID | 인덱스ID·표/후보 수·복구/누락 범위 |
| `search_source` | 원문ID·키워드·결과 개수 | 구간ID·원문 위치·짧은 텍스트·단위/머리글/기간·경고 |
| `read_fragment` | 구간ID | 선택 표/문단/셀의 저장 구조와 문맥 |

`GET /fragments/{id}`로 저장 구조를, `GET /fragments/{id}/original`로 확인된 원본 바이트를 읽는다. 후자는 실행하지 않는 다운로드이며 위치를 확인하지 못하면409다. API 레코드의 JSON Pointer는 원문 JSON 전체와 함께 읽으며 재직렬화한 JSON을 원본 바이트 조각이라고 제공하지 않는다.

검색은 인덱스에 포함된 구간에 한정한다. `no_match_in_index`는 원문 전체에 내용이 없다는 뜻이 아니다. 현재 파서의 인덱스가 없으면 `not_indexed`다. 결과 제한으로 제외된 검색 건수와 문서 인덱스의 부분 범위를 함께 표시한다. 원문 전체를 모델에 전달하거나 문서의 지시를 실행하지 않는다.

## 검증

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m pip check
.venv/bin/python sh/validate_extraction.py
```

전체 자동 시험 **58개 통과**, 패키지 충돌 없음. 합성 표의 반복 숫자·유니코드 바이트 위치·괄호/0/결측·병합 머리글·3개월/누적·날짜 추정 보류·복구 경고·DTD·잘못된 병합/한도·저장 실패 원자성·인덱스 버전 혼합·원문 훼손과 기존 저장/통신 회귀를 포함한다.

실자료 시험은2단계의 상신브레이크 원문/본표를 재사용한다. 원래 DB를 읽기 전용으로 백업해 별도 시험 DB에 후보를 저장하고, 원문 파일은2단계의 불변 원문을 참조한다. 원래 DB/사례/원문은 수정하지 않는다.

| 실제 관찰 | 결과 |
| --- | --- |
| 엄격 XML 검사 | 2733행의 엔티티 오류 등 발견. 복구 로그28개와 커버리지 경고1개 보존 |
| 표/문단 | 표1,266개·문단441개 인덱스 |
| 원래/확장 셀 | 17,319개 / 병합 영역 포함20,564개 |
| 원문 매핑 미확인 표 | 5개. `coverage=partial`과 위치 목록 보존 |
| 현재 반기 계정 후보 | 별도13개·연결13개 항목 모두 발견 |
| 수치 후보 | 분기/누적/전기 열 포함64개. 모두 원문 셀 바이트·해시로 복원 |
| API 레코드 | 별도120개·연결150개 원본 위치 연결 |
| 검색 | 매출액35건·현금흐름 주석27 검색1건·차입금134건. 반환 개수 제한과 구분 |
| 재시작 | 새 MCP 프로세스에서 같은 인덱스/구간 재사용, 실제 HTTP 원본 바이트 일치 |
| 외부 데이터 요청/모델 | 각각0회 |

표5개의 미확인은 원문 위치 매핑 검사 결과다. 파서가 전체 문서를 정확히 복구했다거나 나머지 표의 금융 내용을 전부 검증했다는 뜻이 아니다. 정규식으로 `<TABLE`을 세면 `<TABLE-GROUP`도 포함하므로 실제 TABLE 요소 수와 구분한다.

초기 시험에서는 채권 후보를 놓쳐 현재 계정이12개씩이었다. 본표의 `매출채권및기타채권`은 상위 행에서 유동자산을 구분하므로, 상위 행 위치까지 연결하는 후보 규칙을 보완했다. 비유동자산 아래 같은 이름은 현재 채권으로 취급하지 않는다. 이를 순수 매출채권으로 바꾸거나 회전율 계산 입력으로 확정하지 않았다.

첫 검색어 `유동성차입금`의 결과 없음은 원문 부재로 판정하지 않았다. 관련 원문 검색어 `차입금`의 별도 검색 결과를 남겼다. 실패한 초기 결과는 삭제하지 않았다.

최종 기록: `data/research/validation_stage03/20261020T140713Z-ab0a71df/result.json`, 같은 폴더의 `restart_readback.json`·시험 `session.db`. 원문 참조는 결과 파일의 `source_root`에 있다. 이전 시험 결과도 다른 폴더로 보존했다. 이 로컬 검증 자료는 기존 Git/학생 배포 제외 범위 안에 있다.

## 남은 검증과 다음 단계

현재64개는 모두 **미검증 후보**다. API와 원문을 대조해 금융적 정확성을 통과시킨 수치가 아니다. 다음4단계에서 법인·접수/정정·범위·기간·단위·계정 ID/구성을 대조하고, 산술·비교·검증 결과와 사용 보류를 구현한다.

미확인 표5개의 위치/텍스트 문제는 추가 원문 확보나 파서 보완이 필요한 범위로 남긴다. 공식 IR 수집, 첨부 PDF·XLSX·CSV·TXT, 전체 조사/복구·보고서/차트/출력은 아직 구현하지 않았다. 추출기 자체의 CPU 시간 측정과 전체 실행 예산/취소 연결은 전체 실행 관리자에서 통합해야 한다. NCS 원문·도표·서식은 사용하지 않았다.

파서 선택과 설정은 [lxml 공식 파싱 문서](https://lxml.de/parsing.html)의 엄격/복구·외부 참조·오류 로그 계약을 확인했다. 선택한 파서 기능이 금융 검증을 대신하지 않는다.

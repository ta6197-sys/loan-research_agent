# 4단계 구현 완료와 금융 미확인 분리 — 2026-10-21

기존 [인계 문서](SESSION_HANDOFF_STAGE04_20261021.md)의 승인 사항을 유지하고 XBRL 차입 근거 연결·실패 시험·완료 기준 분리를 보완했다. 이전 결과와 원본은 보존한다. 이 기록의 구현 완료는 금융 자료 전체 확인 완료를 뜻하지 않는다.

## 구현한 내용

- `borrowing_details.py`의 결측 항목에도 명칭·용도·금액 셀 위치와 원래 대시/빈칸을 저장한다.
- `xbrl_borrowing.py`를 수치 검증의 상세 수집 이후에 연결했다. 같은 보고서의 회사·범위·시점·통화·차원·계정·구성요소와 각 금액이 정확히 대응해야 채택한다. `nil`, 상충 중복, 다른 시점·회사·통화·추가 차원, 위치 부재, 모호한 문자 금액을 0으로 바꾸지 않는다.
- 원래 상세는 `source_observation`에 보존한다. 본문의 결측을 수정하지 않고, 별도 수치 근거로만 같은 보고서의 명시적 0을 사용할 수 있다. 전체 원문 항목 비교와 양수 잔액 비교도 유지한다.
- 공시 항목별 XBRL 대응이 모든 관측에서 완전하고 각 항목·합계·필요 재분류가 일치한 경우에만 잔액 한정 연결을 허용한다. 같은 구성요소 ID만 있거나 한쪽에만 근거가 있는 경우는 부족하다. 은행 법인·계약·은행별 상환 일정의 동일성 확인으로 확대하지 않는다.
- 수용 검사에 원문/XBRL 재독해를 연결했다. 원본 SHA와 위치·선언·라벨에서 상세를 재구성해 비교하며 저장된 `source_hash_verified` 같은 플래그만으로 통과시키지 않는다. 재독해 저장소가 없으면 신규 근거의 수용을 거부한다.
- XBRL 공시 하나의 파싱 실패를 다른 공시의 확인 결과와 분리한다. 같은 접수번호에 중복 archive가 있으면 임의로 선택하지 않는다. 미확인 공시도 누락 확인 대상에 남는다.
- 미사용 `XBRLConsultingFirm="자체작성"` 선언의 제한적 복사본 처리에 실제 사용·중복·다른 XML 오류·논리 내용 차이 거부 시험을 추가했다.
- 공식 기준자료의 권리 구분·저장 복구를 시험했다. 공식 참조 수집의 새 진단은 인증 이동 URI 대신 선언 URL과 접근 필요 상태만 남긴다. 기존 원문·이전 진단을 덮어쓰지 않는다.

정책 버전은 `numeric-validation-1.27`, `xbrl-mapping-1.6`, `xbrl-borrowing-evidence-1.1`, `stage04-acceptance-1.14`, `composition-review-1.3`이다. 기존 이력은 새 정책으로 덮어쓰지 않는다.

## 완료 판정 계약

`stage04_completion.py`와 `sh/verify_stage04_completion.py`가 개발 검증을 실행·기록한다. 검사 범위는 전체 자동 시험, 새 분석 복사본 통합 대조, 원문 재독해, 오류 주입, 실제 MCP·서로 다른 HTTP 서버 재조회, 기존 자료 보존, 보안 시험 포함 여부와 현재 소스 지문이다. 빠진 검사·실패·오래된 소스 지문은 완료로 처리하지 않는다.

| 상태 | 의미 |
| --- | --- |
| `stage4_implementation_complete` | 위 개발 검증을 수행한 코드의 구현 완료 |
| `ready_for_stage5` | 금융 보류를 유지하면서 5단계 구현에 진입할 수 있음 |
| 기존 `stage4_complete` / `financial_scope_complete` | 실제 검사 범위의 금융 자료 확인. 미확인이 있으면 false 유지 |
| `required_complete` / `additional_complete` | 실제 금융 확인의 필수·추가 범위 상태. 구현 완료로 승격하지 않음 |

최초 완료 기록은 `data/research/validation_stage04_completion/20261021T074847Z-e45b71fa/verification.json`이다. 이 스냅샷에서 전체 시험 225개 통과, 오류 8종 모두 종료 코드 1, 개발 구현 완료 true, 금융 필수/추가/전체 확인 false였다. 이후 5단계 연결 변경까지 포함한 최종 시험 결과는 [진행 기록](IMPLEMENTATION_LOG.md)의 최신 항목을 따른다.

## 데이터 흐름과 검증 경계

코호트 정책 등록 → 명시적 수집 → 기존 숫자·XBRL 검증 및 게시 → 원문 해시·위치/산업/회계기준/필수 V 규칙 재대조 → 기업·기간 스냅샷 생성 → 적격성·통계·ML 계산 → 보고서에 불변 연결 → 조회 API와 Vue 읽기.

GET 요청은 수집·학습을 수행하지 않는다. 스냅샷 생성이 명시적으로 실행될 때만 모델을 적격성 평가 후 실행한다. 스냅샷과 보고서 연결은 추가 전용이고 전체 산출물 해시를 검사한다. 원문 변조 시 연결된 분석 조회도 거부한다.

재무 특성은 게시된 값, V01–V07·V13·V18, 원문 위치, 법인, 기간, 범위, 통화·단위와 연결한다. 증가율은 기존 V11의 전기 입력 근거도 확인한다. 정정 검증 시점과 코호트 기준일이 일치해야 한다. 산업 정보는 저장된 회사 식별 원문에서 확인하고, K-IFRS는 등록된 원문 바이트 구간의 문구와 해시를 확인한다. 근거가 없으면 해당 보고서/계정에 제외 사유를 기록한다.

모델 임계값과 90·95·97.5분위수 민감도는 모두 학습 점수에서 계산한다. 평가 표본 변경만으로 임계값이 바뀌지 않는 회귀 검사를 추가했다. 과거 회계기간의 뒤늦은 정정 공시도 시간 분할 학습 기준일 뒤 공개됐으면 제외한다. 법인 분할은 고정 분석 기준일의 기업 홀드아웃으로 별도 평가한다.

연간 표본 게이트는 12월 결산일 문자열 대신 실제 기간 길이(350–380일)로 판정한다. 연간 행에서 가용률을 다시 계산하므로 중간기간 행으로 150개 기업-연도 요건을 채울 수 없다. 기존 수치 기준을 낮추지 않았다.

## 실제 저장 자료 재실행

외부 호출 없이 기존 저장 원문과 검증 보고서만 읽었다.

| 기업 | 보관 게시본 수 | 최신 게시본의 분석 결과 항목 | 지원 항목의 기간 |
|---|---:|---|---|
| 상신브레이크 | 2 | supported 78 / withheld 32 / unmeasured 2 | 2023FY, 2024FY, 2025FY, 2025H1, 2026H1 |
| SK | 3 | supported 4 / withheld 12 / unmeasured 15 | 2025FY, 2026H1 |

숫자는 원시 계정 건수가 아니라 기간·범위별 분석 결과 항목 수다. 현재 저장 산업 식별 자료의 SK 코드는 `64992`다. 이를 상신브레이크와 동일 제조업으로 간주하지 않았다. 두 기업 모두 보고서에 연결된 적격 코호트 스냅샷은 없다.

- 실제 기업 분석: 기존 검증 보고서의 결정론적 재무 분석 재실행.
- 실제 다기업 통계·ML: 동일 산업·회계기준 원문 근거와 코호트 등록이 없어 미실행. 실제 ML 성능·정확도 미산출.
- 합성 시험: 격리 SQLite에 합성 원문, 2개 이상의 합성 법인, 검증 배치, 게시본을 저장해 데이터셋 생성·불변 조회를 검증. 별도 30기업×5기간 합성 데이터로 모델·민감도·분할을 검증. 실제 기업 검증 성능이 아니다.
- 실제 신규 외부 수집: 이번 교정 작업에서는 미실행. 업종·대상 기업 범위 확정 후 별도 명시적 수집 명령으로 실행한다.


최종 실행 결과: 전체 391건 중 390건 통과. 나머지 1건은 격리 환경의 `127.0.0.1` 포트 바인딩 제한이며, 동일 프로세스 재시작 테스트를 권한 환경에서 별도 재실행해 통과했다. 실패한 코드 테스트는 없고 환경 제약 1건을 분리 확인했다. Vue 컴파일·JS 구문·실행 렌더 검증도 통과했다.

기존 금융 검증·보안·PDF·ZIP 테스트를 유지한다. 브라우저 화면 배치의 시각 검사는 별도이며, 이번 프런트 검증은 템플릿 컴파일·구문·실제 Vue runtime의 렌더·근거 연결이다.

## 남은 실무 적용 제약

1. 실제 동일 세부 업종 코호트와 산업 분류 체계·버전 및 회계기준 근거가 필요하다. SK와 상신브레이크를 임의로 합치지 않는다.
2. 일반 공시 수집기의 조회 시작일 2023-01-01, 연간/반기 위주의 비교 창, 일부 표 추출 및 재무 분석의 12월/6월 증감 쌍 가정은 후속 일반화 대상이다. 데이터셋 기간 정의만으로 기존 수집·계산 엔진의 지원 범위를 확장했다고 주장하지 않는다.
3. 차입/자산은 검증된 전체 차입 구성이 부족한 경우 결측이다. 임의 합계로 특성을 채우지 않는다.
4. 통계 최소 10개 기업·20개 관측, ML 최소 150개 연간 행·30개 기업·3개 기간·5개 특성·85% 가용성은 운영상 실험 기준이다. 신뢰성·규제 준수를 보증하지 않는다.
5. 원문에 회계기준 문구가 있어도 세부 회계 정책 동질성 전체를 증명하는 것은 아니다. 업종·계정 정의와 표본 적합성을 별도로 검토해야 한다.
6. 자료가 미비한 실제 기업에 대한 결과를 합성 점수나 위험등급으로 대체하지 않는다.

### 실제 30392 데이터 연결 결과

2026-10-23을 공개 기준일로 상신브레이크·KB오토시스·새론오토모티브의 공식 OpenDART 기업개황, 2023~2025 연간·반기 공시 원문과 재무 API를 각 22회 요청 예산 안에서 수집했다. 세 회사를 자동으로 같은 세부 업종으로 합치지 않았다. 최신 XBRL 자체 업종코드는 상신브레이크 `30392`, KB오토시스 `303`, 새론오토모티브 `30399`였다. 새론오토모티브의 사업 본문 `30392`와 최신 XBRL `30399`는 충돌한다. XBRL `StandardIndustryCode`의 정확한 원문 바이트와 기준일 이전 최신 버전을 확인하는 조건을 추가했다.

상신브레이크의 기존 검증·게시 경로로 신규 보고서를 생성했다. 게시본의 130개 재무 행 중 114개가 검증됐고, 결정론적 분석 결과는 supported 78 / withheld 32 / unmeasured 2였다. 처음 생성한 스냅샷에서 기간의 `column_kind` 메타데이터를 필수 날짜 항목으로 잘못 비교해 기간 행을 누락했다. 검증된 기간의 유형·시작일·종료일만 비교하도록 고쳤다. 최초 게시본과 스냅샷은 불변 기록으로 보존하고, 후속 보고서 판에 새 스냅샷을 연결했다.

최종 코호트 ID는 `514e8bf3fbc944495ba8f13245e3f6fcda1a9e50328359ac56a8840875a3c714`, 연결된 보고서 ID는 `0a59d33878104ea0b523f2d9062dc0d6`, 산출물 해시는 `cef16fc0d0b080f31981d06683ae6d0b9c1e39dde1026e7e1c04489af79304f7`다. 2023·2024·2025 연간 및 2025·2026 반기 관측치 5개가 생성됐고 검증 제외 0건이다. 기간별 유효 특성은 각각 6, 6, 6, 6, 7개다. 로컬 HTTP GET에서도 같은 해시와 `insufficient_peer_data`, `not_trained_insufficient_data`를 확인했다. 실제 ML 모델은 학습되지 않았고 점수도 생성되지 않았다.

이 코호트는 현재 1개 기업뿐이므로 기업 간 분위수와 ML 적격성 게이트를 충족하지 않는다. 추가 기업은 법인별 최신 XBRL `30392`, 동일 회계기준, 검증된 재무 원문과 게시본이 확보될 때만 추가할 수 있다.

코드 수정 후 전체 회귀 시험은 `.venv/bin/python -m unittest discover -s tests -q`로 393건 통과했다. 기간 보조 메타데이터와 최신 XBRL 산업 분류 충돌을 합성 원문 통합 시험에 추가했다. 로컬 HTTP GET은 200과 연결된 산출물 해시를 반환했다.

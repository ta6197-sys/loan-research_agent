# 기업 대출 검토 사전조사 에이전트 — 합의된 기획

기록일: 2026-10-20 (한국시간)

지금까지의 합의·미정 사항·코드 재사용 계획을 통합한 [프로젝트 기획안](../../PROJECT_PLAN.md)을 프로젝트 최상위에 작성했다.

이 문서는 사용자가 제공한 기획을 이후 작업의 기준으로 보존한다. 금융 기능 구현은 시작하지 않았다. 새 조사 제안과 검증 결과는 [RESEARCH_CANDIDATES.md](RESEARCH_CANDIDATES.md)에 기록한다.

## 목적과 사용자

흩어진 공시와 IR 자료를 조사 목적에 맞게 연결하고, 확인된 사실·해석·미확인 사항·추가 질문을 구분해 담당자의 기업 대출 사전조사를 돕는 에이전트다.

첫 지원 대상은 필요한 공시·공식 자료를 확보할 수 있는 국내 상장 제조기업이다. 국내 기업 일반은 장기 방향이다. 결과는 담당자의 사전 검토 자료 초안이며, 조사 범위와 자료 확보 결과에 맞춰 개발 범위를 정한다.

개인 과제에서 시작하여 포트폴리오로 발전시킨다. 제공된 실습 코드의 재사용을 우선 검토한다. 모델은 Ollama로 시작하고 필요하면 OpenAI API를 사용한다.

2026-10-20 추가 합의:

- 첫 사용자 상황은 **IBK 기업금융 담당자의 운전자금 신규 대출 사전조사**다.
- IBK는 서비스를 사용하는 은행이며, 조사 대상은 대출 신청 기업이다.
- 대표 기업은 상장 중소·중견 제조기업 후보를 비교한 뒤 **상신브레이크로 선택**했다.
- 조사 범위는 **2026-10-20 기준 공개 자료, 2023~2025 연간 및 2026/2025 반기 동기간 비교, 별도재무 중심·연결재무 보조**로 합의했다.
- 공개 자료를 활용한 가상 검토 사례다. 선정 기업이 실제로 IBK에 신규 대출을 신청했다고 가정해 사실로 기록하지 않는다.
- 검토 초안의 시각자료 구성은 **핵심 추이 차트 + 주요 쟁점·근거 표**로 확정했다. 기본 주제는 영업이익·영업현금흐름과 현금·차입금이며 쟁점별 추가한다. 화면·PDF·Markdown 출력을 확정했다.
- 첫 버전은 **사전조사·근거 정리·추가 질문을 우선**한다. 소요 운전자금 추정과 지원 한도 자동 산정은 첫 버전 범위에서 보류한다.
- **일곱 항목을 매번 기본 확인하고 쟁점에 따라 심화**한다. 보고서는 **핵심 요약·미해결 질문을 먼저, 기업·재무·차트·쟁점·근거를 뒤에** 둔다. 세부 최소 확인표와 본문 13개 계정도 [항목·양식](REPORT_DESIGN_REVIEW.md)으로 확정했다.
- NCS 학습모듈의 지적재산권 고지를 반드시 준수한다. 제3자 요소와 권리관계가 불분명한 도표·캡처·사례·서식 등은 동의 확인 전 결과물에 재사용하지 않는다. [교재 검토 및 자료 이용 원칙](NCS_REVIEW.md)을 이후 작업에도 적용한다.

OpenDART 인증키 입력 자리는 프로젝트 최상위 `.env`의 `OPENDART_API_KEY`다. 사용자 입력 후 공식 공시검색 요청 1건에서 HTTP 200·상태 `000`을 확인했다. [키 설정·연결 확인과 시각자료 논의 상태](DART_SETUP.md)에 기록한다. 상신브레이크의 선택 수치와 주요 원문을 수작업으로 대조했다. 금융 조사 기능은 미구현이며 자동 실행 정확성을 검증한 것은 아니다.

## 확정된 문제와 가치

- 흩어진 사업보고서·분기보고서·주석·공식 IR 자료를 모아 검토한다.
- 발견한 숫자와 쟁점에 따라 다음에 확인할 자료를 선택한다.
- 설명의 원문 근거와 수치·비교 기준을 추적할 수 있게 한다.
- 무엇이 확인됐고 무엇을 더 확인해야 하는지 구분한다.

목표 가치는 **조사 시간 단축·자료 누락 감소·근거 추적성·추가 질문의 구체화**다. 항목별 자료 연결, 영업현금흐름·재고·채권·차입 변화의 추가 확인, 필요한 내부 자료와 이유가 연결된 질문, 수치·원문 위치를 추적할 수 있는 초안에 집중한다. 대출 판단의 자동화나 이미 검증된 성과로 소개하지 않는다.

현재 문제 정의는 공개 직무 자료와 사례에 근거한 가설이다. 현직자 인터뷰와 실제 사용성 검증은 확보하지 못했다.

## 조사와 사용자 개입 원칙

| 상황 | 합의된 동작 |
| --- | --- |
| 조사 시작 | 계획을 표시하고 자동 시작하며 사용자는 수정·중단 가능 |
| 기본 확인 | 함께 합의한 필수 항목을 반드시 확인 |
| 추가 조사 | 발견한 쟁점에 따라 자료와 조회 순서를 선택 |
| 자료 대조 | 기간·단위·연결/별도·출처·정정 여부 확인 |
| 설명 수정 | 원인 후보와 근거를 비교하여 설명 갱신 |
| 초안 작성 | 미확인 사항을 표시하여 바로 제공. 작성 전 승인 불필요 |
| 후속 자료 | 사용자 답변·첨부 자료를 받으면 관련 쟁점 재조사 및 초안 갱신 |
| 내부 정보 필요 | 필요한 정보와 요청 이유를 구체적으로 질문 |
| 충돌 미해결 | 스스로 추가 조회한 뒤에도 해결되지 않으면 사용자에게 질문 |
| 조사 범위 확대 | 다른 기업이나 별도 주제로 확대하기 전에 사용자와 논의 |
| 답변 대기 | 독립적으로 진행할 수 있는 조사는 계속하고 확인 범위로 초안 제공 |

개발 과정에서는 선택이나 논의할 사항이 있으면 사용자에게 질문한다. 서비스 안에서 에이전트가 자동 조사하는 원칙과 개발 중 사용자가 범위를 결정하는 원칙은 각각 적용한다.

## 자료와 결과의 구분

초기 자동 수집 범위는 DART 공시와 해당 기업의 공식 IR 자료다. 뉴스·외부 산업 자료는 현재 필수 수집 범위가 아니다. 사용자 설명과 파일은 별도 출처로 표시하며, 공식 공시 수치를 임의로 덮어쓰지 않는다.

| 결과 구분 | 의미 |
| --- | --- |
| 확인된 사실 | 원문 또는 검증한 계산으로 확인되는 내용 |
| 근거가 있는 해석 | 사실에 근거한 설명. 확정된 원인과 구별 |
| 미확인 사항 | 확보한 자료로 판단할 수 없는 내용 |
| 추가 확인 질문 | 필요한 정보와 이를 확인해야 하는 이유 |

우선순위는 근거 없는 주장·수치 오류 방지 → 중요한 항목 누락 감소 → 시간 단축이다. 공개 자료로 확인할 수 있는 내용을 조사하지 않고 미확인으로만 처리해서는 안 된다.

## 코드 재사용에 관한 현재 인식

기존 코드의 주요 파일을 확인한 결과 FastAPI·웹 채팅·진행 상황 스트리밍·모델 호출·MCP·조사/재계획/작성 흐름·SQLite·재시도 처리 기반을 재사용할 수 있다. 파일별 활용과 보완 사항은 통합 기획안에 기록했다.

장애 진단 내용, 형식 중심 검증, 재작성 횟수를 채우면 강제로 통과시키는 동작은 금융 조사 기준에 맞게 교체해야 한다. 실행 스크립트의 대화 DB 삭제와 프로세스 강제 종료 동작도 확인했다. 이 기록은 코드의 주요 구성 확인이며, 금융 기능 실행이나 전체 서버 검증을 의미하지 않는다.

## 상세 설계 합의와 남은 사항

현재 사용자의 지시는 **설계까지만 진행**하는 것이다. [상세 설계](../../README.md)에 기존 코드의 확장 지점과 기능·흐름·근거·저장·API·화면·검증·인계 명세를 작성한다.

- 개인 PC·사용자 1명, 조사 한 개 실행·나머지 대기, 화면 단절 시 조사 계속·재접속 복원.
- 서버 시작 시 비정상 중단 조사 자동 재개. 명시 중단·삭제·한도 종료는 유지하고 예산을 초기화하지 않는다.
- 사용자 삭제 전까지 로컬 보관. 기본 로컬 처리, 외부 모델·추적 전송은 사용자 설정 시에만.
- 텍스트 PDF·XLSX·CSV·TXT, 초기 10개/20MB씩/총100MB, PDF 200쪽·표 5만 셀. 조정 가능.
- 조회60·심화10·모델20·전체 실행 최대30분, 마지막5분 작성/검증. 새 추가 조사에는 새 한도와 누적 사용량, 장애 복구에는 기존 잔여 한도.
- 최근3개년+최신 분·반기. 손익/CFO 동기간, 중간 잔액 직전 연말 기본·전년 동기 말 보조. 별도 중심·연결 보조는 서비스 정책.
- 구조·표·키워드 검색부터. 보고서·근거 중심 화면, 생성 본문 읽기 전용·답변/정정 요청/메모.
- 일반 메모는 저장만, ‘조사에 반영’ 선택 시 재조사. Markdown·차트·근거 목록은 ZIP 제공.
- 회사 변경은 새 조사, 목적·공개 기준일 변경은 새 기준 버전으로 보존.
- 추가 조사는 충돌·기본 누락 우선, 이후 대출 목적 관련 설명 공백 심화.
- 첫 평가는 상신브레이크와 직접 만든 오류 상황부터 검증하고 고정 절차와 비교한 뒤 다른 기업으로 확대.
- XLSX는 저장된 계산 결과를 읽고 숨김 시트·행·열도 표시해 포함. 재계산하지 않으며 결과 부재·최신성 한계를 표시.

모델명은 구현 시 실제 PC 검증 후 선택하도록 확정했다. 외부60초·모델180초, 재시도 대기2초/5초·일시 오류 최초 포함3회, 초안 수정 최대2회·연속 복구 실패2회 중지·작성용4회 확보를 적용한다. 평가는 같은 자료·모델·예산으로 각각3회, 정확성·공개 확인 누락 우선 검사다. 최신 회신에 따라 중단은 대기 후속 작업까지 적용, 계획 수정은 현재 조사 완료 후 수정 계획으로 추가 조사, 미완성 결과 제공, 에이전트 원문 대조로 정했다. 첨부 포함 메시지 전송으로 자동 조사하며 별도 제출/시작 단계는 없다. 기업별 독립 조사·한 번에1개 실행/나머지 대기와 기존 조정 가능한 첨부 한도를 유지한다. [최종 결정](design/FINAL_REVIEW.md)에 반영한 설계 기준1.0을 이후 구현 기준으로 사용한다. 신청 금액·기간 등은 실제 조사에서 미제공 정보로 질문하며 추정해 채우지 않는다.

## 진행 순서와 단계별 산출물

| 순서 | 작업 | 완료 시 남길 산출물 |
| --- | --- | --- |
| 1 | 공개 업무 자료로 필수 조사 항목 후보 작성·논의 | 항목별 필요 이유·자료 위치·확정 여부 |
| 2 | 대표 기업 자료 확보 가능성 확인 | 원문 목록·수치·주석 위치·부족 자료 |
| 3 | 사례 하나를 수작업으로 끝까지 조사 | 검토 초안·근거 목록·계산 내역·미확인 질문 |
| 4 | 흐름·양식·구조 논의 | 합의된 구현 범위·처리 규칙 |

| 6 | 추가 조사·자료 요청·재개 구현 | 사례 및 추가 자료에 따른 조사·초안 변화 |
| 7 | 고정 절차와 비교 평가 | 정확성·누락·개입 횟수·시간 및 한계 |
| 8 | 기획·구현·평가 문서화 | 과제 제출 및 포트폴리오 자료 |

현재 위치: 서비스 동작의 설계 기준1.0과 구현 인계를 정리했다. 상신브레이크의 공식 API·원문을 대조하고 [첫 초안·네 차트](cases/sangsin_brake/CASE_REPORT.md), [조사 과정](cases/sangsin_brake/RESEARCH_LOG.md)을 작성했다. 최소 확인표·13개 계정·공통 비교·출력·운영 정책의 최신 답변을 설계에 반영했다. 구현 단계는 아직 시작하지 않는다.

# 2단계 — 금융 MCP와 OpenDART 연결

설계 기준 1.0 · 2026-10-20 (한국시간) · 실제 연결 확인 완료, 금융 원문 대조 전

이 문서는 2단계 당시의 기록이다. 이후 [3단계 원문 추출](IMPLEMENTATION_STAGE03.md)에서 로컬 추출·검색·구간 조회 도구를 추가했고 현재 서버 상태는3단계를 표시한다.

## 선택과 범위

사용자 답변으로 공식 기업 목록 로컬 재사용/첫 검색 갱신, 기존 조사 서버에 금융 MCP 연결, 상신브레이크 대표 자료 실제 검증을 확정했다. 기본 서버에 금융 MCP를 연결하되 모델과 학습용 장애 도구는 시작하지 않는다. DART 요청은 도구 호출 시에만 수행한다. 금융 MCP가 연결되지 않아도 기존 저장 자료를 읽을 수 있다.

이번 단계는 인계서 2단계의 법인·접수·본표·원문 조회 및 오류 구분이다. 공식 IR은 기업개황에서 홈페이지 후보만 확보하며 페이지 자동 수집은 아직 연결하지 않았다. 일곱 항목 자동 조사·원문 위치 정규화·금융 수치 검증·보고서 게시·차트는 이 단계의 완료 결과가 아니다.

## 구현 위치

| 파일 | 책임 |
| --- | --- |
| `mcp_server_finance.py` | 금융 전용 stdio MCP와 다섯 도구 |
| `agent/finance/dart_protocol.py` | 고정 공식 API 주소·입력·응답·오류·ZIP 검사, 인증 정보 비노출 |
| `agent/finance/dart_service.py` | 기업 목록 캐시, 조사 기준/사용량 검사, 재시도, 원본 저장 |
| `agent/finance/runtime.py` | 금융 프로세스의 환경/저장 경로 조립 |
| `agent/mcp_client.py` | 기존 연결 재사용, 금융만 별도 호출, 서버별 환경 전달 |
| `server.py`, `agent/research_api.py` | 시작/종료 연결, 상태·회사 검색 API, 실패 시 저장 열람 |
| `sh/validate_dart.py` | 명시 실행 시에만 실제 대표 자료 조회·별도 시험 저장 |

기존 저장 스키마를 재사용한다. 원문과 응답은 `SourceInput`/`save_source`, 사용량 예약과 결과는 `save_snapshot`, 이력은 기존 이벤트로 남긴다. 새 DB 테이블이나 체크포인터 패키지는 추가하지 않았다.

## 실행과 도구

```bash
bash sh/run_research.sh
```

`GET /health`에서 `implementation_stage=2`, `finance_mcp=connected`를 확인한다. 도구 연결 실패 시 `finance_mcp=unavailable`이며 `/researches` 등 저장 API는 유지한다. `execution_available=false`는 전체 자동 조사 그래프가 연결되지 않았다는 뜻이다.

`GET /companies?query=상신브레이크`로 후보를 조회한다. 첫 호출은 공식 전체 목록을 갱신하므로 후속 검색보다 느릴 수 있다. 반환에는 목록 갱신 시각·이전 목록 사용 여부·갱신 실패 분류를 포함한다. 현재 목록은 과거 공개 기준일 당시의 법인명까지 재현하는 자료가 아니다. 제조업 지원 여부는 아직 판정하지 않는다.

| MCP 도구 | 입력 | 결과 |
| --- | --- | --- |
| `search_companies` | 회사명/고유번호/종목코드 검색 문자열 | 공식 목록의 후보와 캐시 상태 |
| `dart_company` | 실행ID·선택 고유번호 | 기업개황 원본 참조, 법인/종목 정보·홈페이지 후보 |
| `dart_disclosures` | 실행ID·고유번호·접수일 범위·페이지 | 정정 포함 접수 이력과 원본 참조·전체 페이지 여부 |
| `dart_financials` | 실행ID·고유번호·연도·보고 코드·OFS/CFS | 원본 응답 참조·접수번호·행 수·요청 범위·미검증 표시 |
| `dart_document` | 실행ID·이미 확보한 접수번호 | ZIP과 개별 원문 참조·파일 해시/크기/형식 |

실제 수집 도구는 아직 사용자 메시지/조사 그래프에 자동 연결하지 않았다. 내부의 `app.state.finance_mcp.call_finance(...)`에서 사용하며, 임의 URL·도구 실행 요청을 받는 HTTP API는 제공하지 않는다. 조사 생성에 선택 고유번호가 없으면 재무 도구는 법인 선택 필요 상태를 반환한다. 다른 법인 고유번호나 조사에서 확인하지 않은 접수번호로 원문을 받지 않는다.

공시 목록은 한 페이지씩 읽는다. 다음 페이지가 있는데 전체 수집했다고 표시하지 않는다. 기본 `last_report=N`으로 정정 이력을 보존한다. 재무 API가 공개 기준일 뒤 접수본을 반환하면 원본을 보존하되 `outside_public_cutoff`, `usable=false`로 보류한다. API 접수번호의 제출일 확인만으로 정정 관계·원문 기간 대조를 모두 끝냈다고 표현하지 않는다.

## 요청·오류·보호

- 각 실제 요청 전에 SQLite 스냅샷으로 외부 조회 사용량과 `reserved_outcome_unknown` 상태를 저장한다. 결과가 불명확해도 예약한 횟수를 되돌리지 않는다. 실패/페이지/재시도도 조회 한도에 포함한다.
- 조사 생성 전 회사 검색의 공용 목록 갱신은 조사 실행 예산과 분리해 `_catalogue/requests.jsonl`에 기록한다. 조사 사용량에 몰래 포함시키거나 전체 요청에서 누락했다고 설명하지 않는다.
- 실제 요청은 최대60초, 일시 오류 최초 포함3회와 2초/5초 대기를 적용한다. 실행 잔여 시간과 마지막5분 작성 여유를 검사한다. 전체 실행 관리자의 실제 시계·중단·복구·실행권은 7단계에서 연결해야 한다.
- 인증/접근, 자료 없음, 파일 없음, 제공처 제한, 잘못된 입력, 일시 통신/제공처 장애, 파싱/압축 오류를 구분한다. 인증·정상 부재·제공처 제한은 같은 요청을 반복하지 않는다. 제공처 대기시간을 잔여 시간 안에 지킬 수 없으면 보류한다.
- 공식 OpenDART 주소만 사용하고 리다이렉트·환경 프록시를 사용하지 않는다. 키와 인증 URL·제공처 오류 전문을 결과/이벤트/문서에 넣지 않는다. HTTP 요청 로그에서도 인증 매개변수와 키를 가린다. 키는 금융 자식 프로세스에만 전달하며 학습 도구에는 전달하지 않는다.
- ZIP은 디스크에 임의 경로로 풀지 않고 경로·중복·심볼릭 링크·암호화·크기·CRC를 검사한다. 기업 목록 XML의 DTD/엔티티를 허용하지 않는다. 손상 원문을 조용히 복구해서 검증 완료로 취급하지 않는다.
- 전송100MiB·압축 해제 합계256MiB·멤버100개의 조정 가능한 안전 한도를 둔다. `DART_MAX_RESPONSE_BYTES`, `DART_MAX_EXPANDED_BYTES`, `DART_MAX_ARCHIVE_MEMBERS`로 변경할 수 있고, 초과 자료를 부분만 읽고 완료 처리하지 않는다. 이는 사용자 첨부의 별도10개/20MB/100MB 정책을 변경한 것이 아니다.

외부 모델/추적은 호출하지 않는다. NCS 원문·사례·도표·서식은 읽거나 복사/적재/전송하지 않았다.

## 검증 결과

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m pip check
```

전체 **38개 시험 통과**, 패키지 충돌 없음. 기존 대화/기준/근거/보고서 보존·실제 서버 재시작, 합성 오류/키/ZIP/캐시/예산, 실제 stdio 등록, 금융 MCP 실제 종료 시 저장 API 유지가 포함된다. 합성 시험은 실제 금융 수치 정확성 평가와 구분한다.

실제 검증은 `.venv/bin/python sh/validate_dart.py`로 시작했다. 이 명령은 실제 요청을 하므로 자동 시험에 포함하지 않는다. 기존 사례를 덮어쓰지 않고 독립된 검증 DB/원문 경로를 만든다. 서비스 기본 저장 DB는 계속 최상위 `session.db`다.

| 실제 확인 | 결과 |
| --- | --- |
| 회사 검색 | 공식 목록119,673개 파싱·상신브레이크 고유번호 일치·같은 목록 재사용 |
| 기업개황 | 고유번호00129642·종목코드041650 응답 일치 |
| 공시 이력 | 2026-08-01~2026-10-20 응답 확보, 이번 검색 범위는 한 페이지로 완료 |
| 2026 반기 별도 본표 | 접수20260813000874·120행 원본 확보 |
| 2026 반기 연결 본표 | 같은 접수·150행 원본 확보 |
| 공시 원문 | ZIP과 XML3,676,006바이트 저장·해시 확인 |

최초 회사 검색에서는 종목코드를 숫자 전용으로 제한해 목록 파싱이 실패했다. 실제 공식 목록에서 영문 포함 6자리 코드64개를 확인해 `[0-9A-Z]{6}`로 수정했다. 해당 사례를 합성 회귀 시험에 추가했고 실제 서버 `/companies`에서도 재확인했다. 실패한 첫 결과는 지우지 않고 후속 결과를 별도 파일에 남겼다.

이번 실제 외부 요청은 조사5회 + 목록 최초/재검증2회 + 진단용 목록1회 = **총8회**였다. 성공한 본표/원문 요청을 다시 보내지 않고 회사 검색만 재검증했다.

로컬 기록:

- `data/research/validation_stage02/20261020T133931Z-8a3314f6/result.json`: 첫 실행과 회사 검색 실패.
- 같은 폴더의 `result_after_catalogue_fix.json`: 검색 수정 후 대표 도구 모두 성공·총 요청 수.
- 같은 폴더의 `session.db`, `sources/`: 시험 조사·요청 예약/결과·원본 응답·ZIP·XML·목록 캐시.
- `data/research/validation_stage02/catalogue_debug/catalogue.zip`: 파싱 원인 확인용 공식 목록.

검증 자료는 기존 `data/research/` 제외 규칙에 따라 GitHub/학생 배포에 자동 포함되지 않는다. 기존 `.env`·사례 파일은 보존한다.

## 확인 수준과 다음 작업

이번 성공은 **실제 API→금융 MCP→원본 저장 연결의 성공**이다. 13개 계정의 원문 행/열, 반기 3개월/누적, 단위·범위·주석의 의미와 금융 주장 정확성을 자동 검증한 결과가 아니다. 본표 응답은 수치 후보/원본으로 보관하고 기존 사실/보고서 상태 제한을 유지한다.

다음 3단계에서 원문 절·표·머리글·단위·기간·행/열의 정확한 위치를 추출하고 실패/복구 경고를 남긴다. 4단계에서 선택 계정 원문 대조·계산·비교를 검증한다. 공식 IR 수집과 전체 자동 조사·복구·보고서 화면/출력은 각 후속 단계에서 연결한다. 실행 중 장애의 시간 보정·응답 중복 제거·대기열·취소·실행권은 아직 전체 구현한 것으로 표시하지 않는다.

## 확인한 공식 계약

- [고유번호 목록](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019018): ZIP/XML과 법인·종목 식별 필드.
- [기업개황](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019002): 법인/종목 정보·홈페이지 필드.
- [공시검색](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001): 기간·정정 포함·페이지·접수 정보와 오류 코드.
- [전체 재무제표](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020): OFS/CFS·보고 코드·원시 금액 필드.
- [공시 원본](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019003): 접수번호로 ZIP 반환.

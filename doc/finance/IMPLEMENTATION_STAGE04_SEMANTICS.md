## 실제 발견한 원인

- 2026년 반기 연결대상 종속회사 상세표에서 주소 `TK&Dist`의 `&Dist`가 XML 복구 후 누락됐다. 같은 종류의 문제가 다른 보고서의 상세표에도 있다. 원문 바이트는 그대로 보존돼 있다.
- 일부 임원 표의 `R&D본부장`도 복구 과정에서 일부 글자가 빠진다. 보수 표에는 XML 태그가 아닌 꺾쇠 문구를 파서가 태그로 해석한 사례가 있다.
- 2025년 사업보고서 차입 주석에는 `당기`·`전기`와 `차입금명칭 합계` 열이 있다. 기존 검사기는 `당기말`·`전기말` 등의 제한된 표현만 지원한다. `당기`를 무조건 기말 잔액으로 치환해서는 안 되며 표의 의미와 근거를 추가 연결해야 한다.
- 과거 수기 형식의 주석에는 XBRL NT_C/NT_S 표시가 없고 `5. 재무제표 주석` 절의 별도 범위 위치도 기존 코드에서 미확인이다. 계정 값이 같다는 이유만으로 범위를 추정해 통과시키지 않았다.

진단 JSON에는 각 표의 원문 ID·접수번호·SHA·바이트/행 위치·절 경로, 내용 차이 예시, 차입 주석 후보의 머리말·단위·표 머리글·행 이름, 계정별 기존 검사 상태를 저장했다. 후보 목록은 발견용이며 검증된 금융 근거가 아니다.

## 질문한 처리 기준 — 답변 대기

1. 확정된 조사·비교에 필요한 항목과 추가로 추출된 조사 범위 밖의 보조 열을 완료 판정에서 구분할지.
2. 연결 범위가 바뀌고 조정 근거가 없을 때, 변경 근거를 기록하고 해당 비교를 차단하는 기능의 검증은 완료로 보되 증감 값은 미검증으로 남길지.
3. 원문을 수정하지 않고 파싱용 복사본의 명백한 XML 특수문자 오류만 보완한 뒤 엄격 검사와 원문 내용/위치 대조를 할지.

답변 전에는 위 기준을 적용하거나 완료 조건을 완화하지 않는다. 기존 수치 규칙·검증 이력·4단계 미완료 상태는 그대로다. 새 외부 조회는 이번에 실행하지 않았으며 필요해지면 요청 범위를 설명하고 먼저 질문한다.

## 후속 선택 확정·구현 결과 — 같은 날

사용자는 필수 항목과 추가 항목의 완료 표시를 분리하도록 지정했다. 연결 범위 변경을 확인하면 해당 확인·차단 검사는 완료로 보되 동일 범위 조정 근거 없는 증감 값은 보류하도록 승인했다. 주소의 글자 누락 사례와 사용 상황을 다시 설명한 뒤, 원문을 보존하고 파싱용 복사본만 제한적으로 보완·대조하는 방식도 승인받았다. 앞의 세 질문에 대한 답변 대기는 해소됐다.

### 필수·추가 완료 표시

`validation_acceptance.py`에서 `completion.required`, `completion.additional`, `required_complete`, `additional_complete`를 별도로 반환한다. 현재는 검증 결과 JSON에 표시하며 Vue 조사 화면 구현을 의미하지 않는다.

- 필수 범위는 확정된 2023~2025년 연간, 2025·2026년 반기와 별도·연결이다.
- 필수 참조가 가리키는 근거는 문맥 오류가 있더라도 추가 항목으로 빼지 않는다. 문맥을 분류할 수 없는 결과와 전역 검사는 보수적으로 필수에 둔다.
- 추가 항목이 미완료인 상태에서도 필수 항목만 따로 완료로 표시할 수 있다. 추가 항목이 없으면 ‘없음’이며 완료로 꾸미지 않는다.
- 추가 실패도 실패 목록에 남고 전체 회귀 명령의 종료 코드1은 유지한다. 기존 전체 완료·금융 미검증 상태를 임의로 통과시키지 않는다.

### 원문 읽기 보완

`literal_xml.py`는 원문의 텍스트 영역에 있는 명백한 단독 `&`와 태그가 아닌 `<`를 파싱용 복사본에서만 이스케이프한다. 기존 엔티티, 정의되지 않은 엔티티, 태그·속성·주석·CDATA는 추측해서 바꾸지 않는다. 복사본은 다시 엄격 XML 검사를 통과해야 채택한다. 실패하면 기존 원문의 경고 있는 복구 경로를 사용하며 원문 일치가 확인되지 않은 표는 계속 차단한다.

원본·파싱용 복사본의 SHA-256, 보완한 원문 바이트 위치와 사유, 엄격 검사 결과를 추출 이력에 저장한다. 원문 파일을 생성본으로 덮어쓰지 않는다. 실제 근거 위치와 해시는 항상 원본 바이트에서 확인한다. 문법 검사를 통과한 것과 금융 검증 통과를 구분한다.

공식 원문 6개 모두 파싱용 복사본의 엄격 검사를 통과했다. 내용 차이 표는 33개에서 6개로 줄었고 연결대상 종속회사 상세표 6개는 모두 원문 내용과 일치했다. 나머지 6개(2024년 사업보고서 5개, 2024년 반기 1개)는 임원·보수·주총·계열회사·제재 관련 표다. 이 표들은 일치한 것으로 승격하지 않았다. 모든 원문 표를 완전히 읽었다는 뜻이 아니다.

기존 ‘단독 &는 복구 과정에서 반드시 손실된다’는 시험 전제는 새 기능으로 달라졌다. 정상 복원 시험을 추가하고, 여전히 엄격 검사에 실패하는 조합을 사용해 미확인 위치·표를 차단하는 기존 시험을 유지했다. 정의되지 않은 엔티티는 lxml이 텍스트로 보존할 수도 있음을 확인했으며, 실제 내용 손실을 유발하는 미지원 입력을 따로 사용했다.

### 연결 변경 확인과 비교 차단

`consolidation_checks.py`는 회사·표지 기간이 확인된 공시에서 ‘연결대상회사의 변동내용’ 문단, ‘구분/자회사/사유’ 머리글과 원문 셀을 확인한다. 실제 회사명과 당기 중 변동 사유가 명시된 신규 연결·제외만 `V03_scope_change_detected`로 저장한다. 대시·해당없음·계획/예정 표기는 변경 없음이나 실제 편입으로 추정하지 않는다.

실자료에서 2024년 사업보고서 접수번호 `20250314001195`, 원문 340행의 `SANGSIN BRAKE EUROPE SP.Z O.O.`와 ‘당기 중 설립출자’를 확인했다. 정확한 편입일을 알아냈다고 표시하지 않았다. 명시된 변동 기간과 겹치는 연결 비교 49개를 보수적으로 보류했다. 이 수는 계정·기간별 계산 수이며 기업 49개나 독립 사건 49개가 아니다.

해당 계산에는 양쪽 입력 금액·근거와 변경 확인 이력을 보존한다. 사용 가능한 `result` 필드는 두지 않고 산술 후보는 `unverified_arithmetic_result`로 구분한다. `scope_review.status=checked_change_detected`, `comparison_status=withheld`다. 완료 판정은 실제 변경 검증 ID와 비교 기간의 연결을 확인하며, 확인됐다는 플래그만 넣거나 존재하지 않는 ID를 주입하면 실패한다. 다른 기간 전체에 변경이 없었다고 선언하지 않았으므로 연결 범위 전체 검사는 아직 미완료다.

- 차입 주석 묶음은 기존 4개 통과/26개 미확인 그대로다. 본 보완이 리스·보증 구성까지 해결한 것은 아니다.

- 외부 데이터 요청·모델·추적 호출·Git 작업은 없다. 원문·이전 DB·이전 분석 파일·키·사례를 보존한다.

| 7. 계정명 차이 | 승인된 정확한 명칭 조합 4개만 공식 계정 코드·유동/비유동 분류·합계 수준으로 확인; 차입은 주석 구성 필요 | 유사도 매칭, 유동자산↔자산총계, 순수 매출채권↔기타채권 포함 합계, 유동↔비유동 거부 |
| 8. 흩어진 주석 | 회사·실행·범위·기준일·통화·공식 코드·원문 명칭·금액이 일치한 경우에만 같은 시점의 다른 공시 주석 연결 | 금액만 같은 경우, ‘사채 포함’ 표현 차이는 연결 거부 |
| 9. 구성 불명확 | 원문별 수치 확인은 보존하고 해당 필수 항목의 조사 사용·관련 증감·차입 소계 보류 | 미확인을 추가 항목으로 이동하거나 표현을 지워 완료 처리하지 않음 |

`note_context.py`에 표지·절 구조·본표 근거 연결을 두고 `note_checks.py`가 사용한다. `scope_observations.py`는 종속회사와 지분율, 변동표의 위치·공시 기간을 기록한다. 변경 없음은 절대적 선언 대신 **확보한 공시 범위에서 변경 미발견**으로 제한한다. 실제 변경은 확인 완료로 기록하되 조정 근거 없는 증감은 보류한다.

`borrowing_composition.py`는 차입 본표 3개 계정 소계와 리스 부채 분리 근거를 확인한다. 보증을 차입 소계에 가산하지 않으며 보증 노출액을 0으로 추정하지 않는다. 이 결과는 전체 금융부채·보증·리스까지 모두 파악했다는 의미가 아니다. `할인 후 리스부채`와 유동·비유동 합계 등을 대조하고 할인 전 금액이나 공정가치 열을 장부금액 대신 쓰지 않는다.

`account_equivalence.py`는 정확한 네 명칭 조합에 대한 증거를 저장한다. 원문 명칭은 그대로 둔다. 반기 비교에서 발견한 네 계정 × 별도/연결, 총 8개 비교에 적용됐다. `composition_review.py`는 같은 회사·실행·범위·시점·통화·계정에서 ‘사채 포함’ 표현의 유무가 섞인 경우 구성 검토를 기록한다. 이는 실제 사채 발행이나 구성 변경을 확정한 판정이 아니다. 관련 숫자의 원문/API 검증은 보존하지만 사용 가능한 계산 `result`는 제거하고 산술 후보만 `unverified_arithmetic_result`에 남긴다.

`numeric_validation.py` 정책 버전은 `numeric-validation-1.19`, 수용 판정은 `stage04-acceptance-1.9`, 원문 추출은 `dart-extraction-1.7`이다. 기존 후보와 이전 검증 이력은 수정하지 않는다. 새 DB 스키마 변경은 없다. 기존 API의 검증 이력 반환에 연결했고 Vue 화면 개편·초안 생성은 시작하지 않았다.

### 실제 자료 검증 결과

검증 입력은 기존 공식 공시·API 보관 자료다. 새 외부 요청·모델 호출은 0회다. 기존 수집 DB를 읽기 전용 백업한 새 분석 DB에서 실행했다.

- 본표 원문/API 수치 후보 606개 정확 일치. 기존 사례 수치 130개 일치. 독립 금융 전문가의 정확성 인증이나 전체 공시의 최신성 보장이 아니다.
- 차입 주석 금액 대조 30묶음 중 24개 확인, 6개 미확인. 최초 4개 확인/26개 미확인에서 개선됐다. 24개 차입 구성 근거와 엄격한 교차 공시 연결 2개를 기록했다. 교차 연결 2개는 추가 범위인 2022년 별도/연결이며, ‘사채 포함’ 표현을 건너뛴 연결은 없다.
- 연결 변경 1건, 종속회사·지분율 관찰 6건, 각 공시 기간 안의 변경 미발견 관찰 5건. 2024년 유럽 법인 신규 연결 관련 증감은 조정 근거가 없어 계속 보류한다.
- 필수 비교 114개가 모두 결과 또는 보류 사유를 가진다. 필요한 비교가 생성되지 않는 누락은 완료 조건을 통과하지 못한다.
- 구성 불명확 검토 18묶음: 2023·2024·2025년 말 × 차입 3개 계정 × 별도/연결. 영향을 받는 수치 기록 54개, 계산 보류 72개(필수 60개·추가 12개). 18건의 실제 오연결을 확정했다는 의미가 아니다.
- 전체 계산 386개 중 248개 통과·138개 보류. 보류 사유는 구성 검토 72개, 연결 변경 43개, 연결 범위 근거 부족 17개, 차입 구성 근거 부족 4개, 추가 반기 현금 입력 부재 2개다. 연결 변경의 전체 영향 49개 중 6개는 구성 보류와 겹치므로 기존 사유도 함께 보존한다.
- 원문 내용 차이 표는 33개에서 6개로 감소했고 필요한 종속회사 상세표 6개는 모두 원문 일치다. 남은 6개 표는 미지원 내용 차이를 유지한다. 문법 통과를 내용 확인이나 금융 검증 통과로 대신하지 않았다.

사채 관련 설명도 기존 6개 원문에서 조사했다. 2023·2024년 사업보고서의 ‘당사는 ... 회사채 ... 자금조달한 실적은 없습니다’ 문장을 찾고 원문 위치를 저장했다. ‘당사’의 범위와 실적의 기간·상품을 확인하지 않은 채 연결 종속기업 전체나 모든 기준일의 잔액 0으로 확대하지 않았다. 미상환 표의 대시도 0으로 바꾸지 않았다. 이 후보만으로 해제한 구성 검토는 0개다.

### 자동 검증과 실패 판정

전체 자동 시험 **147개 통과**(5.280초). 새 구성 검토 시험 6개에는 회사/실행/날짜/범위/계정/통화 분리, 같은 금액의 다른 구성 표현, 관련 없는 계산 보존, 강제 통과와 가짜 ID 차단이 포함된다. 합성 오류 시험과 실제 금융 정확성 검증을 구별한다.

최신 실자료 결과의 메모리 복사본에 아래 네 오류를 각각 주입했고 모두 종료 코드 1로 실패했다. 저장한 정상 결과는 변경하지 않았다.

1. 필수 비교 한 개 누락: `required_comparison_coverage_missing`.
2. 재고자산 비교의 공식 코드를 자산총계 코드로 변경: `account_equivalence_evidence_missing_or_invalid`.
3. 구성 보류 계산을 강제 통과시키고 결과값 삽입: `account_composition_withholding_missing_or_invalid`.
4. 보류 근거 ID를 존재하지 않는 ID로 변경: 같은 이유로 실패.

새 저장 인스턴스에서 저장된 검증·계산 이력을 다시 읽어 원래 결과와 일치함을 확인했다. 새 분석 DB의 SQLite 무결성 `ok`, 외래키 위반 0건이다. 이번 확인은 검증 이력 재조회이며 서버 재시작 후 조사 자동 재개 기능의 구현을 의미하지 않는다. 저장·서버 재시작 기초 검증은 앞선 단계와 전체 회귀에 포함된다.

최종 회귀 명령은 종료 코드 0이지만 **필수 항목 미완료 / 추가 항목 미완료 / 4단계 전체 미완료**다. 허용된 보류를 정직하게 기록하는 프로그램 동작의 회귀 통과와 금융 근거 확인 완료를 구분한다.

### 남은 문제와 다음 순서

사채 포함 표현을 같은 구성으로 볼 수 있는지 원문별 구성·재분류·시점·별도/연결 근거가 아직 부족하다. 기존 확인 문장과 주석 후보를 연결하되 범위를 확장해서 추정하지 않아야 한다. 현재 기업 밖의 지원 확대, 새 공식 자료 조회, 다른 비교 정책이 필요하면 범위와 이유를 설명하고 먼저 질문한다. 이 항목이 해소되기 전에는 관련 필수 완료나 동일 구성 비교를 허용하지 않는다.

추가 범위의 과거 주석·연결 비교·2023년 반기 현금 입력과 내용 차이 표 6개는 별도 미완료로 남는다. 실제 정정 공시·다른 회사/비12월 결산기까지 시험했다고 주장하지 않는다. 5단계 보고서 초안·6단계 후속 조사·화면 반영은 아직 시작하지 않았다. Git은 사용자 지시대로 보류하며 5~6단계에서 다시 질문한다.

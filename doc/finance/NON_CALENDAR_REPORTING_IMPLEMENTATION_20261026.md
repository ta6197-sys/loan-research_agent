# 비12월 결산 보고서·차트·분석 연결 결과

기준일: 2026-10-26. 기존 게시 보고서와 검증 배치, 코호트 스냅샷은 수정하지 않았다.

## 구현

- `report_context.py`는 기업개황의 확인된 결산월과 수집 계획의 실제 시작·종료일로 연간·반기 비교기간을 만든다. 숫자 검증 결과는 회사·범위·기간이 일치하는 행에만 연결한다.
- `xbrl_mapping.py`는 XBRL의 당기 컨텍스트를 결산월에 맞춰 해석한다. 독립적인 개념·기간·금액 대조를 거친 매핑만 `xbrl_report_gate`의 증거가 된다. 숫자 대조 통과와 게시 가능 여부는 별개 상태다.
- `general_collection.py`는 실적 원문의 XBRL 스키마에서 직접 선언된 DART 분류체계 참조만 안전한 기존 조회기로 받아 보관한다. 수집 완료의 다음 단계는 숫자 및 XBRL 검증이다.
- `change_analysis.py`, `financial_analytics.py`는 12개월 연간끼리, 6개월 반기끼리 전년 동기를 비교한다. 기간이 다른 수치를 섞지 않는다.
- `report_view.py`, `report_exports.py`는 명시된 비교기간으로 표와 차트를 만든다. `research_stage05.py`는 게시 직전에 비12월 보고서의 XBRL 게이트를 다시 확인한다.

결산월 변경·원문 기간 충돌·XBRL 컨텍스트 부재·매핑 실패는 보류한다. 과거 게시물의 기본 12월/6월 해석은 보존한다. 원문 검증 실패 행을 통계·ML 입력으로 승격하지 않는 기존 경계도 유지한다.

## 실제 세원정공 원문으로 확인한 범위

기존에 보관한 세원정공 6월 결산 자료를 격리 저장소로 복사한 뒤 검증했다. 원본 DB SHA-256은 `50b1e24f139fc71eb9a1066ff2c3b302e264f5e8daddc15101515b55c37afd2c`로 변하지 않았다. 5개 XBRL 보고서에서 직접 참조한 공식 분류체계 21개를 보관했고, 독립 매핑 112건의 개념·컨텍스트·금액 검사가 모두 통과했다. 기존 `numeric-validation-1.30` 배치를 재사용해 재무행 130건 중 86건을 `verified`로 연결했다. 격리 재현에서 게시 게이트는 `pass`였고 재무분석은 지원 47건, 보류 42건, 미측정 23건이었다. 차트 2개는 일부 기간 공백과 함께 표시 가능, 2개는 개정 버전 간 계정 대응 미확인으로 보류됐다.

이는 **게시 전 게이트의 재현 검증**이다. 실제 게시 보고서를 새로 만들거나 30392 코호트에 편입한 결과가 아니다. 상세 수치와 보류 사유는 [감사 JSON](FISCAL_REPORT_GATE_AUDIT_20261026.json)에 있다.

## 테스트 및 영향

`tests/test_non_calendar_reporting.py`는 3·6·9·12월 결산 연간·반기, 시작·종료일 불일치, 다른 기간 혼합, XBRL 근거 미확인, 게시 차단, 동적 차트·표, 공장과 법인 구분을 검사한다. `tests/test_general_company.py`의 수집 다음 단계 기대값도 수정했다. 전체 회귀 테스트 명령은 `.venv/bin/python -m unittest discover -s tests -q`다.

이 구현은 결산월과 원문 기간이 확인된 연간·반기에 한정된다. 결산월 변경 이력이나 분기 자료의 자동 승격은 제공하지 않는다. 기존 PDF·ZIP·UI 계약과 원본 저장 자료는 그대로 두고 새 검증 배치에서만 새 정책을 사용한다.

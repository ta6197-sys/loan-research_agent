# 계정과목 매핑 공식 자료 확인 및 후속 선택

확인일: 2026-10-21 (한국 시간)
상태: 공식 개념 우선·검증 독립, 기업 고유 계정 근거 수집 우선, 추가 XBRL 확보 모두 승인됨. 버전 간 연결은 공식 대응 근거 확인 후 허용하도록 확정. 대표 자료 확보·보고서 내부 매핑 구현 및 검증 완료.4단계 전체는 미완료이며 최초 검토와 질문 이력은 아래에 보존한다.

## 판단

공식 표준계정·택사노미·XBRL 관계를 활용해 계정을 식별한다는 사용자의 지적은 타당하다. 현재의 정확한 명칭 조합 허용만으로 지원을 넓히는 방식에는 한계가 있다. 표준 개념 식별과 원문 금액 검증, 상세 구성 검증, 기간 간 비교 허용을 구분하는 보완을 제안한다. 기존 다섯 검증 축과 사용 범위 제한은 유지하며, 표준 ID가 같다는 이유로 기존 구성 보류를 해제하지 않는다.

## 공식 출처 확인

- [OpenDART 단일회사 전체 재무제표](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020): account_id는 XBRL 표준계정 ID이며, 비표준 항목은 표준계정코드 미사용으로 표시한다. account_nm은 표시 계정명이다. OFS/CFS·재무제표 종류·보고서·통화·기간별 금액이 별도 정보다. account_detail은 가이드상 자본변동표에만 출력되므로 전체 계정의 세부 구분을 제공한다고 가정하면 안 된다. 분·반기 손익의 당기금액과 누적금액도 구분해야 한다.
- [OpenDART XBRL 택사노미 재무제표 양식](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2020001): xbrlTaxonomy API는 계정 ID·명칭·적용 기준일·한영 라벨·자료형·IFRS 참조를 제공한다. 공개된 요청 인자에 과거 버전 선택은 없고 응답 명세에 전체 계산 링크·차원 구조가 있지도 않다. 현재 사전만으로 과거 적용 버전과 모든 관계를 확인했다고 표시할 수 없다.
- [OpenDART 재무제표 원본파일 XBRL](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019019): fnlttXbrl.xml은 접수번호·보고서 코드로 XBRL 원본을 받는 별도 API다. 기존 document.xml 공시 문서와 구분한다. 실제 ZIP의 구성 및 참조 파일 포함 여부는 아직 검사하지 않았다.
- [XBRL Defining Reporting Requirements](https://specifications.xbrl.org/reporting-requirements.html): 라벨·정의 참조·표시 관계·계산 관계·세부 차원·택사노미 변경을 설명하는 공식 개요다. 표시 순서/계층 자체를 합산 관계로 간주하면 안 된다.
- [XBRL Essentials](https://specifications.xbrl.org/xbrl-essentials.html): 보고 값은 계정 개념뿐 아니라 회사·기간·단위 등의 문맥과 연결된다. 원본의 개념 정의와 문맥을 확보해 확인할 필요가 있다.
- [XBRL Anchoring 관계 가이드](https://www.xbrl.org/guidance/esd-relationships/): 공식 사이트 자료이지만 현재 페이지는 검토 초안이다. wider–narrower는 ESEF를 위해 개발한 넓은/좁은 개념 연결이며 동일성 선언이 아니다. 한국 공시마다 존재한다고 전제할 수 없다. 문서는 이 관계를 차원 구성원 간 연결에 쓰는 용도로 설명하지 않는다. 따라서 계정 연결 근거를 은행 법인명 변형의 동일성 증명으로 확대할 수 없다.
- [XBRL Calculations 1.1 공식 명세](https://www.xbrl.org/Specification/calculation-1.1/REC-2023-02-22%2Bcorrected-errata-2024-02-14/calculation-1.1-REC-2023-02-22%2Bcorrected-errata-2024-02-14.html): 계산 링크의 가중치와 문맥 일치, 보고 정밀도와 반올림 방식 등을 다룬다. 기존 2.1 계산과 1.1 계산의 처리 결과도 구분한다. 실제 파일의 관계 종류와 적용 규칙을 확인하지 않고 최신 명세 검증 통과라고 표시하지 않는다. 계산의 일관성만으로 공시 전체의 정확성이나 구성 항목 누락 부재까지 입증되는 것은 아니다.
- [IFRS IAS 1 공개 안내](https://www.ifrs.org/issued-standards/list-of-standards/ias-1-presentation-of-financial-statements/): 재무제표와 비교정보의 표시 기준을 안내한다. 비교정보 재분류 조항은 공식 PDF 검색 결과로 확인했으나 PDF 직접 열기는 구독 안내로 연결돼 전문 대조를 완료하지 못했다. 문단 전문 검토 완료로 기록하지 않는다.
- [IFRS IAS 8 공개 안내](https://www.ifrs.org/issued-standards/list-of-standards/ias-8-basis-of-preparation-of-financial-statements/): 회계정책 변경의 소급 적용, 추정 변경의 전진 적용, 중요한 전기 오류의 비교금액 재작성을 구분한다. 예외 조건도 존재한다. 같은 연도 값이라도 공시 시점과 재작성 여부를 보존해야 한다. 과거 판과 현재 판의 제목·적용 내용이 같다고 전제하지 않는다.
- [IFRS 18 공개 안내](https://www.ifrs.org/issued-standards/list-of-standards/ifrs-18-presentation-and-disclosure-in-financial-statements/): 국제기준상 2027-01-01 이후 시작하는 연차기간에 적용하며 조기 적용을 허용한다. 국내 적용 일정과 해당 기업의 실제 적용 여부는 이번에 별도로 확인하지 않았다. 2023~2026년 보관 자료에 자동 소급 적용하지 않는다.

위 자료는 개념 식별·계산·비교정보 관리의 공식 근거다. AI 매핑 절차, 내부 관계 이름 EQUAL/PART_OF/SUM_OF, 시스템의 자동 채택·보류 정책은 이 자료를 응용하는 구현 선택이다. 공식 자료가 특정 AI 절차를 요구하거나 모든 한국 공시에 앵커를 보장한다고 설명하지 않는다. 표준 문서 전문·예제 코드는 복제하지 않고 링크와 확인 사항을 기록했다.

## 현재 코드와 차이

- agent/finance/numeric_validation.py: ACCOUNT_IDS로 공식 코드를 검사한다. comparison_policy는 명칭이 다르면 account_equivalent 근거를 요구한다. 같은 공시의 원문 행과 API 행 연결에서도 명칭 일치를 검사하므로, 이 결합 조건과 기간 간 동일 개념 판정을 구분해 검토해야 한다. 원문 행 결합 조건을 무조건 삭제하는 제안이 아니다.
- agent/finance/account_equivalence.py: 네 가지 정확한 명칭 조합·공식 ID·유동/비유동 분류 등을 검사한다. 표준 개념을 일반적으로 식별하는 택사노미 저장소나 버전 대조는 아직 없다.
- agent/finance/document_extractor.py: 공시 DOCUMENT XML의 표·셀과 ACLASS 등 표시 정보를 읽는다. 실제 XBRL instance의 contextRef/schemaRef와 관련 택사노미 관계를 읽는 구현과 다르다.
- agent/finance/dart_protocol.py: XBRL 원본 및 택사노미 API 연결은 아직 없다.

## 사용자에게 묶어 질문한 선택

1. 공식 표준계정 개념 우선 연결로 보완할지, 현행 정확한 명칭 조합 제한을 유지할지. 추천안은 개념 연결 상태와 금액·차입 구성·비교 가능 여부를 분리한다. 개념만 확인돼도 구성 미확인이나 범위 변경이 남으면 관련 비교는 보류한다.
2. 2025년 사업보고서(20260318001187)·2026년 반기보고서(20260813000874)의 XBRL과 필요한 공식 사전·참조를 새 검증 자료로 확보할지. 추천안의 전체 HTTP 요청 상한은 재시도·리다이렉트 포함20회다. 부족하면 중단하고 부족 근거를 기록한다. API 키는 DART에만 사용하고 모델 전송은 없다. 다른 선택은 보관 자료만 사용하는 것으로, 원본 관계 확인 한계가 남는다.
3. 표준계정부터 검증하고 기업 고유 계정은 실제 관계 근거 수집부터 할지, 기업 고유 계정의 포함·합산 연결 기능까지 이번 단계에서 구현할지. 넓은/좁은 관계만으로 같은 계정이라고 확정하거나 명칭/AI 추측만으로 자동 채택하는 방식은 어느 쪽에도 포함하지 않는다.

이 질문들은 계정 매핑에 관한 것이다. 앞서 보류한 농협은행 표기쌍의 법인 동일성은 별도 근거 문제로 남으며 이번 확인으로 승인·적용된 것이 아니다.

## 이번 작업 및 검증 범위

공식 공개 문서 조회와 코드 정적 대조, 본 기록과 진행 로그 추가만 수행했다. 실행 코드·설계 결정·실제 DB·원문·기존 검증 결과는 변경하지 않았다. 신규 DART 데이터 요청·XBRL 수집·모델/추적 호출·Git 작업은 수행하지 않았다. 실행 코드 변경이 없어 자동 시험은 재실행하지 않았다. 기존170개 시험 결과나 금융4단계 미완료 상태를 새로 검증·승격한 작업이 아니다. 추가 자료 수집 및 구현은 위 선택에 대한 답변 후 진행한다.


## 2026-10-21 — 선택 1·3 확정, 보관 자료와 추가 XBRL 확보 목적 설명

사용자는 (1) 공식 계정 개념 우선·금액/구성/비교 독립 판정, (3) 표준계정 우선·기업 고유 계정은 관계 근거 수집부터를 선택했다. 이 두 방향은 확정됐다. (2) 추가 XBRL 확보는 승인된 것이 아니며, 보관 자료의 의미와 현재 흐름을 먼저 설명해 달라고 요청했다.

실제 collection.json과 로컬 저장 파일을 읽어 확인했다. 기존 자료는 상신브레이크 2023·2024·2025년 사업보고서, 2024·2025·2026년 반기보고서의 공시 본문·주석 및 별도/연결 재무제표 API 응답이다. 원문 파일은 로컬 sources에, 등록 정보·추출/검증 이력은 SQLite에 보관한다. 실행 메모리나 모델 기억을 뜻하지 않는다. 기존 공시 ZIP 내 XML의 루트는 DOCUMENT로, 실제 XBRL instance를 확보했다는 뜻이 아니다. 첫 확인에 시스템 Python을 사용해 lxml 가져오기가 실패했으며 프로젝트 .venv/bin/python으로 다시 실행해 로컬 파일 확인을 마쳤다. 파일 추출·네트워크 참조·DB 쓰기는 하지 않았다.

현재까지의 흐름은 공식 공시·API 수집 → 원문 표/셀/금액 추출 → 원문과 API 대조 → 구성·비교 가능 여부 별도 검사다. 최신 보관 결과는 추출 수치606개, 구성 검토 미해결16개이며4단계 미완료다. 이는 기존 결과를 읽은 것이며 이번에 금융 정확성을 새로 검증한 것은 아니다.

추가 확보 목적은 같은2025년 사업보고서·2026년 반기보고서의 XBRL과 필요한 공식 사전/참조를 이용해 이름이 달라도 같은 공식 개념인지 판단하는 기능을 실제 자료로 검증하는 것이다. 기존 자료 교체, 조사 회사/기간 확대, 외부 모델 분석 요청이 아니다. XBRL 안의 정의·문맥·관계와 참조 파일을 검사해야 하며, 모든 주석이나 은행 표기 동일성이 자동 해결된다고 보장하지 않는다. 계정 연결이 확인돼도 기존 구성·범위 변경 보류는 각 검사 결과에 따른다.

설명 후2번만 다시 질문했다. 추천안은 전체 HTTP 요청 최대20회(실패·재시도·리다이렉트 포함), 기존 파일 보존, 새 검증 자료로 저장, 키는 DART에만 사용, 모델 전송 없음이다. 추가 확보를 보류하면 기존 검증은 유지하되 원본을 이용한 개념 매핑 실자료 검증은 미완료로 둔다. 답변 대기 중이며 신규 DART/XBRL 요청·실행 코드 변경·시험 재실행·Git 작업은 수행하지 않았다.


## 2026-10-21 — 추가 확보 승인·구현 결과

추가 XBRL 확보도 승인됐으며, 실제 namespace 버전 차이에 대한 후속 질문에서는 보고서 내부 검증부터 진행하고 버전 간 연결은 공식 대응 근거 확인 후 허용하도록 확정됐다. 총12회 요청으로 대표 XBRL2개·공식 사전6종·핵심 참조 스키마4개를 확보했다. 새 개념 매핑 도구에서52건의 식별·문맥·금액을 확인하고26개 버전 간 개념 연결을 미확인으로 남겼다.4단계 전체와 기존 차입 구성 미해결16건은 계속 미완료다. 상세 결과는 [XBRL 구현 기록](IMPLEMENTATION_STAGE04_XBRL.md)을 따른다. 이 절이 앞선 답변 대기 상태를 갱신한다.

## 3. 최신 사용자 승인 — 다시 물을 필요 없는 사항

1. 공식 계정 개념을 먼저 식별하고 금액·차입 구성·비교 가능 여부는 독립 판정한다.
   보고서별 공식 개념을 확인하되 IFRS2021↔2024 등 버전 간 연결은 공식 대응 근거 확인 후 허용한다.
   기업 고유 계정은 관계 근거 수집부터 하며 포함/합산 관계를 동일성으로 바꾸지 않는다.
2. 과거 XBRL 네 보고서와 필요한 공식 참조/대응 자료를 추가 최대20회 HTTP 안에서 확보한다.
   이전 대표 자료 수집12회 기록은 별도로 보존하며 예산을 재설정하지 않는다.
3. 본문의 대시는 그대로 보존한다. 같은 보고서의 XBRL에 회사·범위·시점·은행·대출 구분이 정확히 대응하는 명시적0이 있을 때만 별도 수치 근거로 사용할 수 있다.
   본문을0으로 고치거나 다른 보고서의0, nil, 누락, 모호한 대응을 사용하지 않는다.
4. 은행의 전역 별칭을 만들지 않고 개별 공시 차입 항목의 대응만 허용한다.
   같은 기업 고유 구성요소 ID 이름만으로 충분하지 않다. 공시 구조와 회사·범위·시점·대출 구분·각 금액·빠짐없는 합계·필요한 재분류가 모두 맞아야 한다.
   은행 법인 전체/실제 계약/은행별 상환 일정이 확인됐다고 표시하지 않는다.
5. 공식 기준 문서는 같은 DB의 별도 출처 종류 official_standard로 구분하고 발행기관·버전·원문 위치·이용 제한을 저장한다.
   회사 재무 사실로 취급하지 않는다.
6. XBRL에 `xmlns:XBRLConsultingFirm="자체작성"`이라는 사용되지 않은 작성 도구 메타데이터 선언이 있을 때만 파싱용 복사본에서 해당 선언 하나를 제외한다.
   실제 계정·수치·참조에서 접두사가 쓰이면 허용하지 않는다. 원문은 보존하며 엄격 파싱과 전체 원문 논리 트리의 태그/속성/글자/꼬리 글자 대조를 다시 한다.
7. **4단계 소프트웨어 구현 완료와 실제 사례의 금융 자료 확인 완료를 분리한다.**
   필요한 대조·차단·근거 추적·실패 시험을 마치면 구현 완료로 판단하고 5단계를 진행할 수 있다.
   필수/추가 항목·차입 구성·버전 대응의 미확인은 그대로 남긴다. 보류 수치/비교를 확인된 결과로 쓰지 않는다.
   이 마지막 결정은 아직 코드 반영 전이다. 기존 stage4_complete를 근거 없이 true로 바꾸는 뜻이 아니다.

차입금 원문 금액·상세 합계·문서 간 구성 동일성·유동/비유동 재분류·은행별 배분의 5개 검사는 이미 독립 상태로 관리한다.
전체 명시 항목과 양수 잔액 구성도 구분한다. 계정 합계만 확인해도 전체 계약/은행별 배분이 확인되는 것은 아니다.

2. xbrl_borrowing 초안을 검토하고 단위/기간/범위/차원/중복/상충/원문 위치/해시 위조를 거부하는 시험을 먼저 준비한다.
3. borrowing_details의 수평/수직 미확인 항목에 원문 name_location/purpose_location을 보존한다.
   현재 초안은 이 위치가 없으면 명시적0을 채택하지 않으므로, 기존 누락을 추측으로 넘기지 않는다.
4. NumericValidationService의 상세 수집 이후에 새 근거 연결을 통합한다.
   xbrl_mapping→numeric_validation 의존성이 있으므로 순환 import를 주의한다. 기존 판정 이력은 보존하고 정책 버전을 올린 새 이력을 만든다.
5. review/verification_levels/acceptance에서 원래 전체 항목 비교를 보존하고, 모든 관측의 상세와 구성 근거가 완전한 경우에만 공시 항목 대응에 따른 잔액 비교를 허용한다.
   기존 vector 함수를 일괄 변경해 한쪽만 근거가 있는 경우를 통과시키지 않는다.
   위조된 binding/augmentation/구성요소/0근거를 수용 판정에서 다시 차단한다.
6. 위 3절7번의 구현 완료/금융 확인 상태 분리를 구현한다.
   구현 완료의 기능·실패 시험 근거를 갖추고 금융 필수/추가/보류 상태를 별도로 유지한다.
   이 분리 자체로 아직 미완성인 소프트웨어를 완료 처리하지 않는다.
7. 아래 남은 코드 보완과 전체 자동 시험·새 복사본 실자료 검증·재시작 조회·원본 보존 확인을 수행한다.
8. 결과와 남은 금융 미확인을 기록한다. 구현 기준이 충족되면 승인된 방식으로5단계에 진입한다.
   모델/전송/새 데이터/새 설계 선택은 질문한다. Git은5~6단계에서 다시 질문한다.

검토해야 할 추가 코드 보완:
- xbrl_mapping은 한 archive의 파싱 오류가 전체 배치를 중단할 수 있다. 읽을 수 없는 보고서는 실패/미확인으로 분리하고 다른 보고서의 확인을 보존하는 처리가 미구현이다.
- 사용되지 않은 메타데이터 선언 처리의 거부 시험(실제 사용/다른 오류/내용 차이/중복 선언), official_standard 권리/복구 회귀 시험이 없다.
- 공식 문서 수집 실패 로그의 retrieved_url에 인증 이동 주소가 남을 수 있다.
  새 진단 출력은 선언 URL+접근 필요 상태만 남기도록 보완하고, 자체 생성 진단의 불필요한 인증 이동 URI도 검토한다. 키/토큰/환경 원문은 출력하지 않는다.
- 기존 메타데이터 original_tree_signature 오류가 난 중간 분석은 실패 기록이다. 045538Z 성공 결과와 혼동하지 않는다.

## 8. 보존할 원본과 실행 참고

기존 금융 수집 원본:
`data/research/validation_hardening/live/20261020T233956Z-db52d0dc/`
원본에 ResearchStore를 열면 자동 마이그레이션/저장 복구 쓰기가 일어날 수 있으므로 원본 열람은 SQLite mode=ro와 원문 해시 읽기를 사용하고 분석은 backup 복사본에서 한다.

최근 기존 수치 분석:
`data/research/validation_hardening/live/20261020T233956Z-db52d0dc/analysis/20261021T042341Z-b6864f3d/`

대표52건 검증/재시작 확인:
`data/research/validation_xbrl/20261021-authorized-pilot/analysis/20261021T042536Z-75088913/`

오프라인 통합 재검사 명령:
`.venv/bin/python sh/validate_stage04_xbrl_integrated.py`
새 분석 폴더를 만들며 외부 요청이나 모델 호출을 하지 않는다. 미완성 통합 후에는 적절한 시험을 먼저 수행한다.
전체 시험의 정확한 실행 명령은 저장소 기존 시험 문서/실행 파일을 확인한다.

임시 시험 로그는 /tmp이므로 다음 세션에서 없어질 수 있다. 이 문서의 결과와 data/의 결과 JSON을 함께 확인한다.
현재 마지막 추가 모듈은 문법 검사만 완료했으며 후속 구현/검증을 다음 세션으로 인계한다.

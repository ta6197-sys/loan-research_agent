# 4단계 — 공식 XBRL 계정 개념 식별·독립 대조 구현

2026-10-21. 대표 보고서2개 안에서 현재기간13개 계정의 별도/연결52건을 공식 스키마 선언·문맥·API 금액으로 확인했다. 보고서 간26개 개념 연결은 표준 버전 차이로 미확인이다. 기존 차입 구성 미해결16건을 유지하며 **4단계 전체는 미완료**다.

## 확정한 범위

사용자는 공식 계정 개념 우선 연결, 금액/구성/비교 독립 판정, 기업 고유 계정은 실제 관계 근거 수집부터 진행하도록 선택했다. 같은 보고서의 XBRL·공식 사전/참조 추가 확보를 승인했다. 총 HTTP 상한은 실패·재시도·리다이렉트 포함20회이며, 키는 DART에만 사용하고 모델 전송은 금지한다.

실제 버전 차이를 확인한 뒤 추가로 질문했고, 사용자는 보고서별 확인을 먼저 진행하고 버전 간 연결은 공식 변경 내역·대응 근거 확인 후 허용하도록 선택했다. 코드 이름·자료형이 같다는 이유로 확정하거나 구조 후보를 증감에 사용하는 방식은 적용하지 않았다.

## 실제 확보 자료

새 수집 저장소: `data/research/validation_xbrl/20261021-authorized-pilot/`

- 2025년 사업보고서 접수번호20260318001187의 XBRL ZIP과 구성 파일7개.
- 2026년 반기보고서 접수번호20260813000874의 XBRL ZIP과 구성 파일7개.
- 공식 사전6종: BS1/BS2, CF3/CF4, DCIS1/DCIS2.
- 원본의 import가 직접 지정한 IFRS·DART 핵심 스키마4개.
- 누적 실제 HTTP12회/상한20회. 추가 모델·추적 호출 없음.

자료 원본 바이트와 출처·접수번호·해시·저장 시각을 기존 SourceInput/ResearchStore의 원문 저장 복구 흐름으로 보관했다. 선언된 참조 URI와 실제 HTTPS 수신 URI를 구분해 저장했다. 참조 파일에는 인증키를 보내지 않았다. 참조 주소는 같은 조사 원문에 선언된 DART 공식 택사노미 경로로 한정했다. 리다이렉트도 요청별 예산에 포함하며 외부 호스트나 HTTP로의 이동을 거부한다.

수집 명령은 이 승인 작업의 고정 저장소와 누적 SQLite 실행 예산을 재사용한다. 재실행한다고 새20회 예산을 만들지 않는다. 이미 결과가 기록된 수집 항목은 다시 요청하지 않는다. 새 승인을 받기 전 한도를 재설정하거나 다른 회사·기간으로 확대하지 않는다.

## 확인한 자료 차이

2025년 보고서는 IFRS2021-03-24 및 DART2024-06-30 스키마를 참조하고, 2026년 반기보고서는 IFRS2024-03-27 및 DART2026-01-31 스키마를 참조한다. 실제 IFRS namespace도 http/https 및 버전 경로가 다르다.

공식 계정 사전 API에는 ifrs_ 접두사와20180701 적용 기준일을 가진 행이 있으며, 실제 보고서와 전체 재무제표 API에는 ifrs-full_ 접두사가 사용됐다. 접두사를 지우거나 바꿔 같은 계정으로 만들지 않았다. 이번 확인은 보고서가 참조하는 핵심 스키마 선언과 실제 fact의 QName을 이용했다. 사전의 IFRS 참조는 그대로 보관하며 과거 버전 전체의 의미 대응을 확인한 것으로 취급하지 않는다.

공식 개발가이드와 검토 한계는 [공식 자료 확인 기록](ACCOUNT_MAPPING_OFFICIAL_REVIEW_20261021.md)에 연결돼 있다.

## 판정의 의미와 오연결 방지

계정 식별 확인은 보고서가 참조하는 공식 namespace의 선언 ID·자료형·기간 유형 등을 실제 fact와 연결했다는 의미다. 전체 회계적 의미나 공시의 정확성을 보증하는 판정이 아니다.

회사·별도/연결·시점/기간·통화·세부 구분을 대조한다. 부문·은행·계약 등 추가 차원이 있는 값을 본표 총액에 섞지 않는다. 기업 고유 스키마에서 표준 ID처럼 보이는 이름을 사용해도 공식 계정으로 채택하지 않는다. 다른 공식 개념·다른 유동성·다른 기간 유형을 같은 계정으로 합치지 않는다. 이름 유사도와 AI 매핑은 사용하지 않았다.

금액은 Decimal과 원문 문자열로 정확히 대조한다. nil·빈칸·대시를0으로 바꾸지 않는다. 상충하는 중복 fact에서 API와 같은 값 하나만 골라 통과시키지 않는다. 반기 손익에서는 누적금액과3개월금액을 구분한다. 엄격 XML 검사만 사용하며 새 XBRL을 복구해서 근거로 채택하지 않는다.

같은 표준 ID가 자본변동표 세부 항목 등에도 나타났다. 초기 진단에서는 본표가 아닌 행까지 읽어97개 기록이 생겼으므로 API의 재무제표 종류를 적용해 본표 대조 대상과 구분했다.45개 행을 본표 대조 대상에서 제외하되 원본은 보존했다. 초기 진단 결과를 실제 공시 오류나 최신 확인 결과로 취급하지 않는다.

기업 고유 계정 선언832건과 표시/계산/정의 관계선13,234건은 두 보고서의 원문에 기록된 항목 수의 합계다. 서로 다른 개념832개가 모두 검증됐다는 의미가 아니다. 관계선은 priority/use/weight/role/출처와 함께 recorded_not_applied로 보관한다. 표시 관계를 합산 관계로 바꾸거나, 포함 관계를 동일성으로 바꾸지 않았다. 관계의 전체 유효성 결정·계산 수행·확장계정 자동 매핑은 이번 범위가 아니다.

## 남은 일과 다음 순서

1. 공식 변경 내역·대응 근거로 IFRS2021↔2024 및 DART 버전 간 해당 계정의 대응을 확인한다. 코드 이름·자료형 일치만으로 연결하지 않는다.
2. 확인한 대응을 새 매핑 이력에 추가하고, 기존 증감·차입 구성 검증에서 필요한 근거와 연결한다. 현재 새 도구의 개념 판정이 기존 계산 보류를 자동 해제하지는 않는다.
3. 차입 구성 미해결16건, 농협은행 표기쌍의 법인 동일성 등 기존 미확인을 별도로 해결한다. 계정 ID가 확인됐다고 은행 법인·대출 계약이 같다고 판단하지 않는다.
4. 다른 과거 기간의 XBRL과 전체 첨부 형식·일반 기업 지원은 이번 대표 자료 검증 완료로 확대하지 않는다.2023~2024년/2025년 반기 XBRL은 이번 추가 확보 대상이 아니다.
5. 4단계 필수·추가 판정을 다시 평가한 뒤5단계로 진행한다. Git은 이번 작업에서 커밋·푸시하지 않았다.

자료를 모델/외부 추적으로 전송하지 않았으며 NCS 교재의 본문·추출·이미지를 새로 적재하거나 복사하지 않았다. 기존 사용자 설계 문서 변경은 보존했다.

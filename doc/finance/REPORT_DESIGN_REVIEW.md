## 2. ‘기본 확인’과 ‘심화’의 구분

일곱 항목은 매번 빠뜨리지 않고 점검한다. 각 항목에서 실제로 확인한 범위, 근거, 남은 부분과 이유를 남긴다. 기본 확인을 했다는 것과 모든 질문이 해결됐다는 것을 구분한다.

발견한 쟁점은 관련 주석·과거 보고서·정정·후속 공시 등으로 더 조사한다. 공개 자료로 확인 가능한 내용을 먼저 찾고 대조한다. 내부 정보가 필요하거나 추가 조회로 해결하지 못한 충돌은 질문으로 남기며, 나머지 조사와 초안 작성은 계속한다.

다음 두 가지는 기존 합의를 유지한다.

- 신청 조건이나 내부 정보가 비어 있어도 확인된 범위로 초안을 제공한다. 초안 작성 전 승인 단계는 없다.
- 조회·시간·재작성 한도에 도달했다고 미확인 내용을 검증 통과로 바꾸지 않는다.

## 3. 일곱 항목의 최소 확인 내용 — 확정

**사용자가 다음 표의 최소 확인안을 적용하도록 선택했다.** 각 항목에 원문·관련 주석·확인 범위·남은 질문을 기록한다. 상신브레이크에서 확인한 자료와 한계를 바탕으로 작성한 서비스 체크리스트이며 은행 내부 규정이 아니다.

| 기본 항목 | 합의한 최소 확인 내용 | 그 항목을 두는 이유 | 더 조사할 조건의 예 | 초안에 남길 내용 |
| --- | --- | --- | --- | --- |
| 1. 기업 식별·조사 기준 | 대상 법인·고유번호, 목적, 조사 기준일, 보고 기간, 연결/별도, 사용 보고서·정정 상태 | 다른 법인이나 다른 기간의 자료가 섞이면 이후 해석이 달라짐 | 회사명 중복, 범위·계정 변경, 정정·비교 수치 차이 | 기준 요약과 사용 자료, 대조하지 못한 범위 |
| 2. 사업·매출 구조 | 주요 제품·사업, 판매 방식, 공개된 부문·지역·거래 구조와 자료 범위 | 회사가 어떻게 매출을 만들고 회수하는지 이해해야 자금 용도와 연결 가능 | 구성 변화·집중·계절성·계열회사 거래 또는 총액/순액 차이 | 확인한 사업 구조와 자금 필요에 연결할 질문 |
| 3. 재무상태·수익성 | 자산·부채·자본과 매출·영업이익·순이익의 동기간 변화, 관련 주석 | 잔액과 성과의 변화를 구분하고 설명의 출발점 마련 | 손익 방향 차이, 흑자/적자 전환, 일회성·비현금 손익, 잠정/확정 차이 | 변화의 사실, 근거 있는 설명, 설명하지 못한 부분 |
| 4. 현금흐름·운전자본 | 영업현금흐름과 이익의 관계, 채권·재고·매입채무 관련 변동, 현금흐름 주석 | 이익·잔액 증가를 현금 유입이나 회수 지연으로 잘못 해석하지 않도록 함 | 이익과 현금 방향 차이, 자금 유출입에 영향을 주는 구성 발견 | 본표·주석 연결과 회수·판매·지급 관련 미해결 질문 |
| 5. 차입·만기·유동성 | 현금·차입 구분과 구성, 공개 만기·리스·담보·약정·자금 사용 제약 | 차입 잔액, 계약상 상환 일정, 담보·인출 가능 한도를 구분 | 특정 만기 집중, 범위 불일치, 사용 제한, 차환·담보·약정 관련 쟁점 | 확인된 잔액·공개 일정과 현재 차환 등에 필요한 정보 |
| 6. 공시된 부담·보고서 신뢰성 | 감사/검토 자료, 공시된 보증·소송·약정과 기준일 이후 후속 공시 | 본표에 바로 보이지 않는 부담과 자료의 시점·신뢰성 확인 | 보증 연장·신규 부담, 감사 관련 쟁점, 잠정/후속 자료 차이 | 사건의 기준일·내용·진행 상태와 불확실성 |
| 7. 대출 목적·상환재원 연결 | 제공된 신청 용도·금액·기간·집행 시점·상환 계획과 공개 자료의 연결 여부 | 일반적인 기업 소개가 실제 사전조사 목적에서 벗어나지 않도록 함 | 용도와 공시 활동의 불일치, 상환 시점·재원의 근거 부족 | 제공된 조건, 없는 조건, 필요한 자료·질문과 이유 |

수치 변화가 있다는 사실만으로 위험을 확정하거나 조회 이유를 만들지 않는다. ‘크게 증가’ 등의 수치 기준과 중요한 쟁점의 판정 기준은 별도 논의 대상이다. 위 예시는 자동 발동 임계값이나 구현 명세가 아니다.

공개 만기표를 찾았더라도 차주 단독 범위와 맞지 않으면 그 이유와 실제 확보 범위를 남긴다. ‘미확인’과 ‘해당 없음’을 구분하려면 각각의 이유와 근거가 필요하다. 항목을 통째로 ‘확인 완료’라고 표시해 부분적인 미확인을 가리지 않는다.

## 4. 공통 수치표 — 본문 13개 계정 확정

상신브레이크에서 원문과 대조한 다음 13개 계정을 **본문에 표시하도록 확정했다.** 확보하지 못한 값은 이유와 확인 시도를 남기며 다른 계정을 몰래 대체하지 않는다.

| 묶음 | 표시할 수치 | 작성할 때의 주의 |
| --- | --- | --- |
| 손익 3개 | 매출액, 영업이익, 당기·반기순이익 | 누적/3개월, 연결 순이익/지배주주 귀속 이익을 구분 |
| 현금흐름 1개 | 영업활동현금흐름 | 영업에서 창출된 현금과 영업활동현금흐름을 구분 |
| 자산 구성 3개 | 현금및현금성자산, 재고자산, 매출채권 및 기타유동채권 | 기타채권을 포함한 수치를 순수 매출채권으로 쓰지 않음 |
| 차입 3개 | 단기차입금, 유동성장기부채, 비유동 차입금 | 분류·명칭을 주석과 확인하고 리스·보증과 구분 |
| 재무상태 3개 | 자산총계, 부채총계, 자본총계 | 법인·시점·범위가 같은 값끼리 합계 확인 |

차입 합계를 표시하면 구성 항목과 리스 포함 여부를 함께 남긴다. 현금은 사용 가능 자금 전체와 같다고 가정하지 않는다. 구성 표와 잔액에 빈 값이 있으면 0으로 메우지 않는다.

13개 계정만으로 모든 쟁점을 설명하지 않는다. 필요하면 비유동 채권·매입채무·환산손익·리스·금융상품·약정 등을 추가 확인한다. 새 재무비율이나 은행 기준의 위험 점수는 이번 검토안에 도입하지 않았다.

공통 기본값은 최근 3개년+최신 분·반기, 손익·현금흐름 전년 동기간, 중간 재무상태 직전 연말 비교다. 전년 동기 말 잔액은 보조한다. 별도 중심·연결 보조는 은행 규정이 아닌 서비스 정책이다. [근거와 한계](design/COMPARISON_POLICY_RESEARCH.md)를 구분해 적용한다.

## 5. 보고서의 읽는 순서

**앞부분에서 핵심 사실과 남은 질문을 판단하고, 필요할 때 뒤의 근거로 이동하는 구조를 확정했다.** 구체적인 페이지 수와 화면 접기·펼치기 방식은 미정이다.

| 순서 | 구성 | 독자가 확인할 내용 |
| --- | --- | --- |
| 머리말 | 대상 법인·목적·기준일·재무 범위 | 어느 기업의 무엇에 대한 초안인지 |
| 1 | 핵심 요약 | 중요한 확인 사실, 근거 있는 해석, 미해결 부분 |
| 2 | 우선 확인할 질문 | 무엇이 부족하고 왜 필요한지, 어느 쟁점을 바꾸는 답인지 |
| 3 | 조사 기준·사업 이해 | 사용 자료·기간·정정 상태, 주요 사업·매출 구조 |
| 4 | 재무 표·핵심 차트 | 동기간 변화와 잔액. 단위·범위·근거 포함 |
| 5 | 주요 쟁점과 설명 | 사실→해석→추가 조사 결과→남은 부분 |
| 6 | 근거·계산·항목별 확인 범위 부록 | 원문 위치, 산식·입력값, 일곱 항목의 확인 범위·한계 |

반기 이후 사건은 해당 쟁점과 요약에 함께 연결한다. 감사·검토 구분과 자료 충돌은 필요하면 요약에 표시하고 상세 근거를 뒤에 둔다. 신청 용도·상환재원 연결은 질문과 쟁점에 포함하며, 미제공 조건을 추정해 채우지 않는다.

재사용할 수 있는 구체적 문안은 [검토 초안 양식](REPORT_TEMPLATE.md)에 작성했다. 화면·PDF·Markdown은 같은 게시 버전에서 생성한다. Markdown·차트·근거 목록은 ZIP으로 동봉한다.

## 6. 주장·근거·질문을 연결하는 예

아래는 상신브레이크 사례에서 확인한 조사 경로를 축약한 설명이다. 새로운 위험 판정이나 추정치를 추가하지 않았다.

| 구분 | 보여줄 내용의 예 | 연결할 근거 |
| --- | --- | --- |
| 확인된 사실 | 이익과 영업현금흐름의 방향이 다름 | 같은 기간·같은 범위의 두 본표 |
| 근거 있는 해석 | 영업 관련 자산·부채 변동이 현금 유출 설명에 기여 | 현금흐름 주석의 구성과 재계산 |
| 미확인 | 판매·거래조건·회수 지연의 기여도와 실제 회수 시점 | 공개 자료에서 확인한 범위와 남은 한계 |
| 추가 질문 | 해당 채권의 회수 일정·실제 회수 내역은 무엇인가? | 질문이 해결할 설명과 필요한 자료 |

근거 번호만 붙이는 것으로 충분하지 않다. 연결한 자료가 해당 법인·기간·주장을 뒷받침하는지 확인해야 한다. 과거 시점의 보증이나 현금을 현재 상태로 바꾸어 표현하지 않는다.

## 7. 차트와 표

확정된 것은 핵심 추이 차트와 주요 쟁점·근거 표다. 상신브레이크 사례에는 사용자가 선택한 영업이익·영업현금흐름과 현금·차입금의 연간/반기 네 차트를 유지한다. 공통 정책은 두 주제를 기본으로 하고 비교 가능한 기간만 표시하며 쟁점별 차트를 추가하는 방식으로 확정했다. 모든 기업에 네 차트를 강제하지 않는다.

- 차트에 법인 범위·단위·기간·원문을 표시하고, 수치의 산식·구성은 부록에 연결한다.
- 손익·현금흐름 같은 기간 누적과 현금·차입 같은 시점 잔액을 구별한다.
- 만기표를 쓰려면 장기차입/전체 금융부채, 원금/이자 포함, 별도/연결 범위가 맞는지 확인한다.
- 공시 수치로 독립 제작하며, NCS 교재나 회사 IR의 도표를 복제·변형하지 않는다.

## 8. 이번에 바꾼 실제 사례와 남은 결정

[상신브레이크 초안](cases/sangsin_brake/CASE_REPORT.md)은 핵심 요약→질문→조사 기준→사업·재무·쟁점 순서로 재배치했다. 기존 수치·계산·근거·차트는 유지하고, 조사 항목의 현재 합의 상태를 갱신했다.

세부 최소 확인표와 본문 13개 계정은 확정했다. 현재는 사용자의 지시에 따라 제품 구현 없이 [상세 설계](design/README.md)를 정리한다. 자동 복구·저장·근거·API·화면·검증의 명세와 [남은 선택](design/DECISIONS.md)을 확인한다. 이 문서의 사례 결과를 금융 기능 실행 검증으로 소개하지 않는다.

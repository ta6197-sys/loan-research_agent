# SK㈜ 일반 기업 조사 확장 계획

기준일은 2026-10-22이며, 대상은 SK㈜이다. 이 계획은 상신브레이크 보관 사례 전용 경로와 기존 조사·보고서 이력을 보존하면서, 일반 기업의 공개 공시 조사 경로를 추가하기 위한 실행 순서다.

## 목표

회사 식별부터 OpenDART 공개 공시 수집, 원문·XBRL 근거 저장, 수치 검증, 일곱 조사 항목의 확인 범위와 질문, 보고서·PDF·Markdown 출력까지 한 조사로 연결한다. 확인하지 못한 사실은 보류하고, 대출 승인·등급·한도·금리 판단을 만들지 않는다.

## 우선 구현: 재무 변화 원인 분석

일반 기업 수집과 병행하되, 먼저 보관 사례에서 검증된 수치를 사용하는 분석 계층을 만든다.

1. 별도 범위에서 같은 비교 기간의 차입 3계정, 재고, 매출채권 및 기타채권, 영업현금흐름 변화를 계산한다.
2. 차입 증가·운전자본 증가·영업현금흐름 감소가 함께 관찰돼도 이를 인과관계로 확정하지 않는다. 가능한 설명, 반대 근거, 필요한 공시와 내부 자료를 따로 기록한다.
3. 차입 구성 중 하나라도 보류이면 차입 합계·원인 가설을 만들지 않는다. 매출채권 및 기타채권 합계로 DSO·CCC를 계산하지 않는다.
4. 다음 조사 행동은 차입금 주석, 현금흐름 조정 내역, 재고 구성, 회수 일정처럼 검증 가능한 자료로 제한한다. 공개 자료가 부족하면 담당자 질문으로 남긴다.

첫 구현은 `agent/finance/change_analysis.py`에 추가했다. 이후 보고서 화면·출력에 변화 사실, 가설, 반대 근거, 추가 질문을 근거와 함께 표시한다.

## 실행 원칙

- 기존 `cached_case` 실행은 변경하지 않는다. 일반 기업은 `general_company` 트리거와 별도 자료 목록·근거·실행 이력을 사용한다.
- 외부 요청은 실행별 예산(기본 60회)과 공개 기준일을 검사한다. 기준일 이후 자료와 법인 코드가 다른 응답은 저장 전에 거부한다.
- 수집 원문, API 응답, XBRL 파일은 해시·접수번호·검색 인자·수집 시각을 함께 보존한다.
- 법인·기간·연결/별도·통화·단위·원문 위치가 모두 맞는 수치만 모델 입력 후보로 사용한다.
- OpenAI에는 전송 허용 출처의 검증 수치 문장과 보류 항목만 보낸다. 원문·첨부·사용자 답변·DB 경로·키는 보내지 않는다.

## 수집 범위

첫 실행은 기준일 이전에 공개된 정기 보고서와 그에 연결되는 재무제표·원문/XBRL을 우선 수집한다. 차입·보증·감사·소송 등은 공시 목록과 원문에서 관련 항목을 찾되, 의미 판정은 원문 위치·기간·범위 검증을 통과한 근거에 한정한다. 공식 IR 자료는 DART 자료로 공백을 해소할 수 없고 자료별 이용 조건을 확인한 경우에만 다음 단계에서 연결한다.

## 검토 지점

1. 법인 코드가 확정되고 수집 계획이 저장되면, SK㈜의 실제 공시 목록·대상 보고서·예산 사용량을 확인한다.
2. 원문/XBRL 수집 뒤, 확인 가능한 수치와 보류 항목을 먼저 검토한다.
3. OpenAI 호출 전, 전송 대상 근거 목록과 모델 호출 예산을 확인한다.
4. 게시 전, PDF·Markdown·근거 화면이 같은 보고서 버전을 가리키는지 확인한다.

## 현재 알려진 제약

- 기존 실행기는 상신브레이크 보관 사례 전용으로 제한돼 있어, 일반 기업 트리거와 수집 오케스트레이터를 새로 구현해야 한다.
- 현재 자료만으로 차환, 회수 일정, 보증 잔액, 신청 목적·금액·기간·상환 계획 같은 내부 정보를 확인할 수 없다.
- OCR, 암호 해제, 다중 사용자 권한, 저장 암호화, 위변조 방지 감사 로그와 인터넷 공개 운영은 이 확장 범위에 포함하지 않는다.

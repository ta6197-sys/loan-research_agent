# 정기공시 조사 갱신 — 2026-10-27

기존 조사 화면을 열 때 `POST /researches/{research_id}/refresh`가 새 공개 기준일로 불변 기준 버전을 만든다. 같은 날짜에는 기준 버전을 재사용하지만 공식 기업개황과 정기공시 목록을 다시 확인한다. 새·정정 공시가 없으면 가장 최근의 원문·수치·XBRL 검증 실행을 화면에 유지한다. 새 공시가 있으면 새 실행에서 수집한 뒤 숫자 검증과 독립 XBRL 매핑 배치를 실행한다. 어느 경우에도 이전 원문·보고서·검증 배치를 수정하지 않는다.

실제 SK㈜ 조사(`ec8fb41947ad47b6bcff626427cd4ab8`)를 2026-10-27 기준으로 조회했다. OpenDART 기업개황 1회와 전체 공시목록 9쪽을 조회해 새·정정 정기공시가 없음을 확인했다. 새 확인 실행 `b01942e39d3c44e4a14ba5ea758ea40a`는 `unchanged`로 끝났고, 기존 검증 실행 `a2121e8cb8cd41eab7af9a9111b5b4a3`을 보존했다. 모델 호출은 없었다. [불변 조회 결과](SK_REFRESH_20261027.json)에 기준 버전·접수 이력·요청 수를 기록했다.

화면의 미게시 분석은 확인 전용 최신 실행 대신 직전 완전 수집·검증 실행을 선택한다. 따라서 새 자료가 없는 상태에서 검증 카드가 사라지지 않는다. 새 공시 수집과 자동 재검증 경로는 합성 시험 및 코드 경로로 검증하며, 이번 SK 실자료 조회에서는 새 공시가 없어 그 분기를 실증하지 않았다.

## 공식 정정 공시의 역사 시점 재생

운영 조사와 분리한 시험 DB에서 새론오토모티브의 공식 원본 접수건 `20260813000914`을 2026-08-13 기준의 **접수번호만 있는 이전 상태**로 등록했다. 이전 상태는 숫자·XBRL 검증을 하지 않았으며 `financial_verification=not_performed`다. 2026-08-14 기준으로 OpenDART를 다시 조회하자 정정본 `20260814002314`이 신규 접수건으로 발견됐다. 새 실행에서 원문·재무 API·XBRL을 수집하고 별도 숫자 검증 및 XBRL 매핑 배치를 생성했다. 외부 요청은 45회, 모델 호출은 0회다. [재생 결과](SAERON_HISTORICAL_REFRESH_20261027.json)에 실행·배치 ID와 수집 결과를 기록했다.

이전 상태에는 원본 접수건 한 건만 있었으므로 변경 목록에는 정정본 외에 2023~2025 사업보고서와 2025 반기보고서도 포함된다. 이를 정정본 한 건만 추가됐다는 증거로 해석하지 않는다. 새 숫자 후보는 87확인/43보류, 독립 XBRL 게이트는 `pass`다. 이 별도 시험 저장소에는 운영 조사에서 만든 정정 관계 증빙을 이식하지 않았으므로 읽기 모델은 2026년 반기를 보류해 72확인/58보류로 표시한다. 게시 보고서는 생성하지 않았다. 원래 새론오토모티브 조사·검증 배치·코호트는 수정하지 않았다.

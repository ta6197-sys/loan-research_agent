# OpenDART 인증키 설정과 연결 확인

업데이트: 2026-10-20. 통합 기획안은 [PROJECT_PLAN.md](../../PROJECT_PLAN.md)에 작성했다.

프로젝트 최상위의 `.env` 파일에 다음 항목을 준비했다.

```dotenv
OPENDART_API_KEY=
```

`=` 뒤에 발급받은 인증키를 입력하고 저장한다. 예시 설명 문구를 키 값으로 넣지 않는다.

기존 서버는 프로젝트의 `.env`를 읽는 구조다. `.gitignore`에도 `.env`가 이미 포함되어 있다. 이번에는 키 입력 자리와 재설정용 `.env.example` 항목을 마련했다. 금융 조사 코드가 이 키로 DART를 조회하는 기능은 아직 구현하지 않았다.

## 연결 확인 결과

사용자가 키를 입력한 뒤, 2026-10-20 16:27 KST에 공식 공시검색 API로 읽기 전용 요청 1건을 실행했다.

- 요청 대상: OpenDART 공시검색. 조회 기간 2026-10-19~2026-10-20, 목록 크기 1건.
- 결과: HTTP `200`, OpenDART 상태 `000`, 목록 항목 1건 수신.
- 키 값과 키가 포함된 요청 주소는 출력·문서 저장하지 않았다. 다른 모델·추적 도구를 호출하지 않고 별도로 확인했다.
- 첫 시도는 실행 환경의 주소 조회 제한으로 실패했고, 네트워크 접근이 가능한 실행에서 위 응답을 확인했다.

이는 설정한 키로 공식 API 응답을 받은 **연결 확인**이다. 특정 기업의 최신·정정 공시, 재무 수치·주석, 금융 조사 기능의 정확성을 검증한 결과는 아니다. 서버에 금융 조회 기능을 추가한 것도 아니다.

후속 진행: 상신브레이크와 비교 범위를 합의한 뒤 고유번호·공시 이력·10개 재무정보 응답·주요 원문·첨부 검토보고서를 확보했다. 선택 계정의 본표 대조 및 산술 연결 결과와 한계는 [조사 기록](cases/sangsin_brake/RESEARCH_LOG.md)에 남겼다. 이는 수작업 검증이며 서비스 금융 기능 구현과 구별한다. 이후에도 키 값이나 키가 포함된 요청 주소를 출력하지 않는다.

## 보고서 시각자료

사용자는 검토 초안의 시각자료 구성을 **핵심 추이 차트 + 주요 쟁점·근거 표**로 선택했다(2026-10-20).

핵심 추이 차트는 주요 수치의 변화를 보여주고, 쟁점·근거 표는 설명과 원문 근거를 연결하는 방향이다. 차트의 구체적인 종류와 지표는 대표 기업의 자료를 확인한 뒤 사용자와 정한다.

차트에도 기존 수치 검증 원칙을 적용한다. 사용하는 수치의 기간·단위·연결/별도와 원문 근거를 연결한다. 데이터가 없는 구간을 0으로 채우거나, 아직 확보하지 않은 만기 자료를 임의로 구성하지 않는다.

구체적인 보고서 형식, 차트 종류, 비교 기간, 지표는 확정하지 않았다. 실제 데이터를 검증하고 사용자와 범위를 정한 뒤 차트를 작성한다.

# 4단계 구현·검증 기록 — 수치 대조와 계산 이력


후속 보완은 [2026-10-21 보완 기록](IMPLEMENTATION_HARDENING_20261021.md)을 참조한다. 아래는 최초 4단계 구현 당시의 범위·결과다.
설계 1.0에 따른 수치 대조 기반을 구현했다. **차입 주석 구성·리스/보증 중복, 연결 범위 변경, 최신 정정 이력 전체 검증은 아직 미완료**다. 이번 결과를 보고서 게시 가능 또는 대출 판단 가능으로 해석하지 않는다.

## 사용자가 확정한 선택

1. 같은 `session.db`에 검증·계산 이력을 추가한다. 기존 추출 후보·대화·조사·보고서는 보존한다.
2. 정확 일치와 반올림 일치를 구분한다. 표시 정밀도와 처리 방법이 확인되지 않으면 자동 통과시키지 않는다.
3. 보관한 2023~2025년 연간, 2025·2026년 반기 자료를 별도 시험 DB에 복사해 확인한다. 원문 부재와 정정 확인 한계를 남긴다.

새 DB를 별도로 요구하는 기능이 아니다. 서비스는 기존 최상위 `session.db`를 계속 사용한다. 이번 검증용 DB만 `data/research/validation_stage04/` 아래에 격리했다. 기존 1~3단계 검증 DB와 원문에는 마이그레이션을 적용하지 않았다.

기존 `research_facts.status`는 계속 `candidate`다. 대조 결과는 새 이력에서 확인하며, 후보 자체를 수정해 과거 상태를 지우지 않는다. 각 계산 입력은 실제 후보와 검증 결과에 외래키로 연결하고, 식·정확값·기간·범위·통화·차이를 보존한다. 결과와 이벤트를 한 트랜잭션으로 저장한다. 같은 입력/규칙이면 재사용하고 새 원문·정정 관계·추출/검사 규칙이면 새 묶음을 만든다.

검증 버전은 `numeric-validation-1.4`다. 처음 읽을 때도 원문 해시를 검사하므로 훼손된 파일에 예전 성공 캐시를 반환하지 않는다. API 구간의 JSON Pointer가 실제 원본 레코드와 같은지도 확인한다. 기존 사례의 `response` 래퍼는 지우지 않고 `/response/list/n`으로 연결한다.

## 어떤 검사를 하는가

법인 고유번호와 원문 표지 → 접수/공개 기준일 → 별도/연결 → 보고기간·열 → 단위·부호 → 표준 계정 ID/원래 명칭·계층 → 원문 셀·행/머리글/단위/기간/범위의 바이트·해시를 대조한다. 이름이나 숫자가 비슷하다는 이유만으로 계정을 연결하지 않는다. 표준 ID가 미확인이거나 여러 레코드가 경쟁하면 보류한다. 원문 복구 경고를 보존하며, 확인된 원문 위치와 실제 API 대조 없이 지원된 수치로 만들지 않는다.

반기 손익의 3개월과 누적, 현금흐름의 당기/전기 필드를 구분한다. 1분기에서 3개월 시작일이 연초와 겹치는 경우도 명시된 열을 우선한다. 현재 자동 API 기간 연결은 원문 표지로 확인한 12월 결산 역년 보고기간만 지원한다. 다른 결산기는 추정하지 않고 보류한다. [OpenDART 전체 재무제표 공식 명세](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020)

금액은 정밀 십진수 문자열로 처리한다. 부동소수점과 표시 반올림 값을 정확한 계산 입력으로 사용하지 않는다. 수치 길이/지수 범위를 제한하고 충분한 정밀도 및 의도치 않은 정밀도 손실 검사를 적용한다. 현재 환산 단위는 원·천원·백만원이다. [Python Decimal 공식 문서](https://docs.python.org/3/library/decimal.html)

반올림 일치는 정확 일치와 별도다. 현재 자동 인식하는 선언은 같은 표 앞의 위치·원문이 확인된 `원/천원/백만원 미만 사사오입` 또는 `절사`다. 그 외 표현은 방법을 추정하지 않는다. 단위만 확인되고 차이가 있으면 추가 확인으로 남긴다. 반올림 일치 수치는 정확값 계산 입력에서 제외한다. 이번 실자료는 모두 정확 일치이며, 반올림 처리 성공은 합성 시험에서 확인했다.

계산 규칙:

- 자산 = 부채 + 자본.
- 현금흐름 기말 = 같은 날짜·범위의 재무상태표 현금. 같은 문서가 우선이고, 없으면 같은 조사 실행 내에서 대조된 동일 시점의 현금 값이 서로 일치할 때 다른 공시를 연결한다.
- 기초 현금 + 영업 + 투자 + 재무 + 원문에 표시된 환율 효과 = 기말 현금. 필요한 입력이 없으면 미실행이며, 차이를 없애기 위한 조정항을 만들지 않는다. 현재 이 식 외의 별도 조정이 필요한 문서는 차이/미확인으로 남는다.
- 유량은 전년 같은 기간, 잔액은 직전 연말을 기본으로 비교하고 전년 동기 말은 보조로 구분한다. 연간과 반기를 직접 비교하지 않는다. 범위·통화·원문 계정 구성이 맞지 않으면 비교하지 않는다.
- 같은 계정·시점에 공시별 값이 다르면 충돌을 남기고 비교를 보류한다. 같은 값의 여러 근거는 모두 보존하며 원문 입력 순서가 비교 가능 여부를 바꾸지 않도록 한다.
- 차입 세 본표 항목의 소계와 유동 차입 두 항목의 소계는 식·값을 남기되, 주석 구성·리스/보증 중복 검증 전이므로 `not_checked`다. 확정 차입 합계로 게시하지 않는다.
- 연결 증감 계산도 연결 범위 변경을 확인하지 못했으므로 `not_checked`다. 산술 값이 있다는 이유로 비교 가능성 검증까지 통과시키지 않는다.

`pass/fail/not_applicable/not_checked`를 구분한다. 수치 대조의 `pass`는 해당 원문/API 값이 명시된 조건에서 일치한다는 의미다. 최신 정정 전체 이력·주석 의미·보고서 주장까지 통과했다는 뜻이 아니다. 요약은 대상별 건수와 규칙별 건수를 따로 제공하고, 보고서 게시 가능 상태는 계속 false다.

## 실제 보관 자료 결과

최종 실행 폴더: `data/research/validation_stage04/20261020T144449Z-192e42b3/`

- API 원본10개와 XML 원본3개를 별도 DB/원문 저장소에 그대로 복사했다.
- 수치 후보290개(전기·3개월/누적·보조 현금 계정 포함)가 원문/API와 정확히 일치했다. 이는 서로 다른 290개 경제적 사실을 모두 검증했다는 뜻이 아니다. 공시별 반복되는 기간 값도 각각의 근거로 센다.
- 2025년 연간 및 2025·2026년 반기의 현재 기간은 별도/연결 각각13개 계정이 모두 대조됐다.

## 실행·재시작 검증

프로젝트 루트에서 다음 명령을 실행한다. 실자료 명령은 매번 새 격리 폴더를 만든다.

```sh
.venv/bin/python -m unittest discover -s tests -q
.venv/bin/python -m pip check
.venv/bin/python sh/validate_numbers.py
```

전체 자동 시험82개 통과, 패키지 의존성 충돌 없음. 새24개 시험은 직접 만든 자료의 규칙/오류 처리 검증이며, 실제 금융 자료 정확성 평가와 구분한다. 기존58개 저장·키 보호·로컬 MCP·추출 시험도 통과했다.

실제 금융 MCP를 별도 프로세스로 다시 실행해 같은 검증 묶음을 재사용했다. 실제 Uvicorn/FastAPI 서버 두 프로세스에서도 `GET /runs/{id}/validations`, `GET /validation-batches/{id}`가 동일한 저장 결과를 반환했다. 시험 서버의 모델/추적/외부 데이터 접근은 비활성화했다. SQLite 무결성 및 외래키 검사도 통과했다.

이번 금융 검증의 새 공시 데이터 요청0회·모델 호출0회다. 구현 참고용 OpenDART/Python 공식 문서 조회는 이 데이터 요청 수와 별개다. NCS 원문·사례·도표를 코드/시험/검색 코퍼스에 옮기지 않았다. 기존 `.env`, 사례, 1~3단계 DB/원문을 해시로 확인해 보존했다. 기본 서비스용 최상위 DB에 이 시험 조사를 자동 주입하지 않았다.

## 남은 작업

차입 주석 구성과 리스·보증 중복, 연결 범위 변경·재작성 의미, 최신 정정 이력 전체를 확인하는 작업이 남았다. 숫자 일치만으로 이 검사를 통과시키지 않는다. 2024년 반기말 등 없는 원문도 별도 확보가 필요하다.

보고서 게시/주장 검증·일곱 항목의 조사 그래프·모델 선정은5단계 이후다. 실행 대기열·전체 시간 예산/취소·자동 복구는7단계에서 연결한다. 이번 도구 호출은 저장 자료에 대한 독립 검증이며 전체 조사 워커를 시작하지 않는다. 화면 개편, 첨부 파서, IR 자동 수집, 차트/출력도 기존 계획에 따라 남아 있다.

다음은 남은 주석·연결 범위 검증을 보강하고5단계 조사 초안 흐름을 연결하는 일이다. 모델·전송 정책 등 구현 선택이 생기면 사용자에게 먼저 질문한다.

# 5단계 첫 보관 사례 연결 — 2026-10-21

4단계 구현 검증 완료 후 사용자는 기존 로컬 모델 시험·연결과 보고서 버전 보존 방식을 승인했다. 현재 범위는 **보관한 상신브레이크 사례의 기본 조사·로컬 초안·표/차트 입력·게시 버전 연결**이다. 이후 사용자9번 선택에 따라 [회사 입력부터 자료 준비·첫 게시본](IMPLEMENTATION_STAGE05_COMPANY_INPUT.md)까지 빈DB에서 연결했다. 일반 신규 기업 자동 수집부터 전체 UI까지의 완성을 선언하지 않는다.

## 사용자에게 보이는 버전의 의미

조사 중 후보를 저장하고 수치·근거 검증이 끝나면 보고서를 자동 게시한다. 이후 정정으로 새 보고서를 만들면 이전 판도 조회할 수 있다. 별도 승인 버튼은 추가하지 않는다.

기존 보고서 테이블의 내용·작성 중 상태를 변경하지 않고 v4 마이그레이션으로 `research_report_publications`를 추가했다. 게시 기록에는 보고서 ID·검증 배치 ID·내용 해시·게시 시점을 남긴다. API는 이 기록이 있는 보고서를 `published`로 반환하며 원래 저장 상태는 `stored_status=building`으로 보존한다. 내용과 게시 이력의 갱신은 차단한다. 같은 요청 키의 재전송은 기존 게시본을 반환한다.

실제 기존 수집 DB에 마이그레이션을 적용하지 않았으며 새 분석 복사본과 임시 시험 DB에서 확인했다. 신규 조사 저장소를 열면 v4가 적용된다. 이전 후보·대화·원문·검증 이력은 보존한다.

## 코드와 실제 연결

- `research_stage05.py`: 별도 금융 LangGraph의 계획→기본 조사→로컬 작성→검증/게시. 계획과 진행을 저장하고 중단 상태·모델 호출·시간의 남은 한도를 확인한다. 한 번에 한 실행을 허용하며 6단계에서 텍스트 후속 대기를 연결했다. 재시작 복구는 이후 [7단계](IMPLEMENTATION_STAGE07.md)에서 연결했다.
- `report_context.py`: 일곱 항목의 원문 검색 범위, 별도/연결 5기간×13계정 130칸, 확인/보류 상태, 기본 두 차트 주제의 연간/반기 입력을 만든다. 분기 수치를 반기 누적에 섞지 않는다.
- `local_model.py`: 루프백 Ollama만 호출하고 환경 프록시·리다이렉트·외부 대체·도구 실행·추적을 사용하지 않는다. 모델은 확인된 문장을 정확히 인용하고 질문을 만든다. 수치·보류 근거를 바꿀 수 없다. 미확인 누락·질문 누락·없는 근거·추가 도구 출력을 거부한다.
- `POST /runs/{run_id}/drafts`: 보관 사례 초안 실행. 연구 모드만 허용하며 `request_key`를 받는다. `GET /reports/{id}`와 기존 조사별 보고서 목록에서 이전/현재 판을 읽는다. 임의 신규 기업·일반 첨부를 지원한 API로 소개하지 않는다. 텍스트 후속 입력 API는 [6단계 기록](IMPLEMENTATION_STAGE06.md)을 따른다.
- `sh/run_stage05_cached_case.py`: 4단계 성공 분석을 새로 복사해 실행한다. `--existing TARGET UPSTREAM_ANALYSIS`는 같은 분석 DB의 남은 예산을 유지하고 보완 판과 새 결과 파일을 추가한다.

## 로컬 모델 시험 결과

Ollama 0.33.0과 이미 보관된 `qwen3.5:2b`를 사용했다. 클라우드를 끄고 `127.0.0.1:11434`에서 실행했다. 재설치·새 모델 다운로드는 필요하지 않았다. 모델 선택은 이 PC의 메모리 16GB와 실제 실행 결과에 한정하며 다른 모델보다 우수하다고 주장하지 않는다.

정상 근거·미확인·악성 지시 포함의 합성 3건으로 시험했다. 최초 두 시험 묶음의 악성 지시 사례에서는 보류 근거 누락을 검증기가 거부했다. 실패 기록을 보존하고 허용된 최대 2회 검증 피드백을 적용한 시험에서 통과했다. 실제 첫 초안에서는 질문이 빈 목록인 문제가 발견돼 누락 검사도 강화했다.

강화된 계약의 재시험 결과: `data/research/validation_local_model/20261021T081254Z-cb2deca9/result.json`. 세 사례 통과, 해당 묶음 4회 호출(수정 포함), 합성 모델 시험 누적 14/20회다. 시험 저장소를 새로 만들어 누적 횟수를 초기화하지 않는다. 합성 시험은 인젝션 공격 전반이나 실제 금융 해석의 정확성을 입증하지 않는다.

## 첫 실제 실행과 보완

첫 분석: `data/research/validation_stage05/20261021T080900Z-234e0dad/`.

초기 1판은 수치·보류 보존은 통과했으나 모델 질문이 없었다. 원래 `report.json`과 게시 내용을 보존했다. 질문 누락 검사를 강화한 뒤 2·3판에서는 날짜를 금액과 구분하지 못한 과도한 숫자 검사 때문에 모델 설명을 보류했다. 실패 판도 삭제하지 않았다. 진단 호출은 같은 실행 사용량에 포함했다.

날짜 전체·연/월/일·금액을 구별하고 참조 근거의 날짜·수치만 질문에 허용하도록 보완했다. 4판 `report-v4.json`에서 모델 출력 검증이 통과했다. 현재 필수 질문 4개에는 요청 자료·이유가 붙는다. 확인 수치로 답할 수 있는 모델 질문 3개는 사용자 필수 답변 대신 에이전트 검토 후보로 분리했다. 초기 실행의 누적 모델 사용량은 9회/20회이며 같은 실행의 재작성으로 한도를 초기화하지 않았다. HTTP 서버 2개에서 1~4판 재조회와 파일 보존을 확인했다(`publication_readback.json`).

확인한 표의 상태는 130칸 중 114확인/16보류다. 수치 606개를 모두 보고서의 사용 가능한 값으로 승격한 것이 아니다. 연간 영업이익/CFO 차트 입력 6개는 확인됐고, 연간 현금/차입 차트의 차입 소계는 미확인 구간을 표시한다. 반기 두 차트는 공식 버전 대응이 부족해 그리기를 보류한다. 시각화를 위해 보류 수치를 합산하거나 빈칸을 0으로 채우지 않는다.

## 남은 범위

- 5단계 전체: 일반 신규 기업의 입력→자료 자동 확보, 공식 IR 연결, 항목별 설명의 추가 검토·확인 범위 확대. 현재 첫 보관 사례의 검색 결과를 일곱 항목 전체 확인 완료로 표시하지 않는다.
- 6단계: 사용자 승인으로 텍스트 답변·정정의 별도 출처/새 실행·관련 항목 재검색·새 판 게시를 연결했다. 일반 첨부·외부 재수집은 남아 있으며 [구현·시험 범위](IMPLEMENTATION_STAGE06.md)를 따른다.
- 7단계: 이후 보관 사례의 저장형 대기열·마감·중단/재개·비정상 종료 복구를 연결했다. [7단계 기록](IMPLEMENTATION_STAGE07.md)을 따르며 일반 기업 수집과 구별한다.
- 8단계: 보고서 중심 Vue 화면·원문 보기·PDF/Markdown/ZIP의 같은 게시 버전 출력. 현재 JSON API와 분석용 SVG를 완성 화면/출력으로 소개하지 않는다.
- 9단계: 고정 절차와 실제 모델 각각 3회 비교 평가·실무 검토·다른 기업 확대.

모델·형식 실패 시 외부 모델로 바꾸지 않고 검증된 표/근거·미확인과 미작성 범위를 제공한다. 신용 판단·필요 대출 한도·DSO/CCC를 근거 없이 산정하지 않는다. 같은 PC의 다른 프로세스·사용자에 대한 인증, 저장 암호화, 위변조 방지 감사 로그는 [프로젝트 README](../../README.md)에 명시한 한계로 유지한다.

Ollama 계약 참고: [Chat API](https://docs.ollama.com/api/chat), [Structured Outputs](https://docs.ollama.com/capabilities/structured-outputs), [Thinking controls](https://docs.ollama.com/capabilities/thinking). 형식 준수와 근거·금융 의미 검증을 별도로 수행한다.

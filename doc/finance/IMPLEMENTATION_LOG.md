## 구현 전 묶음 질문 — 최초 점검 당시의 질문

1. 기존 `session.db`에 `research_` 테이블을 추가할지, 별도 `data/research.db`를 사용할지.
2. 명시적 단계 스냅샷을 저장할지, 지금 LangGraph 전용 체크포인터를 도입할지.
3. 패키지 설치 없이 저장 기능을 검증할지, 프로젝트 가상환경과 기존 의존성을 설치할지.
4. 저장 모드를 기본으로 하고 기존 채팅을 학습 모드로 보존할지, 기존 채팅을 기본으로 유지할지. DB 삭제·무관 프로세스 종료 제거 및 외부 모델/추적의 명시적 허용 설정을 함께 제안.

답변 전에는 이 선택에 의존하는 제품 코드를 변경하지 않는다. 모델 선정·다운로드, DART 재조회, 외부 모델·추적 전송, NCS 원문 복사·검색 적재는 하지 않았다.

## 최초 점검의 검증 상태

현재까지는 문서·파일·환경 확인이다. 저장 기능·서버 재시작 시험은 구현 선택 후 실행한다. 가짜 모델 성공이나 실제 금융 자료 정확성 검증을 완료했다고 표시하지 않는다.

## 사용자 답변으로 확정한 구현 선택

1. 기존 코드가 사용하는 `session.db` 파일에 조사 테이블을 추가한다. RAM이 아니라 디스크에 저장하는 SQLite 파일이다. 기존 `messages`와 조사 테이블은 구분한다.
2. 단계·입력·계획·사용량을 명시적 스냅샷으로 저장한다. 그래프 전용 체크포인터와 자동 실행 복구는 지금 완성한 것으로 표시하지 않는다.
3. 프로젝트 `.venv`에 기존 `requirements.txt` 의존성을 설치한다.
4. 기본은 조사 저장 모드, 기존 채팅은 `APP_MODE=legacy`로 명시적으로 실행한다. 기본 실행이 장애 진단 도구나 모델 상태에 의존하지 않고, 향후 금융 조사 흐름과 실습 흐름을 분리할 수 있다는 이유를 설명하고 채택했다.

가상환경 생성 중 실제 경로의 `:` 때문에 표준 Python venv가 생성을 거부했다. 사용자가 상위 폴더 이름을 `mini-project_10-20`으로 변경한 뒤 표준 방식으로 생성했다. 임시 별칭/이동형 가상환경 우회는 사용하지 않았다. 실제 생성된 `.venv`는 Python 3.14.7이다. 최초 환경 조사 Python 3.11.15와 구분하며, 이후 설치·시험은 `.venv/bin/python`으로 수행했다.

## 1단계 — 구현한 내용

- `agent/research_schema.sql`: 별도의 조사 마이그레이션 버전, 조사·기준·실행·스냅샷·원문·구간·수치 후보·보고서 후보·보고서/근거 연결·이벤트 테이블. 기존 `messages` 정의와 행, SQLite `user_version`은 변경하지 않는다.
- `agent/research_models.py`: 저장 입력 계약, 운영 기본 한도, 정밀 수치 문자열과 결측값 구분. 공식 법인 식별 전에는 `unverified`, 수치는 `candidate`, 보고서는 `building`만 허용한다.
- `agent/research_store.py`: 요청별 SQLite 연결과 짧은 트랜잭션, 외래키 검사, 새 이력 추가, 갱신 방지 트리거, 동시 요청의 중복 생성 방지, 기대 버전/리비전 검사, 감소할 수 없는 사용량, 조사 누적량. 다른 조사/기준의 근거 혼합을 차단한다.
- 원문은 `data/research/` 아래에 원본 바이트 그대로 저장한다. 공식/사용자 자료 경로 구분, 임시 파일·해시 확인·확정 저장, 정정 원문 연결, 조회 시 해시 재확인을 구현했다. 위치·표 머리글/단위 등 문맥·추출 경고는 구간에 저장한다.
- 보고서 후보의 사실/해석/미확인/질문 구분과 근거 연결, 버전 이력을 저장한다. 금융 검증 기능이 없는 단계이므로 확인된 사실을 채워 넣거나 게시 완료로 처리하지 않는다.
- `agent/research_api.py`, `server.py`: 조사 생성/조회·새 기준 저장, 실행/스냅샷·보고서/근거/원문·순번 이벤트 조회. 기본 모드의 `/chat`은 학습 모드 안내를 반환한다. `/health`는 `execution_available=false`, `llm_backend=disabled`를 명시한다.
- 원문/구간/수치/스냅샷/보고서의 쓰기는 내부 저장소 계약이다. 사용자 파일 업로드·실제 수집·보고서 생성 UI를 구현한 것은 아니다. 생성 요청은 기준과 대기 실행을 저장하며, 1단계에는 실행 관리자가 없다.
- `.env`를 수정하지 않고 외부 모델/추적의 별도 허용 설정을 적용했다. 저장 메타데이터의 인증 필드·인증 URL·설정된 비밀값·원시 프롬프트를 차단한다. 알려진 비밀값은 원문 바이트 저장에서도 차단한다. 이는 임의 자유 텍스트의 모든 비밀을 탐지하는 기능은 아니다.
- 로컬 Host/Origin 검사, 프런트 서버 루프백 바인딩, 원문 다운로드 시 스크립트 실행 방지, 요청 검증 오류의 원문 반사 방지를 추가했다.
- `agent/session_store.py`에 대화 연결의 동시 접근 잠금을 추가했다. 학습 MCP 자식 프로세스에는 필요한 환경만 전달하고 금융/API 키를 전달하지 않는다.
- 실행 스크립트의 DB 삭제와 포트 기반 프로세스 강제 종료를 제거했다. 정리 시 직접 시작한 PID만 종료한다. Ollama 설정 스크립트도 실행 중 서버를 보존한다. 모델 설정/다운로드 스크립트는 실제 실행하지 않았다.
- `.gitignore`와 학생 배포 제외 목록에 로컬 조사 자료·DB 보조 파일을 추가했다. GitHub 저장소 생성·연결·업로드는 수행하지 않았다.

## 남은 작업과 다음 단계

- 다음은 인계서 2단계의 별도 금융 MCP: 법인·공시 이력·본표·원문 조회와 오류 구분. 실제 DART 연결/수치는 해당 단계에서 따로 검증한다.
- 3~5단계에서 위치 추출·정규화·13개 계정 대조·일곱 항목 조사·초안 검증/게시를 연결한다. 현재 후보 상태 제한은 그 기능과 함께 마이그레이션한다.
- 실제 중단/재개·대기열·서버 재시작 자동 조사 복구·예산 예약·실행권·늦은 결과 차단은 7단계다. 현재 검증한 것은 **저장 상태를 다시 읽는 것**이다.
- 원문 파일 저장과 DB 확정 사이에 프로세스가 끊기면 고아 파일이 남을 수 있다. 시작 시 정리·삭제 수명주기는 이후 복구/삭제 구현에서 연결한다. 정상 예외 경로의 취소는 이번에 시험했다.
- 파일 업로드·출력·보고서 중심 Vue 화면·실시간 SSE 재생은 이후 단계다. 지금 이벤트 API는 저장 순번 조회만 제공한다.
- 모델명은 선정하지 않았다. 외부 모델·추적은 호출하지 않았다. 금융 정확성·업무 시간 절감·현직자 검증은 미수행이다.

실행·API·저장소 사용 안내는 [0~1단계 사용 안내](IMPLEMENTATION_STAGE01.md)에 정리했다.

## 2단계 — 금융 MCP와 DART 연결

사용자의 다음 진행 요청과 묶음 질문 답변에 따라 다음을 확정했다.

- 공식 기업 고유번호 목록은 로컬 캐시를 재사용하며 금융 서버 프로세스의 첫 회사 검색 때 갱신한다. 갱신 실패 시 이전 목록과 갱신 실패 상태를 표시한다.
- 기본 조사 서버 시작 시 금융 전용 MCP만 연결한다. 모델이나 DART 요청은 시작하지 않는다. 금융 도구 연결 실패 시에도 기존 저장 자료 열람을 유지한다.
- 실제 검증은 상신브레이크 대표 자료로 한정하고 기존 사례를 덮어쓰지 않는다.

금융 전용 `mcp_server_finance.py`, `agent/finance/`와 검증 스크립트를 구현했다. 기존 MCP 클라이언트에 서버별 환경·금융 전용 호출을 연결하고 학습 도구/가짜 실패와 분리했다. 서버에 `/companies`를 연결했다. 조사 생성·보고서 작성 자동 실행은 아직 수행하지 않는다.

실제 조회 전에 기존 스냅샷으로 요청 사용량과 결과 불확실성을 예약한다. 실패·재시도도 요청에 포함하고 일시 오류 최초 포함3회/대기2초·5초를 적용한다. 정상 부재·인증 오류·제공처 제한은 반복하지 않는다. 원본 응답·공시 ZIP·원문을 기존 조사 근거 저장소에 연결한다. 응답을 검증 완료 수치/주장으로 승격하지 않는다.

전체 자동 시험 **38개 통과**. 기존 저장/재시작 시험, 합성 HTTP 오류·ZIP·키 비노출, 캐시·기간·법인·예산, 실제 stdio MCP 도구 등록, 실제 MCP 프로세스 종료 시 저장 열람 유지를 포함한다. `pip check`도 통과했다.

실제 자료 조회: 기업개황, 공시 이력, 2026 반기 별도120행·연결150행 본표, 접수 `20260813000874`의 원문3,676,006바이트 저장에 성공했다. 회사 검색 목록은 최초 파싱 실패 후 숫자 전용 종목코드 가정을 수정했다. 공식 목록119,673개 중 영문 포함 코드64개가 있었으며, 수정 후 서버 API의 상신브레이크 검색과 같은 목록 재사용에 성공했다. 최초 실패 기록도 보존했다.

실제 외부 요청은 조사5회·목록 갱신2회·원인 확인용 목록1회로 총8회였다. 실자료의 수치·단위·기간·표 행/열 대조는 아직 하지 않았다. 합성 시험과 실제 연결 확인을 금융 정확성 평가로 표현하지 않는다.

원본/검증 기록은 `data/research/validation_stage02/20261020T133931Z-8a3314f6/` 아래에 별도 저장했다. 이 폴더의 `session.db`는 격리된 시험 DB이며 실제 서비스의 저장 위치는 계속 최상위 `session.db`다. 원인 확인용 기업 목록은 별도 `catalogue_debug/`에 보존했다. 로컬 검증 폴더는 기존 `.gitignore` 범위 안에 있다.

다음 단계는 원문 절·표·머리글·단위·기간·행/열 위치 추출 및 정규화다. 공식 IR 페이지 자동 수집, 제조업 지원 판정, 자동 조사 그래프, 전체 복구·대기열·출력은 아직 미구현이다. API 본표는 요청 범위와 접수 시점을 검사했지만 실제 원문 의미 대조는 이후 단계다.

자세한 도구 계약·근거·실행법·한계는 [2단계 안내·검증 기록](IMPLEMENTATION_STAGE02.md)을 참조한다.

## 3단계 — 원문 위치·표·단위·기간 추출

사용자는 lxml 추가, 엄격 검사 실패 후 경고를 보존한 후보 복구, DART XML·HTML/API부터 구현하는 범위를 선택했다. 첨부 PDF·XLSX·CSV·TXT 지원 요구는 보존하되 이번 구현에 섞지 않았다. `.venv`에 lxml6.1.3을 추가하고 요구사항/잠금 파일에 반영했다. 실제 libxml2는2.14.6이다.

`source_locations.py`로 원문 바이트 범위·행/열·부분 해시를 계산하고, `document_extractor.py`로 엄격 검사/복구·절 경로·표/병합 셀·단위·머리글·기간 후보를 추출한다. `extraction_service.py`는 기존 근거/수치 테이블에 인덱스·API JSON Pointer·13개 계정 후보를 원자적으로 저장한다. 새 테이블은 추가하지 않았다. 파서/라이브러리/원문 버전 지문으로 재사용하며 이전 인덱스는 보존하고 현재 검색에는 한 버전만 사용한다.

금융 MCP에 `extract_source`, `search_source`, `read_fragment`를 추가했다. HTTP `GET /fragments/{id}`와 `/fragments/{id}/original`로 구간 정보와 확인된 원본 바이트를 읽는다. 반환 원문은 실행하지 않는 다운로드다. 기본 서버 상태는3단계를 표시하며 전체 자동 조사·모델은 연결 전이다.

실자료는 2단계 DB를 읽기 전용으로 복사한 별도 시험 DB에서 처리했다. 원래2단계 DB/원문·기존 사례·`.env`는 수정하지 않았다. 파서 오류는 실제2733행의 잘못된 엔티티 등에서 발생했다. 오류 분류/행/열은 기록하고, 원문과 위치/텍스트가 맞지 않는 구간은 확인된 근거로 채택하지 않는다. XPath는 파싱된 트리 기준의 보조 위치이고 원본 바이트/해시가 복원 기준이다.

초기 실자료 실행은 채권 계정 후보를12개씩만 찾았다. 실제 본표가 `매출채권및기타채권`으로 표시하고 상위 행에서 유동자산을 구분하므로, 유동자산 행의 원문 위치까지 확인하는 규칙을 추가했다. 같은 이름이 비유동자산 아래에 있으면 현재채권 후보로 채택하지 않는 시험도 추가했다. 기존 실패 결과를 보존했다. 검색어 `유동성차입금`의 불일치를 내용 부재로 바꾸지 않고, 관련 원문 용어인 `차입금`으로 별도 검색했다.

최종 실자료 결과:

- 표1,266개·문단441개·원래 셀17,319개(병합 영역 포함20,564개) 인덱스.
- 원문 표 위치 매핑 미확인5개를 별도 위치 목록과 `coverage=partial`로 보존. 표1,266개 전체의 의미/추출 정확성을 검증했다는 뜻이 아니다.
- 별도/연결 각각 현재 반기의13개 계정 후보 확보. 분기/누적/전기 열을 포함한 수치 후보64개 모두 원문 셀 바이트와 부분 해시로 복원 확인.
- API 별도120개·연결150개 레코드는 원본 JSON Pointer로 연결. API 필드만 보고 기간이나 단위를 추정해 확정하지 않았다.
- 매출액·현금흐름 주석27·차입금 검색의 위치 반환 확인. 인덱스에서 찾지 못한 내용과 원문 전체의 부재를 구분한다.
- 새 MCP 프로세스에서 같은 인덱스/구간을 재사용하고 실제 HTTP API가 동일한 원본 바이트를 반환하는지 확인.
- 데이터 외부 요청0회·모델 호출0회. 패키지 설치는 별도 승인한 환경 구성이다.

전체 자동 시험 **58개 통과**, 패키지 충돌 없음. 원문 반복 값·병합 머리글·괄호 음수/0/결측·기간 추정 보류·원문 훼손·실패 원자성·인덱스 버전 혼합 차단·기존 저장/서버 재시작/금융 MCP 회귀를 포함한다. 파서 복구와 후보 저장 성공은 금융 검증 통과가 아니다. Fact 상태는 계속 `candidate`, 금융 검증은 `not_performed`다.

최종 오프라인 검증: `data/research/validation_stage03/20261020T140713Z-ab0a71df/result.json`, 같은 폴더 `restart_readback.json`. 3단계 DB는 이 폴더의 `session.db`이고, 원문은 결과 파일에 기록한2단계 `sources/`를 참조한다. 이전 시험 결과도 별도 폴더로 남겼다.

다음4단계에서 API와 원문 계정/행/열·단위·기간/범위를 대조하고 계산·비교·검증 결과를 구현한다. 첨부 파서, 공식 IR 자동 수집, 전체 조사 그래프·복구·보고서/차트/출력은 아직 연결하지 않았다. 자세한 계약과 한계는 [3단계 안내·검증 기록](IMPLEMENTATION_STAGE03.md)에 남긴다.


## 4단계 착수 점검 — 선택 대기

사용자의 다음 단계 진행 요청에 따라 숫자 대조·계산·비교 정책 명세와 현재 저장/추출 구조를 다시 확인했다. 기존 58개 자동 시험을 다시 실행하여 모두 통과했다. 이번 점검에서 금융 정확성 검증을 새로 수행한 것은 아니다. 외부 데이터 요청과 모델 호출은 하지 않았다.

구현 전에 사용자에게 세 가지 선택을 요청했다. 기존 후보를 보존한 검증/계산 이력 테이블 추가 여부, 명시된 반올림 방법까지 확인하는 처리 여부, 보관 자료로 연간/반기 비교까지 시험할지다. 아직 답변을 받기 전이므로 이 선택에 의존하는 코드와 DB 스키마는 수정하지 않았다.

보관 자료 범위를 읽기 전용으로 조사했다. 사례 API 파일은 조회 정보와 실제 응답을 구분한 `response` 래퍼를 사용한다. 2023년 연간은 별도105/연결133행, 2024년 연간은 별도103/연결127행이 있지만 각 접수번호20240315000633/20250314001195에 대응하는 원문 XML은 사례 폴더에 없다. 2025년 연간은 별도113/연결153행, 2025년 반기는 별도103/연결127행, 2026년 반기는 별도120/연결150행이며 각각의 접수번호에 대응하는 XML이 있다. 따라서 전체 기간 선택 시에도 원문 미보유 구간을 검증 완료로 취급할 수 없다. 최신 정정 여부를 새 외부 조회로 확인한 것도 아니다.

반기 손익 API의 `thstrm_amount`와 `thstrm_add_amount`가 실제로 3개월/누적 값으로 다름을 확인했다. 기간을 확인하지 않은 숫자 매칭은 금지한다. 4단계 시작 전 파일 해시 기준은 `/tmp/finance_stage04_baseline.json`에 152개 파일로 남겼다. 기존 원문·사례·DB·키 파일은 수정하지 않았다. 이후 구현 완료 기록은 이 착수 점검과 구분해 추가한다.


## 4단계 — 수치 대조·계산 이력 구현

사용자는 후보 보존 + 같은 DB의 검증/계산 이력 추가, 방법까지 확인된 반올림만 구분 인정, 보관 자료로 연간/반기 비교까지 검증을 선택했다. 선택 대기를 해소하고 실제 구현과 검증을 수행했다.

버전2 추가 마이그레이션으로 `research_validation_batches`, `research_validations`, `research_calculations`, `research_calculation_inputs`를 만들었다. 기존 후보/대화/보고서와 SQLite user_version을 보존한다. 새 결과/계산/입력은 불변이고 외래키로 연결하며 결과와 이벤트를 함께 저장한다. 같은 입력/추출/정책 버전이면 재사용하고 다른 버전은 새 이력이다. 후보 Fact 상태는 여전히 candidate다.

`numeric_validation.py`로 원문 표지 법인/보고기간, 공개 기준일, OFS/CFS, 손익의3개월/누적과 CF 필드 차이, 통화/단위/부호, 표준 계정 ID와 원래 행, 머리글/단위/기간/범위·원문 바이트/부분 해시를 대조한다. API JSON Pointer도 실제 원본과 확인한다. 원·천원·백만원 환산과 명시된 사사오입/절사를 정확 일치와 구분하며, 반올림 일치 수치를 정확값 계산 입력으로 사용하지 않는다. 현재 명시된 역년 보고기간만 자동 연결한다.

자산 등식, 현금 기말 연결, 기초+영업+투자+재무+표시된 환율 효과의 검산, 같은 기간/직전 연말/전년 동기 말 증감을 구현했다. 서로 다른 범위/통화/원문 계정 구성을 섞지 않는다. 같은 기간 공시별 값 충돌은 비교 보류이며 동일 값의 여러 근거는 함께 보존한다. 대표 근거 입력 순서가 비교 건수에 영향을 주던 문제도 직접 만든 회귀 시험으로 수정했다. 차입 소계는 계산을 보존하지만 주석 구성·리스/보증 검증 전이므로 not_checked다. 연결 증감도 연결 범위 변경 검증 전이므로 not_checked다.
